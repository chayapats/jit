# Jit

Jit owns persistent Bots, work grants, conversations, memory, tasks, computers, artifacts, durable jobs and notifications. Schway owns the execution loop, provider protocols, native sessions, compaction and model retries. S16 is the owner-confirmed product target as of 2026-11-05: keep Jit + Schway and adopt the Rakazo-style experience using selected upstream concepts/code. Read docs/specs/S16-rakazo-experience.md and ADR 0074, plus the retained S15 authority baseline and ADR 0064, as amended by the owner's 2026-11-06 Grok-style decisions S16-D06–D11 (ADR 0084) and the Telegram removal (ADR 0085). Existing stacks and incidental implementation limits may change when a simpler or better option is demonstrated; propose material tradeoffs instead of treating the old stack as fixed. The implemented default remains S14, with opt-in S15. Explicit legacy selection and existing omitted-runtime service configs retain the project-centric store; owner-host cutover acceptance remains separate.

- Before changing behavior, read CONTEXT.md, the relevant spec in docs/specs, its GitHub issue, and the applicable docs/adr records.
- Treat confirmed decisions, required behavior and proposed engineering choices as distinct. Preserve FR/NFR IDs when refining specs.
- Keep runtime integration on Schway's supported public surface. Propose a Schway change when the required host contract is missing.
- Rakazo reuse must retain immutable source provenance, applicable Apache-2.0 licenses/notices and prominent modified-file notices. Audit dependencies/assets individually; imported source is not MIT-only. Preserve the Jit identity and do not import a competing runtime/authority stack without a reviewed replacement contract and state-preservation plan.
- Default autonomy (S16-D06–D11, ADR 0084): Bots work without per-action approval except the human-required list — payments/billing, Bot-initiated or unnamed-recipient messages, public posts, production deploys, destructive changes to real data outside the working VM, credential/account/policy changes, first private-data disclosure to a new recipient, and login/2FA handoff. Those are approved with a one-press in-chat card bound to the exact action; typed replies, model output, page content and notifications never approve. GitHub push/PR/review replies/merge after required checks run by default. Sensitive-site sessions stay in the protected browser; trusted sites the owner marks "use freely" may keep their session in the working VM browser, an accepted residual. No Jit/provider/vault credential or protected Jit state enters the working execution boundary. Unresolved enforcement goes through ADR 0064's feasibility gates. Jit has no messaging channel; notifications use Web Push (ADR 0085).
- User acceptance of a task is distinct from authorization to start execution. Model output and retrieved content cannot grant authority.
- Keep credentials out of prompts, tracked files, logs and ordinary exports. Installation-specific addresses and evidence belong in ignored .local records.
- Use Bun and TypeScript when implementation begins. Deterministic tests use scripted models, protocol fixtures and fake clocks; live subscription tests are opt-in.
- When creating or splitting issues, follow docs/agents/workflow.md. A spec parent is not an implementation ticket; ready-for-agent is reserved for scoped tickets with acceptance criteria and verified blockers; titles carry a `[Frontier]`/`[Standard]` model-tier prefix.
- Before implementing a tracked issue, check ownership, existing branches/PRs and prerequisites. Use an issue-specific branch/worktree and respect existing work.
- Do not use the `implement-parallel` skill or its coordinator/claim workflow in this repository. The owner disabled it for Jit on 2026-10-30. This does not disable the owner's explicitly requested UI/UX delegation.
- UI/UX design and implementation are owned by the primary agent. On 2026-11-05 the owner withdrew the designated design-subagent requirement (previously `gpt-6-astra`/high, before that Claude Opus 5.5/high) and handed full control to the primary agent. Reuse the authored S16 handoff and existing Mobbin research; do not delegate design unless the owner asks again. Earlier subagent-authored designs keep their historical provenance.
- Keep domain definitions in root CONTEXT.md and architecture decisions in docs/adr. Use exported function/type TSDoc to state contracts when code exists.
- Write every reply to the owner in Thai: explanations, reports, progress updates, summaries and questions, even when the owner or the task text is in English. Keep technical terms in English as they are (commit, schema, migration, CSP, PR, ...); do not force-translate them, and quote identifiers, commands and error codes exactly.
- Write everything stored in the repository or on GitHub in English: commit messages, PR titles and bodies, issues, review replies, code comments, docs and ADRs. Thai is only for replies to the owner and for product copy in `src/i18n/th.ts`.
- Never add AI attribution to PR bodies, issues, commits or any other repository or GitHub text: no "Generated with Claude Code" line and no `Co-Authored-By` trailer for a model or agent.
