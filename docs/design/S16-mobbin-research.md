# S16 Mobbin research

Research date: 2026-11-05. UX16-01 [#394](https://github.com/chayapats/jit/issues/394), against Jit `80cc1c80e2e534c4a5940abecca2c993248bb596`. Research preceded the design in [the experience handoff](S16-rakazo-experience.md). This is visual-reference research, not evidence of another product's backend guarantees.

## Method and coverage

Actual Mobbin MCP `search_screens` calls used `mode: deep`, `limit: 2`; actual `search_flows` calls used `limit: 1`. Every call used identical metadata:

- `task_intent`: `Design a self-hosted persistent AI teammate application with file workflows and connected tools.`
- `output_destination`: `code`; `output_tool` omitted.

Ten screen queries returned twenty images, all inspected inline. Two flow queries returned two flows; their six evenly spaced preview images were inspected (positions recorded below), not all ten constituent screens. Web and iOS were searched separately. No collection, comment, saved item, screenshot export or expiring image URL was persisted. No generic web summary substituted for MCP research. The references below use returned canonical Mobbin URLs. Search results were sometimes weak; those are recorded rather than reinterpreted as evidence. No fabricated scoring or usability-test claims.

## Synthesis and limits

Research covers ten requested themes: progress/steering, attachments, artifact organization, async approvals, connected apps, memory, routines, computer entry points, voice and mobile. The strongest grounded patterns are R01's work inspector, R02's named file and destination clarification, R04's persistent approval queue, R07's schedule review and R10's mobile draft attachment. Bots are supported indirectly by assistant configuration in R05; detailed lifecycle, delegated worker cancellation, protected input, immutable artifacts, retry reconciliation and true cross-device continuity are contract-driven design, not observed competitor guarantees.

Stop searching here: extra broad searches would repeat chat/settings references. The missing takeover evidence is explicit after a targeted follow-up. No conclusion about Mobbin coverage of that workflow as a whole is warranted. No tools failed; irrelevant returned results are relevance limitations, not tool errors. Images are low-resolution previews, so tiny labels are not used as evidence. No usability testing, accessibility measurements or live competitor execution occurred.
