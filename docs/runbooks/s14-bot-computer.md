# BOX14-01 Linux evidence — opt in only

Linux evidence is per architecture/build. The disk-pool follow-up uses a disposable arm64 Linux VM and the installed-service harness below; exact pass/fail results, build identities and raw evidence belong in the ignored `.local/s14-live-hosts.md` record, with a credential-free PR summary. An unprivileged LXC without loop devices cannot provision this pool. x64 VM, reboot, paid inference, website login and UI/device/accessibility acceptance remain separate gates. Fixtures/configured images do not prove Linux support. Requirements: FR-35/36/38/40; NFR-04/06/07/14.

`ops/box/s14-probe.ts` is credential-free. Default/`--diagnostics` probes readiness only. `--smoke` starts two specially named probe computers and writes synthetic markers in dedicated probe filesystems; it never opens application/native state or provider/website sessions. It leaves markers for inspection and removes probe containers in `finally`. Never point it at real Bot storage. It never pulls images or retries another backend.

## Host prerequisites and diagnostics

Use the application's non-root service identity and rootless Podman through its own verified local Unix socket (or an explicit local development client). Record exact Bun/Podman/image digests/kernel/architecture/checkout SHA in ignored `.local/s14-box14-smoke/`. Installation addresses and raw host outputs stay there, never in tracked files/ordinary exports.

| Reason | Operator investigation |

| `subuid_subgid_range_required` | Check >=65536 subordinate UID/GID ranges, `/etc/subuid`, `/etc/subgid`, `newuidmap/newgidmap` and outer LXC mappings. A one-ID map is insufficient. |

## Credential-free smoke

Provision an **isolated test pool**, distinct from the application computer root, through the same root `provisionS14Disks` installer API. It needs a protected manifest and eight finite pairs; do not use active Bot storage. The standalone probe uses only the first two slots and never reads application/native/provider state. The regular `install.sh --s14` provisions the application's pool automatically; its scoped lifecycle is tested separately.

Set non-secret `JIT_S14_SMOKE_ROOT`, actual digest-pinned `JIT_BOX_IMAGE_BASE`, `JIT_BOX_IMAGE_BROWSER` and the service's `JIT_PODMAN_MODE=remote` / `XDG_RUNTIME_DIR`. Run as its service identity. Record exact revisions and results in `.local/s14-live-hosts.md`; no addresses or raw output enter tracked files.

```sh
bun --no-env-file ops/box/s14-probe.ts --diagnostics
bun --no-env-file ops/box/s14-probe.ts --smoke
```

Pool/runtime failures are not permission to disable service hardening or use a host shell. `computer_disk_pool_full_rerun_installer_to_extend` requires `install.sh --s14 --computer-slots N`; overcommit requires more host space. Re-runs retain data and mount image identity. Initial committed capacity is 16 GiB plus the installer reserve; sparse allocation does not waive that requirement.

The installer and compatible-code `service upgrade` prepare the exact runtime user-namespace image mapping before activation, including reused images. This can take longer than computer startup on slow storage; the 30-second runtime ceiling stays unchanged. Preparation never starts an image or mounts Bot data. An upgrade with configured images refuses activation if mapping preparation or cleanup fails; inspect rootless storage/space and retry the upgrade. Do not manually bypass the phase or clear Podman's image/layer cache while the service runs. After an operator removes that cache or changes subordinate mappings, re-run install/upgrade before measuring cold computer startup. Measure independent bounded fsync/metadata latency as well as prepared cold/warm starts before attributing a timeout to disk or to a Podman major version.

Measure two authorized Bots starting together, including the first pair after reboot. Their lifecycle operations may run concurrently (maximum two); operations on one computer remain ordered. The second Bot keeps its own original 30-second deadline, including queue time. Record a missed deadline as a failure even when a later retry succeeds.

The smoke checks container mounts/namespaces/hardening, kernel CPU/memory/PID/swap limits, bounded unique filesystems, cross-Bot marker/profile/socket denial, direct-network/raw-socket denial, owner-image capture and workspace/profile marker persistence across process recreation. The profile marker is synthetic and proves no real website login. Failure remains a blocker; finite limits may not be weakened.

## Installed service lifecycle evidence (no model)

`ops/box/s14-computer-evidence.ts` is an explicitly destructive **disposable-host-only** harness. It requires `JIT_S14_COMPUTER_EVIDENCE=1`, holds the installed runtime lock and refuses any computer/slot claim in the normal application database. Run it instead of `serve` in the installed hardened `jit-s14.service`, with the same identity, environment, mount namespace and all sandbox directives. Change only `ExecStart`, add the opt-in flag and set `Restart=no` through a temporary `/run/systemd/system/jit-s14.service.d/90-computer-evidence.conf`; restore the normal descriptor after the round. Do not run it beside a live service or on a pool containing actual Bot data.

It creates a separate synthetic S14 store beside the installed database, provisions a synthetic owner privately, uses typed setup/work/computer/takeover commands and actual `BotPodmanRuntime`. It never invokes a provider/native model. The first invocation proves runner/profile/socket/network denial, captures a real PNG, exercises owner input, waits five actual minutes, verifies idle stop and reopens the same computer. It emits `awaiting_unit_restart`, closes its store and exits. Start the same unit again to prove boot generation fencing, workspace/profile persistence and a second screenshot. It then resets both filesystems, verifies they are empty, deletes the claim and accepts a scripted proposal for Bot B. An orphan marker injected into the returned slot must be wiped before B starts; B is reset/deleted afterwards. Only safe pass/fail checks and screenshot size/hash are output. Its temporary owner password stays in a private mode-0600 file in the synthetic state tree and is removed after success. Failed rounds retain state for diagnosis; never erase real application state to retry them.

Capture the safe results, exact source/build digests and any failures in the ignored host record. Remove the temporary unit override, reload systemd and start the ordinary S14 service afterwards. This proves the installed kernel/runtime/lifecycle with a synthetic store and no model, not a research/provider/UI acceptance pass or reboot evidence.

## Physical input race helper — prepared, live proof NOT RUN

`ops/box/s14-input-evidence.ts` is a separate, explicitly opt-in operator helper for #256 (S14-AC12/14, FR-35/36/38/40; NFR-04/06/07/14). Preparing or testing it does not execute the physical proof. The parent must first finish the current owner Mac acceptance, review this helper, then decide and provision a **new unused disposable Linux x64/arm64 installation** with the standard `install.sh --s14` boundaries. This procedure does not provision anything. It does not create a second service namespace on an existing host. The existing lifecycle harness and its populated-pool refusal remain unchanged.

Include this helper in the reviewed artifact through the existing package build. The helper checks its own installed code path, root trust, artifact validation, exact rendered base descriptor and exact temporary drop-in, effective main PID/identity/hardening/environment, private state and actual finite scratch tmpfs. It refuses checkout execution, other users/platforms, other drop-ins or relaxed unit settings. - Keep the real application and all other harnesses stopped. The helper holds `acquireS14RuntimeLock` for the installed database until all streams, commands and cleanup settle. Its read-only check retains `evidence_requires_unused_disposable_pool`: any non-deleted computer or any disk-slot claim, including a stopped claim, refuses. - The standard pool is **eight pairs**, each a finite 1 GiB workspace and 1 GiB profile: **16 GiB full logical commitment**, even though the helper uses just one pair and one logical computer sequentially. No systemd, mount, pool, VM or network provisioning is performed by the helper. The helper creates `<stateDirectory>/input-evidence/<random-run-id>/application.sqlite` and its **independent** lifecycle ledger, plus private owned `private.json` and bounded `result.json` records (0600; directories 0700). No installed database/ledger/vault/native/provider state or credential is copied. A CSPRNG password provisions only a synthetic owner through `provisionOwner`/`login`/`authenticate`; it is never printed. Setup, four finite work grants (one attempt/step, 16 calls, 1 KiB output, 180-second expiry each), computer lifecycle and takeover all use public authenticated application methods. One logical computer and slot are retained across all four fresh work/attempt/lease scopes.

The four ordered cases are:

1. Receive and hold the real initial `Target.attachToTarget` reply, commit takeover, then release that exact reply. The original session must fail `input_lease_fenced` with no `Input` frame. An unsupported synthetic `publish` card is proposed through `proposeEffect` with no performer; handback must preserve its exact pending revision/hash and never approve it. This setup is supported by the current public contract; a future unsupported setup must be reported unrun, never replaced by SQL state.
2. Dispatch scroll S0 to Chromium, receive and hold its real ACK, queue S1, commit takeover and queue exact owner Tab. Before settlement there must be no owner frame. Releasing S0 fences its post-settlement guard, S1 sends no wheel frame, then both owner keyDown/keyUp commands and their actual ACKs settle. Releasing the stale agent session must leave the entire owner lease unchanged.
3. Receive a fresh actual input ACK and a completed actual runner response, holding at most those two responses. Commit exact `computer.stop`; assert generation/lease fencing and refusal of later input, backend write and result publication with no additional transport dispatch. Release both responses: neither late runner output nor a successful stale input may publish. Join both promises and confirm exact component containers and their original kernel processes are absent before reusing capacity. Before input, the helper observes both actual component PIDs and `/proc/<pid>/stat` start times in bounded memory; after removal a surviving original process refuses reuse. A different start time distinguishes PID reuse. These ephemeral kernel witnesses are never written to the transport trace or record.
4. Repeat with typed `work.stop`, verify actual grant revocation, sweep/drain and the same late-input/write/publication/output barriers and confirmed process removal. A runner whose response is held has **completed**; it is never described as still executing.

`InputEvidenceTransport` wraps the actual `podmanStreamRunner` used by actual `BotPodmanRuntime`. Input writes call the underlying writer synchronously with the identical bytes; the wrapper never sends extra raw CDP, fabricates a result or inserts an await between a final guard and dispatch. Only already received replies can reach a latch. Latches expire/close after at most 4.5 seconds, before the unchanged 15-second CDP deadline; failure/interruption closes all of them. Bounded parsers use 64 KiB frames/chunks, 16 outstanding commands, 256 metadata rows, at most eight pipes and 2 MiB aggregate observed transport. Actual Podman command stdout/stderr collection is capped at 1 MiB and stdin at 8 KiB, with finite deadlines and joined process settlement. Admission stops at 180 seconds; a 240-second total cap includes preflight and cleanup. Fake clocks exist only in deterministic tests. No input bodies, CDP error text, session IDs, profiles, screenshots or credentials enter the trace: only method/id/pipe/order/stage metadata.

On success, supported cleanup stops all four work grants, drains and exactly stops/deletes the synthetic computer, confirms process removal, verifies both mounted roots empty and confirms `diskSlot:null`. Each observed PID/start-time witness is retained immediately, including when inspection of the other component fails; incomplete inspection refuses cleanup confirmation and a later inspection cannot discard earlier witnesses. Command settlement rechecks its monotonic deadline even if the timeout callback was delayed. Every gate closes and every actual stream/runner promise is joined. The plaintext synthetic password is removed from the recovery marker only after a complete success or confirmed cleanup-only round. The synthetic database/ledger, bounded diagnostic record and completed marker remain private for inspection; the helper does not remove mounts, the unit or the VM.

A failure, SIGTERM/SIGINT, timeout, uncertain wipe/stop or hard-cap exit retains private state. A fresh invocation always refuses an existing marker, even a completed one: no automatic fresh run or input replay is supported. For a valid failed marker, the operator may change only the override's `ExecStart` to append `--cleanup-only`, reload and start the same unit once. This authenticates the retained synthetic owner, runs exclusive boot fencing and typed stop/drain/delete only, and never re-enters an input case. Foreign orphan containers, malformed/linked/foreign-owned/non-private/oversized state, unavailable authentication or unconfirmed settlement/wipe remain blocked for parent inspection. Do not edit SQL authority, erase the marker to retry, broadly prune, force/lazily unmount or invent a successful cleanup. Root mount/unit/VM disposal belongs to parent operations outside this helper.

After inspecting the private safe outcome, the operator removes **only** `90-input-evidence.conf`, reloads systemd and restores the ordinary descriptor; starting `serve` or disposing the disposable installation is a separate parent decision. Keep diagnostic state on a failed or uncertain round. Raw machine details and any host observations stay in the ignored private host record; do not update the tracked evidence summary from deterministic tests.
