# Preserve native sets without inventing execution correlations

ADR 0104 retains current authority while historical material remains inert.
The owning namespace now resolves CHAT/MODEL saved references and GitHub VM
attempt roots. GitHub did not persist an exact native execution reference.
Public inventory supplies management `main` references, not execution grants.
The root journal/component limits (256) also cannot represent one action or
component per historical native root (the namespace can contain thousands).

Select one bounded native-set component and one original capture action. Its
private per-root files preserve complete public native inventory and opaque
snapshots. Owning namespace/current guards span collection and publication;
native snapshots retain their own coherent copy leases and public bounds.
Current original VM/work/generation and uncertain facts remain unchanged.

For each uniquely owned CHAT/MODEL/GitHub intent, retain the exact saved subset
and any additional public managed identities. A versioned `s16-native-root/v2`
records `referenceKind: current_custody`, `savedReferences` and original owning
custody (including the original VM attempt for GitHub). Known saved identities
keep their exact branch; other identities use management `main` references for
protected quarantine without writing an execution correlation. This also retains
a session created before its owning correlation commit. A successful owning
GitHub result requires discovered native identity; an unconfirmed attempt can
retain an explicitly empty observation and original uncertainty. Missing required
roots, ambiguous owner, unrelated files or unsupported native state still refuse.

Adding a new execution-correlation ledger now would couple another authority
record to session creation and still leave existing roots without correlations.
Blocking every such uncorrelated backup would prevent retaining the original unknown
work required by #429. Explicit management custody is simpler and preserves all
known bytes and uncertainty without changing the execution loop. It is not a
replacement authority stack, a job-resume API or permission to settle a VM.

The native-set manifest/independent receipt binds the original operation/action,
installation, namespace basis, exact root roles/provenance, opaque file hashes
and unresolved original facts. Metadata stays within 4 MiB, selected encoded
bytes within the caller's remaining 4 GiB payload budget; roots are processed
one at a time, never accumulated as gigabytes in memory or silently omitted.
Each native root also requires actual public restore quarantine, since shape
validation alone can accept nonexistent branch ancestry. Failed/incomplete sets
stay unpublished and cannot become archive authority. Completed readback uses
the original operation; unknown live effects are never retried by capture.

Historical management snapshots are only format-verified/quarantined. Forward
activation uses the complete current cohort and current native tombstones.
It never imports historical VM state, synthesizes a saved GitHub branch, creates
a native session or resumes an original unknown task. Ordinary export excludes
these native files. Older component readers must refuse v2, and package fallback
must prove compatible readers rather than rewriting provenance to v1.

This decision supplies native custody engineering. Complete aggregate capture,
ordinary export, retention, backend/helper/client coordination and lifecycle
acceptance remain required by #429; no installed host or policy changes follow.
