[Team contract revision 2](../contracts/s15-team-resources-v1.md) and [memory contract](../contracts/s15-memory-v1.md) describe the implemented surface.

They serialize conflicting cooperative writes/input and retain unresolved capacity through restart, without claiming hostile-root CAS. Existing VM/browser/POLICY brokers keep external effects, credentials, accounting, physical generations and settlement ownership. No second effect authority or budget is introduced. RT15-01 option B is owner-resolved; real enforcement/adoption evidence remains separate.

TEAM and MEM each keep explicit schema-1 protected continuity outside guest/ordinary images. Memory withdraws TEAM ancestry before committing its own correction/forget. A failed second commit can only withhold more data; retrieval and history also consult the first withdrawal. Retrying the exact owner command completes retirement without reviving content. Corrections retain inherited privacy/resource ceilings. Fresh public Schway sessions retire on close; active memory changes fence subsequent model/tool/result use, and retired contexts are never replayed. Source hashes/claim lifecycle/command identities must be preserved by MIG15; this implementation does not import S14, activate a host or implement Jod.

## Proposed choices

1. **Reuse current mediated authority, not copied accounts.** Resolve one actual admitted request/purpose/current owner/policy and enabled assignment. Intersect current resource/data/source/access/producer/sender/receiver/account-route/recipient/model/effort/author restrictions before relevance, context, tools and final bytes. Team-approved resources need no second per-Bot setup. Explicit narrower or S14-private restrictions remain binding. No raw cookies/tokens/profile mount, permanent Bot change, new account/provider/billing/recipient or purpose expansion.
2. **Separate plan acceptance from read and dispatch.** Pure plan preparation performs no source/model I/O. Atomic acceptance commits one original team intent/receipt, not an executable grant from model text. Already admitted #323 scope and exact finite original read reservations authorize context acquisition before a future context/model-plan hash exists. #326 selection preparation consumes the complete authorized packet and performs no read I/O. Each actual child acquisition gets its own nonrefundable charge/claim before I/O.
3. **Keep independent complete context and source-bound subsets.** Each Bot/attempt owns fresh context/native ownership with every current owner decision, original bytes and conservative transitive lineage including uncited generated content. Handoff offers accept metadata first, then guarded bounded child reads and synchronous final byte publication to the actual receiver. No full transcript/session/profile/volume copy or native-history reconstruction of authority. Source/receiver/model changes require fresh authorized context; caches never bypass current guards.
4. **Coordinate exact physical conflicts.** Independent immutable reads may overlap under finite aggregate limits. Mutable file read/write and namespace aliases use exact externally resolved object/alias/version footprints; conflicting writes serialize and reacquire current observation/new lease generation after real settlement. Browser input has one effective owner per protected session, with takeover generations and stale-release safety; reads do not acquire/renew input. Native tool `exclusive` does not coordinate different runs.
5. **Distinguish cooperation from malicious-root proof.** Guest-local locks/tokens/path/hash checks and descriptor-relative direct-file observations cannot prove hostile-root CAS, protected evidence integrity or universal effect gates. Preserve #321's checked-parent/no-follow own-entry limitations. Actual external manager/conditional ordering/final emitter/settlement evidence is required before advertising support. Broad root/admin footprint is not one disjoint file. RT15-01 and RF15-G01–G08 remain unproven; no option B, loss acceptance, weakened guarantee or read-only substitute.
6. **Preserve owning-service facts and real output paths.** Team coordination does not mint a second action claim. Retain #321 actor-bound prepare/accept, signal-aware dispatch, guarded readResult, synchronous publishResult and memoized original-scope cancel. Retain #322 independent input/network/capture/channel/scope/process/publication facts and the same protected action-or-read emitter; exact original child charges precede I/O. Complete directional frames include their headers and differ from decoded image/output bytes. Stop/rejected proof cannot erase facts or refund charges. Whole VM/profile stop needs authority for its full impact.
7. **Preserve finite original continuity and honest partial results.** A registered original unconsumed context may continue its exact paid reservation at zero remaining allowance; a new child needs a new exact charge and incremental allowance. No double charging guard callbacks, refunds, stale-budget reuse or rekeying. Unknown usage is not zero; subscriptions/absent telemetry are not free/infinite. Cancel/expiry/restart fence late bytes while actual unsettled scopes retain capacity. Valid sibling evidence survives another sibling's failure/stop; required gaps produce a partial result, not false completion or unrequested replacement work.

## Alternatives and consequences

Repeated per-Bot grants preserve an S14 ceremony that S15 explicitly replaces for team-approved resources. Preserve the implemented S14 records until an explicit replacement slice lands; do not turn them into the new default merely by changing documentation.

A shared mutable native transcript or copied profile would mix context and authentication across receivers and bypass current source/account restrictions. Use fresh independent packets and mediated exact subsets. Historical source/receipt hashes remain evidence, never reusable authority credentials.

A guest-local mutex can coordinate cooperating Bots but cannot establish adversarial-root correctness. Advertising it as a protected CAS or settlement boundary would overclaim support. Unsupported physical semantics must remain explicit while the actual external design is proved. General administration/browser functionality remains the required product target.

Finite conservative reservations and retained uncertainty can reduce available capacity. This is deliberate pending a separately reviewed refund policy. Actual observation and nonrefundable charged bounds remain separate; settlement releases concurrency only. No numeric S15 amount/currency period/profile is selected by synthetic examples.
