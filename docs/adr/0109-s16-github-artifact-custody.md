# Retain current GitHub bundles without replay or inferred publication

The selected GitHub runtime writes immutable bundle_<SHA256> files before
publishing coding evidence. DATA15 can also retain a derived-artifact reference
before that selection commit. Capturing only current selection references would
lose this lineage, an unpublished bundle or older action/receipt evidence. A recursive copy
could admit unowned files. Opening GithubStore instead changes implementing or
remediating records to reconcile_only; that is application recovery, not a
read-only capture.

Select a bounded current artifact cohort under genuine installation/CHAT
exclusion. Bind the exact current selected/retained GitHub reader and installation,
enumerate the closed hash-addressed namespace and retain every valid file.
Resolve bundle references only from the owning selection, action, coding-evidence
and selection-receipt slots, plus DATA15's owning derived-artifact slot with its
original domain-hashed key. Preserve original row/request identities and states;
remote source text and arbitrary nested keys do not supply artifact references.
Missing referenced bytes, unsafe files or unknown formats refuse instead of
publishing a smaller cohort. A retained unreferenced bundle stays unreferenced.

Stream verification reuses the existing payload reader without creating a point,
decoding Git objects or starting a command. Original namespace/absence/inodes and
metadata remain guarded. Byte hashes prove custody, not Git ancestry, acceptance,
current recipient scope, permission to push or a settled original mutation.
Raw connection/selection/action/receipt SQL remains separate protected current
continuity; no token, repository URL or full remote content enters this metadata.

This adds no GitHub request, credential read, workspace boot or installed policy
change. Aggregate publication, current-scope forward recovery, backend/client
custody and the remaining lifecycle acceptance are still #429 work.
