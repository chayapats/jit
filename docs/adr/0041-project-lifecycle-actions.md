# Project identity survives rename and deletion; archived specialists cannot run

S12-D12 requires owner Web actions for rename, role archive and digest-bound project deletion. FR-02/10/15/17 and NFR-05/10 apply. These engineering choices preserve ADRs 0011, 0012, 0027, 0031, 0036 and 0037; they add no model authority, provider calls or host protocol.

- Rename uses the project revision and shared receipt/audit transaction. The trimmed name is display data; identical names write a receipt and audit without advancing either project or collection revision. General is immutable.
- Role archive is an `archivedAt` field in existing JSON. Configuration reads filter before the role limit, route overrides are removed without advancing project revisions, and captured pending requests are fenced. Admission/publication and execution gates check the archived identity too. Historical role names and records remain.
- Whole-project deletion seeds the existing lineage closure with every source generation and every project claim, job and context. The preview adds project identities, schedule/monitor states and a digest of all project-owned rows, including dependent attempt and PR records. It excludes the preview/receipt/audit writes themselves. Owner decision (2026-10-29): open tasks with their states and active decisions in the deleted project are explicitly listed for closure and deletion, bound by the preview digest and typed-name acknowledgment. Cross-project owner-copy blockers remain; unsettled effects and current MCP installs also block. MCP state checks select only the latest revision per server; approval cards, schedules, monitors and discussions store current rows in place. The state digest and redaction intentionally cover all historical revisions. Unknown records and finite inventory ceilings fail closed.
- The installation lifecycle ledger records a `deletion` with `subject: project:<id>` and `record.kind: project`, even for an empty project. It uses the existing ledger table/checkpoint and JSON operation records, so no schema migration is needed. Stable project/group/topic/message/source/task identities remain; project-owned payload and settings copies are redacted. Common project predicates deny new commands, source publication, execution and job admission; navigation, search, Telegram choices and the schedule feed omit tombstones.
- The confirmation transaction fences jobs, retires contexts, revokes schedules and PR monitoring, cancels pending delivery copies, denies pending approval cards and ends discussions/takeover. It commits local payload purge and the ledger before requesting transport cancellation. Managed native deletion, export purge and collateral cleanup remain durable operations with the existing five-attempt bound. Running or uncertain external effects must settle before deletion. Owner decision (2026-10-29): confirmation explicitly closes the previewed obligations through their state machines before redaction: proposed tasks become dismissed, accepted/ready_for_review tasks become cancelled, and active decisions become superseded by the identity-only project tombstone (`supersededBy: project:<id>`), without inventing a replacement conclusion. The decision transition shares the guarded supersession path. Each closure records `project_deleted`, an audit entry and a redacted receipt in the same transaction. Replay closes only still-active records and creates no duplicate closures.
- Every writer connection enables `secure_delete`. Project completion additionally requires `VACUUM` and a successful truncating WAL checkpoint; busy readers leave `databasePurge: pending`. This covers DB/WAL payload removal, not forensic erasure of the disk or retained backups.
- A service-owned collateral contributor supplies identity-only count/bytes/digest, a synchronous transactional confirmation fence and an idempotent asynchronous purge. Its frozen inventory is also in the installation ledger, so an older restore image can reconstruct pending cleanup. Missing contributors cannot report completion. Owner decision (2026-10-29): the built-in execution-box contributor inventories workspace and browser profile separately with counts/bytes and opaque identities, never paths or contents. The Web warns in Thai/English that unpushed box work will be lost. Cleanup waits for concurrent ensure, stops and resets the box with wipeWorkspace, then verifies both directories are absent. The host-side fallback also works without a BoxManager or Podman, only under the service-configured execution root. Root/project/volume symlinks are refused, internal links are never traversed, missing directories succeed and failure remains pending (five-attempt bound). Startup reconciliation still stops tombstoned boxes; durable contributor reconciliation performs verified data removal.
- Settings › Project data retains cleanup status and retries after navigation hides a deleted project. Forms work without JavaScript; all owner actions retain session, Origin and CSRF checks. Streaming files require no edits.

S13's attachment count/bytes and blob/derived-file deletion (including restore replay and per-project refcounts) are delivered by ATT06 #195 after ATT01 #190. LIFE02 provides the contributor contract only, with no attachment tables or files. Existing backup retention and external Telegram/provider copies remain disclosed residuals.
