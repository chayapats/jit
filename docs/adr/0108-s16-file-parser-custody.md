# Preserve interrupted FILE and parser bytes without boot recovery

The ready-file resolver excludes pending uploads and reports untracked bytes.
Opening FileStore instead rejects interrupted uploads and deletes their bytes;
FileParser.recover resets the stable container name and removes old job trees.
Neither supplies a read-only complete custody cut.

Select a protected current FILE/parser cohort under the existing installation
and CHAT exclusion. Keep receipt-pinned immutable bytes distinct from observed
untrusted fragments, unpublished originals/representations and parser snapshots.
Stream hashes with bounded private no-follow handles, retain original row states
and include every known leftover. Unknown names, missing required input, corrupt
hashes or unsafe/over-bound trees refuse instead of shrinking the cohort.

The parser mounts input read-only and publishes bounded stdout files to the host
only after container cleanup. A dead service cannot later publish that stdout;
an orphan may still retain read-only input. Record its stable current namespace
and explicitly unobserved job/image/settlement rather than inventing a request
mapping from equal input bytes. The configured image is not proof of an orphan's
generation. No container query, reset, parser execution or deletion occurs.

Copying arbitrary directory trees would include unowned files and treat unsafe
parser output as usable input. Discarding all scratch would lose original
uncertainty and private byte custody. Closed owning names and separate untrusted
roles preserve that evidence without granting receipt, model or work authority.
Revalidate the original inode/absence/metadata/byte cut before publication.

This component does not settle interrupted uploads or orphan containers, promote
parser output, enable binary support, change installed policy or provide complete
aggregate recovery. Owning forward reconciliation, physical retention and the
remaining backend/client/aggregate lifecycle remain #429 requirements.
