# ADR 0019: Bounded memory extraction and active lineage

Status: accepted for MEM01 engineering choices (Jit #23). Requirements: FR-04/05/10/14/15/17 and NFR-05/07/10/11.

The confirmed decisions remain in CONTEXT.md, the MVP spec and ADR 0003. Memory is derived application state with origin and evidence. It cannot create owner preferences, decisions, accepted tasks, execution authority or model configuration. Correction, forget/delete and cross-project context assembly remain later slices.

Schema v11 adds immutable logical extractions and claims. The explicit Web owner command selects an exact committed source, configured role and finite budgets. This is a bounded source-at-a-time extraction seam, without implicit standing authorization or automatic scans. The unique extractor/policy/source revision/generation key prevents repeated requests from starting another logical extraction. Extraction output is never registered as a source, so it cannot recursively feed itself. Existing task/proposal and discussion sources can be selected; authoritative task/decision status still comes from project continuity, never memory text.

The captured effective route, configuration, source and admitted claim manifest pass through the existing application run port and background queue. Each admitted attempt creates an independent managed context; queued work has no prematurely created native context. Run authority, current source revisions/generations and every admitted claim's transitive lineage are checked before dispatch/reservation/publication. Explicit interrupted-read resume uses the existing reconciliation and remaining budgets. No engine/provider loop or fallback is added.

Model output must contain bounded JSON with exact source references and verbatim supporting quotes. An explicit fact is restricted to the exact quoted owner-attributed statement and has no admitted derived claims. It means the owner said those words, without proving an external fact or accepting a task/decision. All other claims remain inference. Invalid assertions are rejected and incomplete extraction stays partial; a finished response is insufficient. Claims conservatively inherit every admitted claim, including undeclared model dependencies. Conflict references retain both assertions and never overwrite either.

A backward-compatible `WorkOutcome` partial variant lets the shared attempt gate atomically persist validated partial results plus incomplete status. Its producer runs under the same transaction/fence as succeeded results. Waiting/yield/failed retain their existing callback behavior. This avoids labelling a partially validated extraction as a successful complete job.

All memory consumers use `lookupActiveClaim`, which validates current source pointers and transitive dependency generations within depth/node ceilings. Unavailable lookups contain references/reasons without withdrawn claim text. Search is a bounded literal substring query with ASCII case folding and literal Thai/Unicode matching. The Web inspector links exact source and claim revisions, preserves conflicts and reports actual job reasons after cancellation/interruption. Private captured attempt data is not returned in memory command receipts or inspector projections.

The service currently uses scripted fixtures on the same app.run_port seam as deterministic tests. The configured production route remains unverified; JBR01 owns concrete Schway integration. The fixture quotes bounded source text and discloses truncation. This establishes state/provenance behavior, not extraction quality, live subscription access, deletion policy or physical Pi persistence.

## Review refinements

Owner-selected decision conclusions/rationales have their own exact owner-attributed source, registered in the acceptance transaction and linked to the immutable owner decision ID/revision. Migration backfills this evidence for existing decision records. Supersession fences the old decision source generation in the same transaction; authoritative decision history remains intact and continuity selects the current decision. This makes owner wording extractable without promoting a coordinator recommendation to owner authority.

Prospective lineage is checked with the new root included in the same depth/visit ceilings as reads. Oversized derived graphs are rejected as `lineage_limit`, preventing a successful but immediately unreadable claim. Unavailable claims retain non-content source/decision/dependency metadata and exact links, with no claim text/quote. Fixture excerpts are bounded against both the serialized output JSON and normalized outcome envelope, including escape overhead. A rolled-back producer faults the queue and remains interrupted for reconciliation, rather than accepting a subsequent returned failure as a replacement commit.
