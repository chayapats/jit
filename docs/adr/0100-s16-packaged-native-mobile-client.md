## Native boundary and lifecycle

The client is a native React renderer. It never loads a protected service page into an authenticated WebView. Expo Fetch's inspected native sources support manual/error redirects and omit the cookie jar when `credentials: omit`; the adapter always sets these explicitly. Validate the complete bounded body through its streaming response clone and return the real Expo response. SDK 58 still leaves RN's nonstreaming global Response and ArrayBuffer-incompatible Blob constructors installed; do not reconstruct native responses with those globals. On iOS the public `ExpoFetchCustomExtension` configures an ephemeral, cache-free, cookie-free URL session before React starts. Request and response `no-store` and Android's uncached native client retain no private HTTP cache. Exact full origin includes the port. Only literal-loopback HTTP is allowed for development; remote services need HTTPS and normal platform TLS validation. No certificate bypass, alternate auth server, bearer credential URL or global cookie sharing.

Reuse the actual service's `/s14/login` password POST and exact 303 session cookie; do not follow its redirect. The native adapter stores only the bounded expiring cookie in the platform SecureStore, keyed by a hash of the complete canonical origin, with device-only/unlocked custody where supported. CSRF remains ephemeral in `JitClient`. The service remains authoritative on every request. A native storage failure is visible; there is no plaintext fallback. Sign out removes only this client's local credential and state; it does not change the owner's account or server policy.

Inactive/background, service/target switch, authentication failure and explicit reconnect advance a generation, abort outstanding reads/capture and remove private projections before I/O. Late work cannot restore them. Foreground restores only after fresh authenticated bootstrap and target reads; no saved private thread fallback. Native app-switcher protection covers inactive snapshots independently of delayed JavaScript. A bounded original mutation identity can survive uncertainty; restart/foreground only reads its owning receipt. Sending again is explicit and reuses the immutable command identity, never a reconstructed effect or automatic offline queue. Same-session RAM drafts may return only after authenticated continuity revalidation; service/session changes discard them.

Native privacy refinement, 2026-11-20: inspected `expo-screen-capture` 58.0.6. Its iOS app-switcher blur animates and removes itself on native activation without waiting for the JavaScript projection fence. Select a small authored local Expo module instead: an opaque window cover and monotonic native lifecycle epoch, installed before React starts. iOS native resign/activate notifications and Android Activity pause/resume hooks cover synchronously; foreground retains the cover until the newly fenced public root has actually laid out and acknowledges the exact active epoch. An old layout/epoch cannot uncover it. Android marks the covered/inactive window secure, clearing that flag only on a valid current acknowledgement; ordinary validated foreground screenshots remain possible. This module has no command, credential, URL or approval API. It replaces the screen-capture dependency rather than importing an unsupported secure-text-field trick or claiming blur as fresh-read proof. Actual packaged lifecycle/layout evidence is still required.

Native notice/deep-link input selects only a previously configured service hash and validated opaque document/object IDs. It cannot add a service, provide a cookie, construct a command or approve an action. Opening always performs current authenticated reads; approval binds the displayed current revision/hash and one new decision identity through existing CHAT.

## Files, audio and native delivery

Use the native document picker, with cancellation leaving the draft/identity unchanged. Selected bounded bytes pass through existing upload identity/hash/type and sanitizer contracts. A cancelled picker is not an upload or send. Downloads and previews recheck current service/lineage; private bytes are not public URL/cache entries. HTML alone uses a disposable nonpersistent WebView with no Jit cookies, scripts, host bridge, network, file access or parent navigation. Other results use native text/image views. Files are explicitly exported through an owner-selected native destination, never a generic host command.

Export refinement: SDK 58's iOS file creation checks existence and then removes the path before creating it, leaving a destructive race. Use a small authored `openat(O_CREAT | O_EXCL | O_NOFOLLOW)` writer in the currently selected security-scoped directory; existing names/symlinks fail without removal. A write failure may leave its newly created partial file and never removes a name another process could have replaced. Android accepts only the owner's SAF `content:` directory and uses its create-document result, never a raw filesystem overwrite path. Both paths receive freshly guarded immutable artifact bytes after the OS sheet returns. This adapter has no credential or HTML bridge.

RN 0.88.1 also routes ArrayBuffer Request bodies through its incompatible Blob constructor. Select an additive shared-client `fetchBytes(request, bytes)` injection for binary uploads: the bodyless Request carries the original exact metadata/signal and the immutable byte snapshot goes through the same native boundary. Ordinary browser callers keep the original Fetch path. Avoid a broad global Request/Blob shim or a second upload protocol.

Native microphone use starts only from a visible gesture after current voice capability/quota checks and OS permission. Expo Audio's actual PCM buffers retain their reported sample rate/channel count; bounded authored conversion supplies the existing canonical mono 16 kHz WAV contract. No cloud speech route, raw audio persistence or background capture is introduced. Background, target change, cancel and finite limits stop native capture and fence late data. Permission denial/restoration is a real product state. Simulator signals do not establish microphone quality or Thai accuracy.

Audio lifecycle refinement, 2026-11-20: inspection of SDK 58's native `AudioModule` shows its lifecycle handlers track players/recorders, but not `AudioStream`. Its background-recording plugin flag alone cannot establish this contract. Keep Expo Audio's public permission API and add an authored bounded native PCM adapter alongside the lifecycle module. It uses public AVAudioEngine/AudioRecord APIs, no SDK internals or patched dependency. A native-issued single-use lease binds the current native epoch and finite limit (at most 30 seconds); prepare/start/finish all reject stale epochs, and cancel-before-start consumes the lease. Every native lifecycle transition synchronously stops capture and discards its lease/data, independently of JavaScript. Native interruption/read failure is terminal, with no automatic restart. PCM remains in bounded RAM only, with actual sample rate, and is exposed only by an explicit current-epoch finish. The shared conversion kernel emits canonical mono 16 kHz PCM16 WAV. This is a narrow capture capability, separate from the gate's visibility methods, never an authenticated command or HTML bridge. Public API references: [Apple AVAudioEngine](https://developer.apple.com/documentation/avfaudio/avaudioengine), [Android AudioRecord](https://developer.android.com/reference/android/media/AudioRecord).

Final audio dependency refinement: the authored capture adapter makes the broad Expo Audio runtime redundant. Remove `expo-audio` after its inspection/compile experiment. The adapter uses AVAudioSession's public permission API on iOS and ExpoModulesCore's public permission-manager helper on Android; the renderer receives only the OS permission result. This retains the same native lease/PCM and permission-denial behavior while removing unused players, recorders, playback services and their native dependencies. Regenerate the frozen client/native inventories and rebuild both platforms after removal; the earlier Expo Audio pin is historical comparison, not a final shipped dependency.

Final package inspection: the actual Expo Android release inherited overlay and broad external-storage permissions that the authored SAF picker/capture workflow never uses. Block those permissions explicitly alongside advertising permissions. Also, the inspected Expo public-config exporter retains `android.googleServicesFile`; a controlled probe confirmed it exposes the local source path. Select that public client file only during the explicit CNG prebuild stage, then remove its environment input before compilation/bundling. Runtime public configuration carries no build-machine client-file path. Keep the validated public client bytes only in ignored build staging and the generated native project, not a private-path public config field.

Native notification readiness additionally reads only a local platform capability boolean: Android must have the generated public `google_app_id` resource before Enable can request OS permission. This lookup acquires no token or account and does not initialize Firebase. iOS retains its supported APNs token API and reports an unavailable SDK result truthfully. A known native-configuration/token acquisition failure is unavailable; an uncertain service subscription POST remains uncertain and uses original-token read-only recovery. Removing an old subscription remains possible without a newly configured native SDK.

Web Push (#441) remains unchanged. Add explicit protected native push adapters for direct APNs and FCM, rather than introducing Expo Push Service/EAS accounts. Reuse existing `NoticeProducer` identities/projections with a separate opt-in native notification journal and delivery queue. A subscription belongs to the current owner generation. New native stores are additive composition inventory; omitted configuration creates nothing and preserves every existing runtime default. The contract specifies exact register/read/remove and delivery recovery bounds.

APNs/FCM credentials stay on the protected service, never in app bundles, working execution, public logs or exports. Only fixed provider endpoints receive generic notices with opaque IDs/path/service hash; no result, message, recipient, amount, filename, session or approval authority. Provider acceptance is not device delivery. Missing configuration/OS permission returns capability-unavailable state. Live provider credentials/signing/device acceptance remain #431; no absent account blocks deterministic adapter or owning-service proofs.

Android delivery dependency refinement: actual release resolution includes Google Play Services/Install Referrer components under Android SDK terms as well as Apache/BSD/MIT dependencies; it is not an MIT-only distribution. Retain their exact POM/artifact hashes and applicable notices/terms. This is the cost of the selected direct FCM native path; the Web Push baseline remains usable without native enrollment. Force Firebase messaging auto-init and default data collection off in the native manifest before startup, and permanently deactivate analytics/ad-ID/screen collection. The inspected Expo token method calls `FirebaseMessaging.getInstance().token` explicitly without enabling auto-init. Only the authored opt-in/current-token check calls it; no Expo relay or analytics route is selected. Real Google configuration and device behavior remain separately verified acceptance.

## Review refinements, 2026-11-20

Work navigation retains one bounded read across unchanged bootstrap polls, with one latest navigation follow-up. Real request cancellation applies to view/lifecycle replacement, while authentication failures retain their ordinary full-session fence. This fixes slow-list starvation without caching a private fallback or starting work.

An original upload-create lookup is additive and capability-advertised (`s16-upload-creation/v1`); it reads the existing owner/generation/conversation-bound journal identity. Same-session RAM chips retain metadata/hash, not bytes. A confirmed empty original upload may be finished only by a fresh explicit picker selection with the same name/size/hash and current state. Unknown outcomes never create a replacement upload or replay bytes automatically. Older services without the capability show an unavailable recovery control; known-ID status remains compatible.

Release compilation uses a new snapshot of the exact committed Git tree, with every ordinary file byte/mode checked before frozen installs and clean CNG. It excludes and preserves original ignored native projects rather than trusting their contents. The complete artifact seal includes a path-free build-source receipt; Apple input checks inspect the snapshot's actual Pods. This is a build-integrity correction, not native UI/device acceptance.

Corresponding-source refinement: the bundled Public Suffix List is reconstructed from the exact OkHttp JAR selected by the frozen Android runtime inventory. Notice generation and release preflight require matching Maven coordinate/JAR hash, source hash, modified-file header, shipped text and public provenance. A different cached OkHttp version cannot qualify merely because its own source hash matches. Existing dependency discovery records remain separately attributed; no runtime dependency or permission changes.

Review recovery refinement, 2026-11-22: explicit local sign-out deletion is a serialized per-origin storage intent, not a request-generation publication. Background/reconnect cannot silently cancel it; later explicit login writes retain their queue order and deletion failure remains visible. The renderer uses a native-safe receipt/composer coordinator under current service/session/target pins: only confirmed message recovery clears its draft. A decision receipt preserves unrelated text/upload chips and performs no repeated POST. Owning-service lost-reply/effect assertions and held SecureStore races cover these paths; they do not replace packaged native UI acceptance.
