# Conversational admission and result continuity

## Implemented CHAT15-01 refinement, 2026-11-03

`src/s15/conversation/` implements a smaller opt-in server/API contract. A conservative deterministic original-text grammar replaces the proposed model/bootstrap/opaque-grounding pipeline: supported clear English/Thai requests start directly; unknown material scope is held. Installed standing policy still supplies purpose/resources/finite cost limits, and trusted VM/broker adapters own actual I/O gates. No model output can acquire owner authority. S14 remains the default and retains its own store/commands.

One protected SQLite journal with exclusive process ownership commits request identities, queues, claims, observed tool evidence and events. Policy admission is idempotent; a stranded policy admission cannot dispatch without the local committed queue. Every physical Schway stream is guarded/charged; every tool call is claimed before invocation. A lost claimed run is reconcile-only, while retained results are read without rerunning work and recheck current policy. This avoids implementing the speculative full schema, cross-domain transaction coordinator, conversational approval parsing or another agent loop. Runtime contracts are exported TSDoc, with deterministic public-host tests; real VM/browser/host acceptance remains separate.

The owner selected RT15-01 option B on 2026-11-03: root in an expendable working VM, valuable data/credentials/external effects outside it, protected snapshot recovery; arm64 uses Lima and x64 uses an owner-created Proxmox VM later. This resolves the previously open owner tradeoff, without claiming actual isolation/egress/platform proof or activating any host. Historical preparation statements below describe the earlier proposal rather than the current decision.

## Proposed decisions

1. **Authenticate before interpretation and bound interpretation itself.** Protected ingress binds real owner/request/transport/source provenance. A current preapproved bootstrap scope authorizes only necessary interpretation reads and approved inference recipients, with finite per-I/O reservations before context or model calls. An untrusted classifier cannot grant that bootstrap scope or approve execution. A protected semantic resolver must ground proposals in original owner-authored bytes, distinguish quotes/negation/acceptance/inspection and validate current catalogs. Its actual algorithm and language coverage remain explicit implementation freeze obligations, not a claim solved by an opaque type.
2. **Keep one durable request identity across stages.** Initial receipt/source/interpretation intent commit atomically. Later grounded admission atomically binds that same root request to exact purpose/outcome/completion/subject, current policy/resources/Bot/route/model/recipients, finite ceilings, owning policy authority and one work queue. Continuation appends a new authenticated source and resolves only the exact missing datum; it cannot silently broaden purpose or duplicate a start. Receipt hashes precede admission hashes, avoiding self-reference. Full target schema and transaction coordinator are not delivered here.
3. **Separate obligation, inspection, execution, ambiguity and approval.** Clear execution and one-message select/start proceed within existing authority without a new ceremony. Inspect cannot mutate or implement. A material ambiguity holds its uncertain portion once while independent authorized inspection can proceed. Natural action approval must resolve exactly one current prepared action through #320; the separate approval journal does not change prepared action revision/hash. No model/attachment/source/role/hash can authenticate or approve itself.
4. **Compose only Schway public execution.** Keep Schway's native loop/providers/retries/compaction/sessions. Exact tools adapt through the proposed actor-bound VM/browser ports. A public Model forwarding wrapper guards every actual stream, including retries/compaction, without implementing another retry loop or provider protocol. Context/image recipients and bytes are checked before disclosure and after waits. No private imports, protected-host shell fallback or invented Schway blocker.
5. **Expose complete result/cancel/publication paths.** Registered dispatch produces a retained capture, committed evidence/reply, guarded read and synchronous final publication. Async image/file/channel release reacquires its current guard. Signal cancellation and explicit stop share memoized original-scope cleanup; timeout/abort/native completion does not certify external settlement. Preserve #320 original-context exact reservation continuation, #321 guarded readResult/publishResult, and #322 action-or-read emitter plus explicit original child charge history. New uncharged reads at zero allowance refuse.
6. **Keep progress, evidence, settlement and delivery independent.** Bounded provisional progress grants no durable completion. Evidence commit, actual channel/operation/process settlement and final publication have separate facts/events. Stop/revoke fences new dispatch/late content without erasing captured response/input/network/channel/usage facts or refunding nonrefundable charges. Rejected proof cannot rewind known facts. Owner delivery is ordinary output with current access/recipient checks; unknown channel delivery remains reconcile-only, with no reconnect resend.
7. **Preserve one current continuity authority.** Installation-wide request/source-event/dedupe/claim/receipt identities, usage, withdrawals and policy revocations survive restart/restore/rollback. Lost contexts cannot be reconstructed from serialized claims; unknown work/effects never blindly replay. Old grants/approvals/routines remain nondispatchable, S14-private data/accounts stay restricted and native workspaces remain fixed/opaque. No raw native/profile relocation/copy/promotion, inherited numeric allowance/readiness, permanent-Bot policy or Jod integration.

## Alternatives and consequences

- Reinterpreting S14 `message.post` would silently mutate a shipped tool-free contract. Separate versioning allows later explicit activation while reusing proven receipt/fence concepts.
- Running a model first and asking it whether policy allows its prompt would disclose data and spend before authority existed. Bootstrap resolution and per-I/O charges add bookkeeping but remove that circularity.
- Treating a model classification, owner role label or source quote as execution/approval would confuse provenance with intent. Trusted original-byte grounding and current-policy validation require concrete implementation evidence; ambiguous material scope stays held.
- A second acceptance/start command solely for internal state convenience would violate the confirmed conversational target. Atomic internal admission handles clear selection/start without another owner message.
- Returning raw model/tool output or treating a transient progress event as final bypasses source/recipient/cancel fences. Retained evidence plus final guarded publication costs additional identity/state but permits honest partial/unknown outcomes.
- Replaying an old queue or resetting a usage ledger after crash can duplicate effects or renew authority. Conservative nonrefundable upper bounds and reconcile-only lost claims may reduce available budget; the agent cannot increase it to compensate.
