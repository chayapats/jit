# Exact file ancestry through memory and conversation history

Extend the existing protected MEM/TEAM services rather than add another memory database or mirror revocation flags. An immutable metadata pin names the exact original file source/resource generations, original hash and validated representation hash. It contains no principal, path, source bytes or permission. FileStore remains the owner of source availability and byte integrity. TEAM/MEM carry complete pins through parents, retained claims, context/native derivatives, corrections and uncited summaries. Current source status is consulted before relevance and current selected bytes before release; no cached permit survives a wait.

Explicit `files.memory` composition, selected from credential-free runtime configuration, enables `s16-file-memory/v1`. Text-only and binary file custody work independently of memory. Existing installations and file configurations retain the prior memory/history fence unless opted in. The first file-bearing command under this contract stamps CHAT format 4; TEAM stamps format 2 for file pins. MEM uses format 3 for disjoint host derivative keys and format 4 with file pins. New readers retain legacy MEM 1 and, when file-aware, 2 compatibility. Only file-aware readers accept 4; older prefix writers refuse 3/4 before writable open. No table conversion, legacy/private promotion, owner-host change or authority grant occurs.

Generated native/summary/artifact derivative IDs use a closed colon namespace unavailable to public request IDs. Both prefixed short keys and public aliases of hashed long keys otherwise collide in the shared derivatives table. Namespace writes stamp the new format transactionally, so rolling back cannot reintroduce the older writer. Legacy rows remain in place; conflicting legacy reuse fails closed. Updates preserve derivative kind, owning work, all ancestry and retirement. Source IDs remain separately conflict-checked by exact source metadata.

Retain actual complete observed text lines, including lines reconstructed across actual read ranges from guarded file reads, with exact source pins and resource/retention ceilings. Do not extract facts from filenames, projected tool metadata or unread bytes. Work-origin statements retain the existing unconfirmed-inference classification. Complete model answers may contribute locally extracted, explicitly unconfirmed inferences; they inherit every selected/context ancestor. Images use actual admitted pixel evidence and their immutable representation pins, never a filename-only observation. Existing conservative extraction and suppression remain; model citations cannot delete ancestry.

Metadata queries distinguish claim/packet/history ancestry from payload retrieval. An ordinary work receiver must have the original pinned resources and current TEAM/private Bot permissions. Isolated interpretation remains an inference-only authority with no tools or resource dispatch. Its dedicated history projection may read only owner/assistant fragments already bound to currently permitted standing resources and the current Bot. This is the same limited privacy projection already used for ordinary history; it is not a reconstructed working actor. The protected caller explicitly binds the configured approved Bot rather than the first policy Bot. Exact file pins are included in the final DATA15 model-disclosure check on every physical inference send, including auth retry. Retired, missing, private-to-another-Bot or unavailable fragments are omitted before context construction; a selected fragment that changes while waiting fences the send.

Cross-ledger ordering stays conservative. TEAM capture commits before MEM retention; a stranded TEAM source has no adopted claim. MEM context commits before CHAT binds it; missing context fences publication. File withdrawal commits once in FileStore, and every future consumer reads that owning fact. Forget/correct withdraws TEAM before MEM tombstones, as in ADR 0071; interruption can only withhold more. Corrections preserve original file/resource/private ceilings. Suppression retains normalized fingerprints/lengths, not erased private bytes. Generated paraphrases bound to retired file ancestry cannot silently recreate a memory source; a fresh explicit file task remains separate from automatic retention. Exact packet ancestry avoids treating every historical file on a generic computer as a dependency of clean unrelated work.

File-derived artifacts remain staged until CHAT commits references. Their producing packet and selected sources are guarded on preview/download, including after restart and after an owner forget/correction. Previously downloaded or provider-observed content cannot be recalled. Protected audit/native custody is not forensic erasure. Each new request uses fresh Schway native ownership; no private transcript/session is resumed or copied to another Bot/model.

The authored source/impact/correct/forget surfaces reuse the current protected memory API. The S16 client advertises the versioned enabled contract only with the complete composition and shows current provenance/availability. Full memory search/client lifecycle remains #416; file-to-VM, library/revision and other-client consumers must use the same precise ancestry, not infer permission from storage. Existing producer, policy, resource, expiry and private-scope fences remain unchanged in this slice.

Acceptance requires composed file observation → retained sourced fact → later authorized request/model input, plus exact-recipient refusal, private scope, uncited descendants, file withdrawal, correction/forget, live-wait/send fencing, history filtering, clean unrelated work, restart and rollback refusal. Controlled fixtures establish these runtime contracts, not live account/device/host acceptance.
