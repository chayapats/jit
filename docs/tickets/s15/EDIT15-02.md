## Deliverable
A requested reversible document/task edit applies to an approved personal resource with observed version/diff/result evidence, while sharing, invitations and new private recipients remain held.

## Implementation steps
1. Freeze a versioned reversible-personal-record contract over current policy/browser/effect boundaries.
2. Use one controlled document/task service as the reference integrationless browser workflow; record exact approved account/resource, read version and intended change.
3. Apply and verify ordinary edits without per-record approval; preserve undo/recovery information where available and stop on stale versions.
4. Hold sharing, notifications to other people, destructive/bulk edits and uploads to a new private recipient. Real provider-specific support needs its own reviewed binding and opt-in evidence.

## Acceptance criteria
- [ ] An ordinary owner-requested document/task change completes without a Work switch or repeated approval, with actually observed resulting content.
- [ ] Only the approved resource/account/purpose is used; ambiguous or stale versions cannot cause a silent overwrite.
- [ ] Sharing/invitations/external notifications and a new private-data recipient encounter their applicable human gate.
- [ ] A crash or uncertain save reconciles before retry and partial/unsupported changes are reported honestly.
- [ ] Controlled fixture support does not claim universal Google Docs, task provider or arbitrary website write support.

## Tests and evidence
1. Controlled editable-document and task fixtures -> ordinary reversible changes and actual read-back evidence.
2. Version race, sharing/notification and new-recipient fixtures -> hold/refuse before the sensitive effect.
3. Interrupted save, duplicate ingress and revoked scope -> reconcile/fence without duplicate or incorrect edits.
