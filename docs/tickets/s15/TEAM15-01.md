## Deliverable
Two enabled Bots can collaborate on authorized shared team resources with independent context and coordinated mutations/input, without per-Bot account/share setup.

## Implementation steps
1. Implement the reviewed team/resource scope under standing policy and preserve explicit narrower restrictions.
2. Bind handoffs and shared snapshots/working files to source lineage, purpose and current generations.
3. Coordinate mutable workspace and exclusive browser input while allowing independent work to overlap under finite ceilings.
4. Keep existing private S14 material restricted until the explicit transition contract authorizes promotion.

## Acceptance criteria
- [ ] Two Bots complete a representative shared-resource task without a second owner grant and with genuine independent work where safe.
- [ ] Narrower Bot/data restrictions deny access before relevance or tool use.
- [ ] One browser input owner and controlled conflicting file writes prevent collisions.
- [ ] Revocation/cancellation fences late handoff/result publication without discarding valid sibling evidence.
- [ ] No raw account token/session copy or implicit legacy-private promotion accompanies team access.

## Tests and evidence
1. Barrier fixtures -> overlap for independent reads and serialized conflicting input/writes.
2. Restricted/private source and revoke-during-handoff fixtures -> no disclosure/publication.
3. Sibling failure/stop -> successful evidence retained with honest partial result.
