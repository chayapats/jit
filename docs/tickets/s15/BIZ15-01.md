## Deliverable
A controlled business-record workflow updates factual notes/classifications under an approved existing rule, while prices, commitments and major changes wait.

## Implementation steps
1. Specify a bounded reference record/action model and approved resource/rule revision using a controlled fixture service, not an invented production CRM.
2. Implement read/version/diff/commit evidence through a reviewed mediated route.
3. Separate factual/internal edits from notification triggers, prices/discounts/contracts and changes to the governing business rule.
4. Require a future resource-specific adapter/approval for any real CRM/service not yet covered.

## Acceptance criteria
- [ ] An evidenced note/classification edit applies under current policy without per-record approval.
- [ ] Unverified facts, new pricing/discount/contract terms or changed business rules are proposals with evidence/recommendation.
- [ ] A record edit that sends notifications, triggers fulfillment or spends money encounters the applicable gate.
- [ ] Concurrent record changes and stale policy versions prevent an unintended update.
- [ ] Fixture support is not reported as support for an arbitrary production business system.

## Tests and evidence
1. Reference record fixtures -> factual edit executes; inference/price/commitment edit waits.
2. Hidden notification/fulfillment/payment side-effect fixture -> hold/refuse before commit.
3. Record-version and rule-revocation races -> no stale write, honest actionable result.
