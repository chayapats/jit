## Deliverable
A supported execution backend performs real working-VM file/shell/admin tasks while protected authority and credentials remain outside guest control.

## Implementation steps
1. Implement only the reviewed ARCH15-01 transport/administration boundary through public Schway backend contracts.
2. Bind VM identity, attempt/generation, resource ceilings, cancellation and operation receipts to current policy.
3. Exercise file processing, program/dependency installation, sudo/admin, Docker and ordinary service setup under the reviewed boundary.
4. Deny protected-state/session/control access and alternate network/effect paths; leave unproven capabilities inactive until EVID15-01.

## Acceptance criteria
- [ ] Commands execute in the named working VM, with no accidental protected-host shell fallback.
- [ ] The required administration operations actually work; a read-only substitute is not reported as full administration.
- [ ] Protected credentials/state/approval controls cannot be read, mounted, overwritten or reached via guest-local control changes.
- [ ] Stop/revoke fences late outputs; cancellation retains capacity until settlement.
- [ ] Destructive-operation limits and recovery/prevention distinctions match the reviewed contract and are disclosed.
