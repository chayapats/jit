## Model tier
Frontier: first-run owner authentication and route selection are security-sensitive and need design decisions.

## Status
Found during Opus UI work on PR #264. Required before the S14 default flips.

## Context to read
AGENTS.md, CONTEXT.md, docs/specs/S14-bot-first-local-assistant.md, docs/contracts/s14-foundation-http.md, docs/design/S14-bot-first-experience.md section 16, and src/s14/.

## Deliverable
A fresh S14 install reaches a working first conversation from the Web UI alone, and the owner can dismiss proposed tasks, start another conversation and change language and theme.

## Implementation steps
1. Add first-owner credential setup through the existing one-time local setup capability, with no terminal step after install.
2. Derive configured routes from signed-in providers so `JIT_S14_ROUTES` is never required. The owner picks a route, never a model ID or auth alias.
3. Add typed commands for task rejection, conversation creation and owner preferences.
4. Make the Web refusal page the default browser behaviour for a legacy store.
5. Build the Opus-authored states for all of the above.

## Acceptance criteria
- [ ] Fresh install to first reply needs no shell step and no environment variable.
- [ ] Duplicate or stale commands return one logical result or refuse.
- [ ] Task rejection grants nothing and is retained in history.
- [ ] A legacy store still refuses before any write or worker.

## Tests and evidence
1. Scripted fresh setup with no routes configured, then device sign-in, then first reply.
2. Replay and stale cases for each new command.
3. Thai and English, dark and light, no-script forms.
