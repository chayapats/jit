## Deliverable
The installer detects that subordinate ids fall outside the parent user-namespace mapping and reports it instead of assigning an unreachable range.

## Implementation steps
1. Read `/proc/self/uid_map` and `/proc/self/gid_map` inside `subordinateIds` or its caller.
2. When the default 65536 range is unreachable, leave core chat working and report container features as unavailable with the exact host change needed.
3. Do not silently shrink a normal 65536 allocation.

## Acceptance criteria
- [ ] Nested mapping of 65536 ids produces a clear reason and next action.
- [ ] A host with a full mapping allocates exactly as before.
- [ ] Re-running the installer stays idempotent.

## Tests and evidence
1. Fixture mappings: full host, 65536-id LXC, and a larger delegated range.
2. Existing subordinate entries are preserved.
