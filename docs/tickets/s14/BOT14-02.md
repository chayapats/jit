## Deliverable
The owner revises an existing Bot capability policy, retires it, or deletes its named data through revision-bound commands, with preview, fencing and lifecycle propagation. Computer reset remains a separate BOX14-01 action.

## Implementation steps
1. Specify typed capability-change, retire and delete command/query shapes, revisions, generation transitions, idempotent receipts and preview binding. State the main-Jit lifecycle constraint explicitly; do not silently remove the installation coordinator.
2. Accept capability widening only from the authenticated owner accepting the exact current proposal; intersect it with all live resource/work policies. Narrowing/retirement fences new admissions and old attempts, queued dispatch, browser input and publication immediately; retain stopping until transports settle.
3. Retirement preserves explicitly retained history/evidence but disables work and routine dispatch. Define any owner re-enable as a new generation requiring current grants, never resurrection of old authority.
4. Deletion previews owned sources/private claims/artifacts/computer/native contexts, dependent shares and retained lineage. Revalidate the exact preview revision, append lifecycle tombstones before destructive cleanup, retire affected contexts and make interrupted cleanup retry-safe. Preserve unrelated Bots and independently owned shared originals.
5. Record actual supported signatures/schema/version and exported TSDoc before dependent slices consume them.
6. Check ownership, existing branches/PRs and landed prerequisites; use an issue-specific branch/worktree. Any missing UI/UX must be delegated to Claude Opus 5.5 at effort high before implementation.

## Acceptance criteria
- [ ] Duplicate owner commands return one logical receipt; stale previews/proposals and unauthenticated, model or retrieved-content changes are refused.
- [ ] A capability increase never expands grants/accounts implicitly. Revoked/reduced policy rejects in-flight tool/publication results and future use of old contexts.
- [ ] A retired Bot receives no new work/routine dispatch. Deleting a computer alone does not retire/delete the Bot; retiring a Bot alone does not silently erase its history.
- [ ] Delete/forget propagation reaches owned data, share derivatives, caches and native replay without deleting another Bot's independently owned data; already disclosed knowledge is not claimed to be erased.
- [ ] A crash, late worker, duplicate cleanup or subsequent restore cannot revive deleted data, enabled generations or revoked authority. Lifecycle ledger reconciliation precedes worker activation.
- [ ] Thai/English, keyboard and no-script command outcomes match Opus-authored UI; absent prototype states are not treated as implemented design.
- [ ] Record final build/revision, checks, unrun evidence and remaining blockers.

## Tests and evidence

3. Crash before/after tombstone and each cleanup stage; native-context invalidation and old-image lifecycle reconciliation using fixtures. Check isolation of unrelated Bot data.
