## Deliverable
The owner creates a versioned credential-free backup of the fresh S14 store and restores it through quarantine, lifecycle reconciliation and atomic activation. Workers remain fenced until validation/recovery completes. Fresh state waives legacy conversion only.

## Implementation steps
1. Specify versioned manifest and consistency protocol for application state, bounded immutable artifacts, opaque supported native-session snapshots and lifecycle metadata. Define integrity hashes, size/path bounds, schema/contract compatibility, interrupted capture and retention. Exclude provider/Jit/channel/vault credentials and raw website-session profiles from ordinary backup/export.
2. Fence/quiesce writers for a consistent capture or use a verified snapshot mechanism. Record a backup receipt only after every required component is durable and verified; partial captures stay unusable and cannot masquerade as complete backups.
3. Restore to a separate quarantined candidate. Validate type/size/path/hash/version and supported opaque native restore capabilities. Reconcile the current append-only lifecycle ledger outside rollback images before data is readable or any worker starts; missing current ledger evidence fails closed.
4. Stage supported future S14 schema upgrades with a recovery point, documented version matrix and atomic activation. Reject legacy/unsupported formats before writes. Keep the prior active installation intact until exact owner-authorized cutover; rollback must also apply current lifecycle tombstones.
5. Before activation retire/fence old attempts and input/native sessions, invalidate stale grants/approvals as required and apply REC14-01 reconciliation. Unknown effects remain reconcile-only; no routine/coding/send effect is blindly replayed. Publish honest complete/partial/blocked results and an opt-in Linux backup/restore runbook.
6. Record actual supported signatures/schema/version and exported TSDoc before dependent slices consume them.
7. Check ownership, existing branches/PRs and landed prerequisites; use an issue-specific branch/worktree. Any missing UI/UX must be delegated to Claude Opus 5.5 at effort high before implementation.

## Acceptance criteria
- [ ] A new-store backup actually contains consistent state/artifacts/opaque native snapshots and versioned lifecycle metadata, with an integrity-checked manifest. Unsupported snapshot support blocks completion instead of silently dropping sessions.
- [ ] No service credential, raw browser cookie/profile or host path secret appears in archive, prompts, logs or ordinary exports; restoring requires explicit re-connection where needed.
- [ ] Corrupt, oversized, traversal/symlink, incompatible or incomplete inputs cannot modify the active store or start a worker.
- [ ] An old backup cannot resurrect forgotten/deleted data, retired Bot generations, revoked shares or native context. Reconcile the latest independent lifecycle ledger first; a missing ledger cannot be replaced with the backup's older copy.
- [ ] Crash at capture, import, schema upgrade or cutover is recoverable with one active generation. Do not resume old authority, unsettled transports or unknown effects automatically.
- [ ] A round trip on each supported Linux architecture records actual application/artifact/native and lifecycle recovery results before EVID14-01 closes; fixtures do not prove host durability.
- [ ] Thai/English, keyboard and no-script command outcomes match Opus-authored UI; absent prototype states are not treated as implemented design.
- [ ] Record final build/revision, checks, unrun evidence and remaining blockers.

## Tests and evidence
1. Scripted native snapshot fixtures and fake clocks: capture → delete/revoke/retire → restore old image → reconcile latest ledger → activate, proving no resurrection and worker-order barriers.
2. Crash injection around component capture, manifest commit, upgrade transaction and atomic cutover; restore/rollback repeats and unknown-effect reconciliation.
3. Corruption, version mismatch, missing native support/ledger, traversal/symlink/bounds and credential-sentinel exclusion cases. Separate opt-in Linux x64/arm64 durability/native round-trip evidence.
