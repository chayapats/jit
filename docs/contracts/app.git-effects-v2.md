## Connections

- `git.connection.create {repositoryId,label}`, expectedRevision 0, captures one active typed repository resource. Metadata: `GitConnection={id,revision,kind:'github_token',label,repositoryId,secret:'empty'|'set',removed}`. No legacy Project exists or wildcard repository/account scope is inferred.
- `git.connection.secret.set {connectionId,secret}`, empty connection revision; `git.connection.rotate` with the same payload, set connection revision. Normalize/fingerprint via existing connection helpers and store only in `ConnectionVault`. Retry identity replaces secret with `[write-only]`; no value or value digest enters receipts/SQLite. Replayed request IDs never rewrite a value. A new opaque vault file per revision prevents a file ahead of a rolled-back transaction from replacing an older approval's credential. Old file removal can leave an old revision unavailable after rollback; repair is an explicit set/rotate, never credential fallback. Orphan staged secret files remain outside state/exports and are not released through metadata.
- `git.connection.test {connectionId}`, current revision, returns only present/missing/unsafe. `git.connection.remove`, current revision, removes the active secret file and increments/removes metadata authority. Independent append-only connection revision records fence stale-image restore and old approvals after rotation/removal.

`connections(actor):GitConnection[]` exposes metadata only. Vault IDs, filesystem paths and values have no query surface. ## Exact proposal and execution

`git.propose {attemptId,connection:{id,revision},update:{ref,oldCommit,newCommit},pr:GitPullRequest|null,expiresAt}`, expectedRevision 0. It requires the originating still-live coding attempt and explicitly owner-granted `effect_push` in its Bot/work/resource intersection. Internal `computer,coding` alone cannot propose. The captured run must have committed immutable diff/test artifacts, full head and hash; tests may have failed/skipped but remain inspectable. Content changed during tests refuses. `newCommit` must equal that exact run head. The current resource and scoped connection are checked in the same transaction.

`GitPullRequest={base,baseCommit,title,body,draft}`. Branches are exact heads, no options/wildcards/ref expressions. oldCommit is a full nonzero SHA-1 or null for branch creation; newCommit/baseCommit are full nonzero SHA-1. Base and head branch differ. Content is credential-free bounded text (title 200 characters/bytes bound, body <=12000 characters); draft is an explicit boolean.

The service creates one ordinary `Effect` with kind push, exact configured GitHub HTTPS destination, and canonical `GitAction` in content: `{version:'app.git-effects/v2',intentId,codingAttemptId,ownerGeneration,repository,connection,headCommit,diffHash,reportId,update,pr}`. Its exact actionHash therefore binds commits, reviewed diff/report, resource/revision/origin, credential metadata revision, ref compare-and-swap and all PR content. A new owner proposal gets a new identity; generic card revisions cannot substitute for the original typed proposal. Existing `approval.decide` is the sole single-use approval. Unapproved/denied/expired/stopped/changed cards cannot dispatch. This plan authorizes one push and optional one PR only, no merge/deploy/comment/update.

`perform(action,allowed):Promise<'succeeded'|'failed'|'unknown'>` is a trusted EffectPerformer installed only with a configured vault. It verifies the immutable typed proposal identity and consumes the existing durable exact-effect claim before work. Ordinary `authority.runEffect(id,revision,actionHash)` and `git.drain()` retain the foundation single-use/expiry/live-authority/call-reservation rules.

Before any credential release, the original Bot backend exports HEAD in a bounded <=16 MiB full bundle with hooks/helpers/config disabled; canonical paths, head and clean files are checked before/after export and again immediately before push. Changed files/diff/head refuse with git_approved_diff_changed. The bundle is data, never a host checkout. `CodingGitMirror.import(bundle,action):Promise<void>` creates a fresh private broker-owned bare repository with an empty template and environment, verifies bundle headers/full HEAD, imports exact objects with file transport only, runs strict fsck, verifies commit identity and recomputes exact reviewed base→head diff hash. Workspace config/hooks/alternates are never copied or executed in the broker. `verifiedPath()` refuses before verification; `close()` removes the ephemeral mirror/askpass files.

`brokerGit(directory,args,secret?)` is a trusted internal subprocess primitive with fixed hooks/fsmonitor/helpers/config/redirect/protocol settings, empty environment, finite time/output, no stderr persistence and no shell interpolation. GitHubCodingRemote pushes only from the verified mirror via HTTPS, one explicit newCommit:ref and force-with-lease=ref:oldCommit (empty for creation). The secret is confined to that authenticated service process/askpass channel. Fixed GitHub REST supports only POST pulls with the exact approved payload; redirects are refused. Unknown/5xx/malformed mutation responses remain unknown. Explicit protocol rejection can be failed; a PR rejection **after push** retains git_pr_rejected_after_push, never rolls back or repeats the push.

Each stage persists before dispatch: prepared, verifying, push_dispatching, pushed, pr_dispatching, complete, failed, unknown. `GitProgress={effectId,intentId,actionHash,stage,reason,pullNumber,verification:'none'|'protocol'|'remote_readback'}`. The broker rechecks live authority, exact parsed action and current connection immediately before every credentialed dispatch and after waits; a mutated transport argument cannot pass. Uncertain push/PR never retries. Local claims are not proof of exactly-once remote delivery.

## Read-back and recovery

`git.reconcile {effectId,actionHash}`, current unknown effect revision, queues one **read-only** remote reconciliation under explicit current owner/connection/resource authority. Duplicate owner commands return the old receipt. It works after originating attempt/grant expiry or restart without reopening a box or reauthorizing a mutation. Deleted effect payload, changed owner/Bot/resource/connection and stale revision refuse. Existing effect.reconcile remains separately labelled owner_statement and never certifies remote state.

`GitRemotePort` is a trusted service-only deterministic transport seam: push(verifiedMirror,action,secret,allowed), createPr(action,secret,allowed), readBack(action,secret,allowed). Production read-back observes exact remote refs and a bounded complete PR list. A verified result needs the approved head and, for PR creation, exactly one matching base/head/full commits/title/body/draft. Incomplete pagination, duplicate candidates, moved refs, absent matches or transport uncertainty remain unknown. Absence does not prove non-occurrence. Reconciliation performs zero push/create calls; a partial plan needs a separately proposed/approved new action to finish remaining work.

Verified remote state sets complete/remote_readback and succeeds. Identity/hash/progress-only proof is retained in independent append-only lifecycle.git_outcomes and reapplied after stale-image restore. Foundation effect_claim withdrawals fence all old mutations regardless of restored card state. Crash after claim, before/after either dispatch, before receipt or during read-back is reconcile-only; no blind retry. This verifies observed remote state, not causal or exactly-once delivery. Owner statements remain distinct from verified remote proof.

`view(actor,effectId):{effect,progress,reconcileRequested}` queries safe state; `drain():Promise<void>` claims only approved typed Git plans and requested read-backs. It never scans unknown cards for mutations. Root runs it behind `--s14` and waits for the ordinary pump at shutdown.
