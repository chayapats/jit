# app.work-graph/v1

TEAM14-01 (#251), S14-AC04/05/12; FR-02/03/14/21/27/29/31, NFR-02/05/06/10. Opt-in S14 only. Legacy route concurrency is unchanged. Types: `src/s14/graph-types.ts`, implementation: `graph.ts`, `authority.ts`, `lifecycle.ts`.

`WorkLimits` now requires `concurrency` (1–8) and `reads` (1–256), in addition to attempts/steps/calls/outputBytes/wallMs. Read reservations and inference/tool call reservations are distinct: every public read consumes both. Unknown actual usage remains null; no uncertainty is refunded. Owner-confirmed future-work defaults are 2 concurrent Bots, 1800000 ms and 40 reads. `work.defaults.set` updates only future defaults with exact revision; existing immutable grants retain their explicit limits. Forms derive finite call/attempt/output reservations and record concurrency separately from selected Bot count. More selected Bots can queue under a lower concurrency ceiling.

Public service signatures:

```ts
validateWorkGraph(grant: WorkGrant, proposed: StepProposal[]): StepProposal[];
defaultWorkGraph(grant: WorkGrant): StepProposal[];
S14Graph.propose(workId: string, expectedRevision: number, proposed: StepProposal[]): WorkGraph;
S14Graph.view(actor: OwnerActor, workId: string): GraphView;
S14Graph.defaults(actor: OwnerActor): WorkDefaults;
S14Authority.drain(): Promise<void>;
S14Authority.wake(): void;
S14Authority.shutdown(): Promise<void>;
```

`StepProposal` extends Admission with `{id,handler:'research'|'synthesis',dependsOn:string[]}`. `Admission` is `{botId,tools,scopes,input,calls,outputBytes}`. Trusted handlers validate IDs, unique edges, acyclicity, finite node count (at most min(64, attempts, steps)), aggregate call/output reservations, captured Bots/tools/resources and current authority at actual admission. Synthesis has no execution tools; it may carry only named share scopes already in the coordinator's captured grant/ceiling for authorized memory handoffs. Models cannot install a handler, grant, priority, Bot, route, resource or executable workflow. `propose` is a trusted application port for untrusted data, not an HTTP command or authorization source; it replaces only an unstarted graph within its original grant. Work start atomically installs the validated default DAG and receipt. A trusted optional `AuthorityOptions.planner` may narrow that plan; invalid plans roll back the start.

Default plan: one independent research node per selected Bot, then a synthesis node on the first selected Bot when more than one is selected. The graph must fit the explicitly granted budgets; insufficient budgets refuse the atomic start. A single-Bot command remains one run. Each host/session/context, exact tool registry, scope, call/output reservation, workspace backend and cancellation signal belongs to its run. Inputs are untrusted sections, never operator instructions. Result sources inherit all original source/access pins. A receiver must have access to every claim ancestor before a result enters its context. Inaccessible handoffs become explicit gaps; prior disclosure is no bypass.

Scheduler defaults are `{global:2,route:2,bot:1,computer:2}`. Non-secret `JIT_S14_SCHEDULER_LIMITS` is an exact finite JSON configuration (each ceiling 1–64). Route capacity counts the underlying provider credential route across model aliases. Admission intersects global, route, Bot, grant concurrency and computer capacity. Mutable computer/workspace work is exclusive per Bot even if its Bot run ceiling is larger; current owner/agent input leases also hold computer admission. Interactive graph work precedes background work, without preempting already dispatched calls. Interactive chat is checked before another admission. A committed owner command signals the existing drain through `wake()`; pending work is reconsidered without waiting for an unrelated transport to return. `wake()` does not start an idle worker or run before transaction commit. Concurrent and synchronously reentrant `drain()` calls return the same owned promise. All wake-ups reuse the same admission checks and actual transport reservations.

Persisted `attempt_transports.active` holds capacity through actual settlement, even after a provisional committed state or cancellation. Stop/revoke fences tools/publication immediately; actual slots are released only when the executor returns after native host/session cleanup. Interrupted attempts continue holding uncertain capacity. No model retry/refresh loop is added. Exclusive startup fences interrupted attempts and blocks automatic replay pending REC14-01 (#254).

`WorkStep` includes exact opaque identity, work/node/Bot/handler, revision, state/reason, attempt ID and observed `queuedAt`, `waitingAt`, `startedAt` and `settledAt` (milliseconds, null when unobserved). Independent nodes record `queuedAt` at installation; dependent nodes record `waitingAt` then and `queuedAt` when dependencies settle and the node becomes runnable. Phase starts remain recorded after later transitions; they are not run time. Only `startedAt`/`settledAt` measure actual transport. `queueCeiling:'global'|'work'|'route'|'bot'|'computer'|null` names the first held ceiling in that order; the graph query recomputes it for queued lanes from current reservations/leases. Work means grant concurrency; computer includes the finite process ceiling, exclusive workspace and live input leases. Null means no current capacity hold, not an admitted run. Waiting lanes have dependency reasons rather than a capacity ceiling. A stop requests `stopping`, followed by cancelled only at settlement. Work stop cancels queued lanes and fences all dispatched lanes; `work.step.stop` affects only the named exact lane. Its receipt includes `{kind,requestId,step,conversationId}` from the work record, so a pane action returns to `/chats/:conversationId?work=:workId#latest` without another lookup or request-supplied redirect. Dependencies wait until terminal sibling state and actual settlement. Research dependencies require committed usable inputs. Synthesis may use a successful subset plus explicit failed/cancelled/inaccessible gaps. Failed siblings cannot delete successful rows or claim complete coverage. `ready` remains inspectable review evidence, not complete-report certification; REPORT14-01 adds that independent validation.

The graph tables first landed in unreleased schema 7; final bundled schema **9** additionally stores report review and typed gap/phase records; the combined store includes reports/artifacts and work_defaults, work_graphs, work_steps, attempt_transports and grant_usage.reads. Earlier unreleased schemas 1–8 refuse with fresh-state, preserving original bytes. The independent current lifecycle ledger remains mandatory.
