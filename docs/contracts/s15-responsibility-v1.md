# s15-responsibility/v1

Executable opt-in WORK15-01 (#327), 2026-11-03. Requirements remain FR-04/07/12/14/15/18/26/28/29/33/35; NFR-05/06/08/10; S15-AC10/12/15. Exported TSDoc in `src/s15/work/index.ts` and `types.ts` is the actual API. S14 and its stores/defaults remain unchanged.

`openWorkService` requires an explicit protected journal path, installation identity, real POLICY ports, authenticated CHAT `view`, a clock and a protected remaining-call projection. A new journal requires `create:true`; reopen never recreates missing continuity. Its own application ID and exclusive OS-backed process lease prevent writing an S14 store or declaring another live worker lost. Receipts, original conversation source, lifecycle and dedupe identities use synchronous FULL SQLite transactions. No transaction spans external I/O; no model/VM receives these ports.

The stable consumer is `ResponsibilityPort`:

- `assign(owner,input)` retains the exact original CHAT source and admitted POLICY work. Acceptance alone has no work actor and cannot execute. Completion and authorized triggers narrow the assigned responsibility; configuration supplies finite `noProgressApproaches`, `reserveCalls` and `maxAttempts`, with no invented owner allowance.
- `beginAttempt(id,{eventId,approach})` consumes one ready event and issues an original process-local handle. `guard(handle)` checks current authority/state before I/O; `signal(handle)` supplies scoped cooperative cancellation. Effect tools keep their owning-service final guards and claims.
- `settle(handle,observation)` records independent transport/execution settlement, historical effect outcome, measured progress, evidence refs, usage and recommendation. A timeout, model completion, guest exit or signal is not settlement proof. Known facts never regress. A progress/completion claim requires evidence; full completion additionally requires both settled scopes and a known effect outcome.
- `wait(id,{requestId,kind,key,evidenceRefs})` persists CI/review/owner/schedule waiting only after actual settlement. It retains no VM/native session. `observeEvent` deduplicates exact protected trigger identity and wakes only the matching wait/current selected purpose/resources/subject. Outside-purpose or unselected-issue findings become proposals. Retries/reads never create replacement work.
- `reconcile(id,attemptId,observation)` records read-only owning-service evidence for the exact unknown attempt; it never resends. `basis:'remote_verified'` and evidence refs are required to advance recovered settlement/outcome facts. When transport and execution are settled, the effect is known and `complete:true` proves the assigned outcome, responsibility becomes `completed`, independently of execution expiry. The old attempt remains publication-fenced; no handle or output is recreated. A missing/uncertain basis or owner statement is retained with its label but cannot certify settlement, close the obligation or renew execution. Unknown outcomes remain reconcile-only/Needs-you. Restart discards original handles and marks active attempts unknown/reconcile-only while preserving ordinary waits.
- `stop(owner,id,requestId)` revokes only the original POLICY work, commits the stop/publication fence, then aborts original live signals. It never stops a shared VM or another responsibility. Capacity stays held until transport and execution settle; unknown historical effects remain reconcile-only. `publish` is a fresh synchronous guard over an eligible original settled handle.
- `project(owner,id)` is read-only. `resume(owner,id,freshChatRequestId)` requires a new authenticated execution instruction inside the original conversation/purpose/resources/selected subject and current original work authority; recommendations and CI events cannot resume a pause or revive stopped/revoked work.

Stall detection counts distinct settled no-progress approaches since the latest evidenced progress or authenticated resume, independently of elapsed external wait time. A configured attempt cap also bounds repeated variants of one approach. The protected remaining-call projection pauses before reserved reporting headroom is spent. The paused report includes attempts, evidence, budget use/unknown parts and a recommended next step; independent authorized work continues. Maximum attempt and POLICY bounds remain hard ceilings after resume.

`createResponsibilityProjectionHandler` mounts only authenticated `GET /s15/responsibilities/:id`, with no-store JSON. The projection includes original words, completion/scope, responsibility/wait/attempt state, independent settlement and unknown facts, evidence refs, stall report and scoped stop impact. Budget observations use POLICY's original reservation identities rather than double-counting attempt/model samples. The MODEL projection supplies charged/measured/unknown per ceiling, availability and pins. Authentication/Host/Origin/session wrapping and subscription/account configuration are protected host responsibilities; no unauthenticated server, scheduler polling loop or visual UI is installed here.

Deterministic tests cover real CHAT/POLICY integration, scripted public Schway execution, fake-clock wait/stall sequences, duplicate triggers, scoped cancellation/revocation, unknown effects and SIGKILL/reopen boundaries. They establish no live VM, provider/account/billing, browser/effect bypass or installation adoption evidence. Those remain the relevant implementation and EVID15/CUT15 slices.
