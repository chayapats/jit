Retain [s16-client/v1](s16-client-v1.md), [file custody](s16-files-v1.md), [Web Push](s16-notifications-v1.md) and [local API](local-api-v1.md) authority.

## `s16-desktop/v1`

The owner installs the authored launcher, selects their existing service in its separate credential-free connection window and signs in to that service. The launcher opens a browser-owned standalone app in a dedicated profile for the complete canonical origin. An ordinary browser PWA remains available, but is not sufficient evidence of the desktop launcher's navigation guarantees. The install control never claims success from displaying a prompt: installed state comes from standalone display mode or the browser's installation event. Unsupported, unavailable, dismissed and failed prompts are distinct from installation. App settings show the current service origin and explain native permissions and reconnect/update state in English/Thai.

Manifest identity and start path are fixed to S16; no credentials, endpoint parameters, custom protocol handlers, file handlers, share targets, scope extensions or host enrollment. HTTPS is required for remote installation, with explicit loopback development exceptions. Browser cookies are hostname-scoped, not port-scoped: the launcher must block cross-origin navigation/requests/redirects, including the same hostname on a different port, before transmission. Its profile is private and separate per complete origin. No session material or private client state is copied into an app package, another origin, logs or a working VM.

### Launcher boundary

`s16-desktop-launcher/v1` takes a canonical HTTPS service origin (HTTP only for literal loopback), explicit installed Bun/Chrome executable paths and a private installation root. No credentials, arbitrary command, browser flags, URL credentials/query/fragment or raw IPC channel are accepted. Chrome runs through the existing pinned Playwright public API over a private pipe. Runtime and client artifacts have independent exact-version/hash evidence; installation never registers a computer or exposes a shell/browser host API.

All pages, popups, HTTP requests, redirects and WebSockets remain on the selected service origin. Redirect inspection uses zero-follow/zero-retry transport; refusal must precede transmission to another origin. A same-origin sign-in navigation may continue only as a fresh bounded navigation, never an unchecked redirect chain. Private results are not logged or exported. Native downloads retain their existing user-visible browser behavior and bounded service response contracts. Unknown deep links refuse rather than becoming a command or service switch.

The connection window owns only a validated select-service callback, bound to that exact credential-free window/main frame. It is closed with its browser context before service launch. The authenticated client has only the bounded owner-link handoff below; no generic eval/filesystem/command bridge or native messaging host. A profile is never imported or reused for a different origin. Native launcher update stages a sealed artifact before an atomic pointer change, preserving the preceding artifact and profile across interruption; rollback changes client code only.

### Bounded owner-link handoff

`jitDesktopOwnerLink(url)` returns only `{ opened: boolean }`. The caller must be this native context's current service Connections main frame. The native controller, never a page message, captures capabilities from actual HTTP 200 `/api/s16/client/connections/commands` responses for matching typed `source.add`/`source.oauth_begin`/OAuth `source.reconnect` requests. The receipt must be `s16-connection-receipt/v1`, match request ID/kind/source, and carry an authorizing OAuth source with an exact revision plus an authorization URL with one state, S256 PKCE and this service's exact redirect URI. No credential URL/fragment or insecure remote authorization endpoint is accepted. Retain at most eight capabilities per page, each one use and ten monotonic minutes; replay cannot reset its lifetime/use.

Before opening, read current authenticated connections with zero redirects/retries, and require the same authorizing OAuth source/revision. A callback from an iframe, another origin/page, stale/revoked source, invented URL, expired/used receipt or source-less model output refuses. The only receipt-free exception is exactly `https://github.com/settings/personal-access-tokens/new` under genuine current native browser user activation on Connections. Activation is queried with CDP `userGesture:false`, never synthesized by a host evaluation.

Open a separate disposable vendor browser, sandboxed with native platform storage defaults and no imported cookies/profile or native binding. Jit cookies never enter it. Provider login/2FA is manual owner input, not automation or an approval. Direct Jit traffic is limited to the exact captured state callback; other Jit navigation is refused/closed. Normal provider redirects have no Jit session to carry. Observe the actual service callback response (303), matching state and `/s16/connections#oauth=<captured source>` or the known failure return, then freshly revalidate and navigate the original authenticated client to that return. Never invent callback success or exchange a token in the client. The existing service owns single-use state/PKCE, owner/source generation and finalization; public-window creation alone says only `opened`.

The callback is consumed once by the native controller with no provider cookie and zero redirects/retries; the browser navigation itself is aborted. Revalidation for the return permits the unchanged authorizing source, or exactly its next `reconnect_required` revision with `source_login_declined` after a real denied callback. A removed/changed source cannot resume. Reload the original Connections document: changing only its hash would not rerun the client OAuth bootstrap. Disconnect the provider browser before resuming; native process-close cleanup continues independently of its route teardown.

Close owned and in-flight handoff browsers with the native session. Do not log URLs/state/codes, credentials or private response bodies. Provider cookies are never imported back. Web clients keep their existing protected OAuth flow when the native callback is absent.

### Native release and installation records

`s16-desktop-native-release/v1` inventories every shipped regular file by relative path, SHA-256, byte length and mode (0644 or 0755). Its identity covers the canonical contract, application version, exact Bun/Playwright versions, source/lock evidence and inventory. The package contains the bundled native entry, a small versioned bootstrap, the existing pinned Playwright package and applicable LICENSE/NOTICE records. Chrome and Bun executables are explicit existing installed inputs, not redistributed binaries. Symlinks, hardlinks, special files, unknown/uninventoried files, traversal, corrupt bytes, malformed/duplicate JSON and excessive count/size refuse validation.

Installation uses an owner-only root and `installation.json` (`s16-desktop-installation/v1`: canonical Bun/Chrome paths, locale, optional service origin and bootstrap digest). `current.json` (`s16-desktop-current/v1`: active and nullable previous release IDs) is replaced atomically only after a new complete staged tree is revalidated and renamed to `releases/<id>`. A compatible v1 bootstrap remains stable across ordinary client updates; a changed bootstrap contract requires its own explicit migration rather than silent replacement. At most eight releases are retained before explicit maintenance is needed. No update removes profiles or application/service state.

A staged update, interrupted copy/rename or missing final pointer is recoverable from complete sealed releases and the last valid pointer. Rollback verifies the preceding immutable release before atomically swapping active/previous. Launch revalidates the bootstrap and selected release, exact runtime version and private installation/profile identity. No arbitrary release path, URL, command or runtime flags come from the app renderer. Native app/launcher entries contain only safely quoted fixed executable/bootstrap/root arguments. There is no unattended remote update feed.

Profiles are private per full origin and have one native writer. Startup resets only managed Chrome tab-restore/exit preferences so restored pages/forms cannot precede the boundary; unrelated preferences survive. Native launch retains sandbox, native audio, background networking and platform keychain behavior instead of Playwright testing shortcuts, and verifies the actual private-pipe/no-port command line. macOS verifies the complete signed vendor Chrome bundle; the admin-writable macOS vendor-install convention is accepted only for the trusted admin group. OS credential-storage and background-notification guarantees require their exact platform receipts; a Linux basic secret-store fallback is not called strong encryption.

Files use the existing owner-invoked file picker and protected upload/result/download paths. Microphone and notifications use their existing explicit controls and the browser/OS permission prompt. Installing or opening the app requests none of them. Permission denial remains recoverable through browser/OS settings, never a shell fallback. Native file access is limited to the selected File objects or the owner's chosen download destination; no persistent directory grant is added.

Only the service's existing authenticated APIs may start work or decide an exact approval. App/deep-link navigation is inspection, never authority. Query-based commands, arbitrary schemes, cross-origin URLs and unknown S16 paths are not launch commands. Browser origin rules, service Host/Origin/CSRF/fetch-metadata checks, sandboxed artifact rendering and exact-action revisions remain effective in the installed window. There is no privileged IPC surface to invoke.

## `s16-desktop-release/v1`

A release is a bounded immutable inventory of public bytes. The inventory identifies the contract, release SHA-256 and each asset's exact absolute same-origin path, full SHA-256, byte length and content type. It includes the compiled client with applicable license notices, styles, audio worklet, neutral English/Thai HTML shells, app icons and install manifest. It contains no installation-specific hostname, owner/session token, private API projection or model state. The release identity changes when any inventoried byte changes. Paths and inventories are generated by trusted package code, never taken from a page message or arbitrary remote manifest.

Public release assets are served with exact path/method/query validation, nosniff and an appropriate content type. A neutral shell has no private server rendering: it must reacquire the current session/bootstrap before rendering private facts. Legacy authenticated client paths remain compatible. Service/package outputs retain existing LICENSE/NOTICE/third_party custody; this slice imports no new third-party source or native runtime.

### Worker install and update

1. Fetch only the generated same-origin inventory with credentials omitted, redirect refused and a finite deadline/size bound. Check exact bytes, SHA-256 and content type before recording each public asset.
2. A partial cache is not a release. Commit its completion marker only after the entire inventory validates. Install failure removes only its own incomplete cache and never deletes the active or preceding complete release.
3. Do not force skipWaiting over an existing client. A waiting update is reported in the UI; it takes over after all existing app windows close. No automatic page reload, work resend or approval decision accompanies an update.
4. Controlled S16 navigation selects the active complete neutral shell, so HTML and code cannot come from different releases. Exact content-addressed assets come from that complete package. Unknown routes, arbitrary query/scheme/origin and every API/private response bypass this cache and retain service refusal/authentication behavior.
5. Retain the active and preceding complete public packages. Interrupted/malformed updates keep the prior complete app launchable. If required public bytes of the active package are missing/corrupt, recovery can use the preceding verified complete package or report unavailable; it must never label a partial package successful.

Only public static resources and neutral shells are eligible. Cache Storage must contain no request/response bytes from `/api/`, owner login/setup, files/artifacts, screenshots, protected browser sessions, generated model HTML, private download URLs, websocket/event streams or POST requests. Notification locale preference remains its separate non-private record. Storage pressure can evict browser caches; the app then needs a network connection to rebuild a complete package. Browser storage is recoverable delivery, not durable application authority.

### Recovery and compatibility

Disconnect produces an honest reconnect/offline state and withholds private projections that cannot be revalidated. Unknown work keeps its original durable request identity and requires existing read-back recovery; the worker never queues or retries effects. Reconnect refetches current owner/policy/source facts from the same service. An expired session signs in to the same installation; app installation cannot create a new owner.

Client code rollback cannot roll back server journals, owner generation, policy, withdrawal, budgets, action receipts or native sessions. Operator restoration of a prior service/client build must use existing compatibility/state-preservation gates. No app-cache operation authorizes a service update, schema conversion, production deployment or owner-host activation. Additive client capabilities remain negotiated through current bootstrap; unavailable features keep their existing honest state.

## Conformance and evidence obligations

- Verify actual installed standalone window and app identity, not only manifest presence, synthetic install events or browser viewport styling.
- Use that window and the actual service for Bots/work/files/results/approvals/computer views and original-send recovery. Scripted model/provider fixtures remain labelled deterministic.
- Prove completed package preservation across interrupted/corrupt install and closed-window activation; inspect every cached response and current server state.
- Exercise malicious navigation/deep links and a second origin; prove no cookie/CSRF disclosure, privileged native effect or host enrollment. Keep local API Host/Origin/token and inspect/execute regressions green.
- Exercise English/Thai, keyboard, loading/error/empty/reconnect and permission support/denial states using the actual bundle.
- Record exact source, package hash, OS/browser revision, command, outcomes and pending physical-device/live-service inputs. #431/#432 retain live account/device and owner-host acceptance.

No completion is claimed by this contract alone.

Review refinements: the managed browser closes when its last owned page closes (including after the standalone handoff), releases the profile lease and closes pending owner windows. The zero-follow/zero-retry native response budget is fifteen minutes, covering bounded multi-page MCP discovery without a shorter client-only cutoff; buffer limits remain unchanged. Disconnect and explicit reconnect/revalidation clear every private projection and advance child-view keys, so old private component state cannot survive a successful reconnect. OAuth hashes are consumed from the current document, not retained across later remounts.

After a conclusive owner mutation, navigation metadata may refresh without losing the view's current typed receipt. These reads are serialized and retain the view only under the same authenticated `sessionScope`/local continuity marker. A changed binding or failed read withholds private state; a lost mutation reply keeps only the established session/capabilities needed for an explicit same-identity recovery, never an automatic new effect. Current document routes, rather than stale initial selection state, restore inspectors after revalidation.
