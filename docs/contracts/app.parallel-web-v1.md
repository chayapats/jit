# app.parallel-web/v1

WEB14-01 logic delivery; S14-AC07, FR-13/17/18/39/41, NFR-07/09/10. Types: `src/s14/parallel-types.ts`; gateway: `parallel.ts`; protocol: `parallel-protocol.ts`; native executor: `research.ts`. Product UI: `src/s14/web-research.ts`.

`S14Application.parallel:ParallelWeb` is a service-owned gateway. `definitions(attempt:Attempt):ToolDefinition[]` returns only granted `web_search({query})` and `web_fetch({url,fullContent})`. Both are trusted Jit tools passed through `tools.definitions`, exact policy, hostedLookup off. Search uses `ParallelMcp implements SearchProvider` from the pinned public `schway/host` contract. Fetch is Jit-owned; no FetchProvider or private engine import is assumed. No vendor declaration or advertised readOnlyHint grants a tool.

`read(attemptId,tool,input,signal?):Promise<WebRead>` validates a live owner/Bot/work/resource intersection, reserves one tool call and checks current memory before any network dispatch. The exact dispatched query/URL, settings revision, timestamps, remote protocol request count, actual outcome, missing sources, failures and vendor usage are inspectable. Unsafe inputs are recorded with content-free refusal markers, not credential/private copies. Private context is compared using the existing full-text normalized outbound guard (24 Unicode code points; percent decoding, NFC, case folding, whitespace and format handling, conservative exhaustion). Its corpus includes full Bot-owned owner/Bot sources, supplied claim text/quotes, decisions, packet/Bot metadata and work input. A corpus above 2 MiB refuses. This is a conservative verbatim guard, not proof against semantic paraphrase or a grant to release private data. There is no bypass/release control in this slice.

Queries/URLs are at most 8192 UTF-8 bytes. Credential patterns, registered vault values, userinfo, credential query parameters, internal hostnames and nonpublic numeric addresses refuse before dispatch. URL policy permits HTTP(S), ports 80/443 and syntactically public destinations only. Numeric-address restrictions mirror the pinned direct-fetch guard, including mapped/translation/tunnel ranges. **Parallel performs remote retrieval and DNS. These input checks do not validate Parallel's remote DNS, redirects or network isolation.** The legacy supported direct-fetch transport remains unchanged; no direct-fetch fallback is selected.

The endpoint is fixed to `https://mcp.parallel.ai/mcp`. Streamable HTTP accepts bounded JSON or SSE JSON-RPC responses. Each logical read performs initialize (`2025-03-26`), initialized notification, tools/list and one tools/call; maximum five requests, no retry/redirect/fallback. A 15-second whole-read abort deadline (including body streaming), 256 KiB per protocol response and a whole escaped model envelope of min(32768, attempt.outputBytes) bound input/output. Oversize is explicit, not a successful silent truncation. Search keeps five results, reporting omittedResults; full-content requests lacking full_content stay excerpt/partial. Cancellation requests transport/reader cancellation; it does not prove vendor-side execution stopped. Production fetch must honor AbortSignal. Work transport ownership and existing `execution_capacity_held` serialization remain unchanged; no native overlap is introduced.

SSE skips valid JSON-RPC notifications without an `id`, then waits for the matching response within the same byte/deadline limits. Mismatched response IDs and malformed envelopes still refuse. Failure handling clears evidence, missing/failure metadata and usage before persistence, rechecks the escaped model frame, and replaces an oversized subject with a marker when necessary. Tool delivery rechecks the frame too; an output reservation smaller than a minimal failure record gets a bounded error marker. The durable read retains its actual failure outcome.

Protocol fixtures are documentation-derived, verified **2026-10-30**, not live captures:

- [Unified MCP](https://docs.parallel.ai/integrations/mcp/quickstart): endpoint, tool arguments, modes, session correlation and usage.
- [Programmatic MCP](https://docs.parallel.ai/integrations/mcp/programmatic-use): anonymous/authenticated discovery.
- [Extract API](https://docs.parallel.ai/api-reference/extract/extract): results/excerpts/full_content/errors and returned session_id.

`src/s14/protocol/parallel-mcp.json` pins structural input schemas; `tests/fixtures/parallel/` supplies anonymous/authenticated discovery and results. Titles/descriptions are ignored; structural or tool-set changes refuse as schema_changed. The unified docs advertise web_decisions anonymously and add web_research with authentication. These known extras are never offered or called. This differs from assuming discovery itself contains only two tools in ADR 0047. Unknown additions, removals, duplicate names and paging also refuse. Exact live discovery serialization/conformance remains **pending opt-in**, alongside live usefulness; a mismatch never dynamically installs a schema.

Unified docs use client_model (trusted configured exact model, omitted above the vendor length limit) and provider-returned session_id. Jit omits session_id on the first conversation call, persists the returned opaque value and reuses it for subsequent anonymous search/fetch. It never supplies an installation/Schway identity or rotates correlation to evade limits. The older search.parallel.ai docs use different model_name/caller-generated correlation semantics and are not this adapter's protocol. Authenticated requests omit anonymous-only analytics/correlation fields.

Validated anonymous correlation is committed through the trusted `ParallelMcp.options.onSessionId` callback before evidence normalization/acceptance. A rejected body/evidence envelope or late authority fence therefore cannot lose an already parsed and validated ID. Transport responses rejected before parsing cannot supply a validated ID. Changed or malformed IDs refuse and never replace the stored correlation. Settings list each enabled Bot with the actual selected subset of `web_search`/`web_fetch`; either capability counts as available public reads.

Anonymous is the initial explicit setting and requires **no key**. `web.parallel.key.set` writes an optional API key to the existing service `ConnectionVault`, creates metadata and fingerprints it; it does not select authenticated use. `web.parallel.configure` requires an exact setting revision, selected connection and billingAcknowledged=true to enable authenticated use. `key.remove` leaves the selected mode in place and makes reads unavailable; only another explicit owner configure command selects anonymous mode. No automatic account/key/provider/model/billing switch exists. Missing usage is null; supplied SKU count/cost is vendor-reported evidence. Key commands have write-only receipt identity excluding the value and its hash; retrying a secret command returns the original receipt. A rolled-back vault write may leave an unselected protected file; metadata never authorizes it. Failed removal may conservatively leave the selected key unavailable. No secret enters prompts, URLs, errors, application SQLite, ordinary exports or native tools.

The opt-in root configures `JIT_S14_VAULT_DIRECTORY`, default a sibling `s14-vault` outside the application directory. The vault reuses owner-only modes, symlink/collision checks and protected atomic writes. Anonymous operation never reads a key. Full backup/upgrade/restore integration remains OPS14-01; connection metadata alone cannot restore a credential.

`schwayResearch(directory,app,scriptedModel?):WorkExecutor` runs fresh strict sessions on the same pinned artifact, maxConcurrentTools=1 and maxAttempts=1, within the existing serialized root. Initial inference is the admission reservation; later model turns and tools each reserve calls through the same live authority ceiling. Every tool/protocol dispatch and final result rechecks current authority. Native sessions retire/close through supported APIs. Unknown/failed native calls never silently resume on boot. Tool-free conversation remains separate; these public tools require explicit work.start authority in this slice.

Combined schema **11** includes parallel_settings (initial anonymous revision1), parallel_connections (metadata only), parallel_sessions (opaque vendor correlation by conversation), web_reads (attempt FK) and external_evidence (attempt FK). Earlier unreleased S14 schemas refuse before writable open and need a fresh separate path. Legacy default runtime and its provider selection remain unchanged. Deterministic evidence is `tests/s14-parallel.test.ts`; no live/paid network, subscription, billing or quality claim is made.
