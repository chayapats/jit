# app.routine-grants/v1

ROUT14-01 (#255), S14-AC10/11; FR-12/26/28/30/33/34, NFR-05/06/10/11. Logic only, behind `--s14`; UI acceptance remains unticked. Types: `src/s14/routine-types.ts`; service: `app.routines:S14Routines` in `routines.ts`. Consumes app.work-grants/v1, app.work-graph/v1, app.work-checkpoints/v1, app.replay-policy/v1 and app.attention-outbox/v1. The pinned supported Schway artifact remains `vendor/schway-1.0.0-rc.2-697bf40.tgz` (`697bf406a84c8d1deb8d4a6d71876ea1003be5b3`), public release/v2, credential-lifecycle/v1 and session-inventory/v1; no engine change/private import.

Exact owner envelope/receipt/authentication follows app.bots/v1. `routine.enable` takes `RoutinePurpose`: StartPayload without task/expiresAt, plus `{timezone,recurrence,misfire:'coalesce',occurrenceBudget,endsAt}`. `expectedRevision` is the conversation revision. `requiredEvidence` remains optional. There is no implicit task acceptance. The enable transaction captures the exact typed command, owner generation, current enabled Bot revisions/generations/capabilities, exact routes, resource/share policies and finite per-run budgets. Work-bound share policies refuse, since future occurrences have independent work IDs. Limits use the normal WorkLimits maxima; occurrenceBudget is 1–1200, endsAt is finite within 366 days, at most 128 retained routines. The default graph must fit the selected finite budgets at enable time. Neither a title, schedule nor deadline adds authority.

`routine.pause`, `routine.resume`, `routine.revoke` take exactly `{routineId}` with current Routine.revision. Pause/revoke fence existing occurrence grants, queued lanes, tools/input and late publications immediately. Actual work stays stopping until transports settle. Resume requires the original capture still current, preserves remaining budget, creates a fresh dispatch generation and drops the paused backlog. To change purpose/resources/Bots/tools/limits or recapture changed Bot policy, enable a new exact routine; model/source edits cannot mutate a capture. Revoked routines cannot resume. A named work.stop stops only that occurrence, not the routine or unrelated work (Q6).

`tick():void` runs in the trusted opt-in service pump after recovery. Pure `nextScheduledInstant`, `dueRange` and `normalizeSummaryOutcome` reuse the legacy schedule/quiet algorithms with new identities, without Project state. Recurrence is `{kind:'once',at}`, `{kind:'interval',everyMs}` (60 seconds–30 days), or `{kind:'daily',time:'HH:mm'}`. Timezone is explicit validated IANA. DST gaps shift forward; overlaps use the first instant. Missed instants coalesce into the latest due occurrence, with missed range/count retained; one occurrence per routine may remain in flight, and no interval backlog is materialized. Every occurrence consumes budget even when not admitted. Independent monotonic routine usage and consumed occurrence identities prevent refunds/duplicate triggers across stale application images; missing consumed history blocks with `restored_occurrence_requires_review` rather than inventing work.

An occurrence starts ordinary bounded background work atomically through the existing work.start validator/graph. The synthetic typed start is derived solely from the captured owner command; it cannot accept a proposed task. Current owner/Bot/route/scope snapshots must equal the capture. The occurrence-to-work binding joins every normal grant barrier. Expiry, changed capture/policy or failed admission is visible failed history, never quiet. No new provider/model/billing/account fallback exists.

`WorkOutput.text` retains the legacy typed outcome normalization: prose or unknown outcome strings are report candidates; only explicit `no_update` is quiet; malformed typed fields fail. All graph steps must complete quietly for a quiet occurrence. Provider errors, stopped/not-admitted work, failed/partial reads, malformed proposals, missing results, failed siblings and owner-waiting outcomes cannot be hidden by no_update. Results/evidence remain in ordinary work history. A settled report candidate requires an available committed report for that occurrence work; otherwise the occurrence fails visibly with `routine_report_missing`. A model claim, arbitrary JSON object or staged file alone cannot complete a report occurrence. Typed no_update and owner-waiting outcomes retain their separate semantics. `WorkOutput.proposals?:unknown` or a raw JSON `proposals` array can suggest at most eight exact `{title,purpose,completionRule}` items per bounded attempt. Each becomes a sourced, unstarted Work with state proposed, reason routine_out_of_scope and no grant. Task acceptance retains it without execution; a separate explicit work.start with current scope is required. Unsupported authority fields refuse. Proposal lineage pins the producing result and original sources/access revisions.

The native routine executor accepts `{outcome:"report",text,report:ReportProposal,proposals?:[]}` and the ordinary `{text,report}` envelope. It forwards the untrusted report to the same `authority.commit` → `reports.publish` transaction as ordinary work; there is no routine citation bypass. Actual own reads/committed handoffs, exact citation revisions/quotes/scopes, coverage gaps, staged artifact validation and output reservations use app.report-artifacts/v1 unchanged. Invalid report publication rolls back the result, proposals and files together. Typed `{outcome:"no_update",proposals?:[]}` and `{outcome:"failed",reason,proposals?:[]}` remain supported; unknown routine envelope keys refuse `invalid_routine_result`.

`result(tx,attempt,output)` runs within fenced result commit; `guard(tx,workId)` checks standing dispatch generation; `reconcile(tx)` records settled outcomes and grouped attention. `list(actor):RoutineView[]`, `view(actor,id):RoutineView` return `{routine,nextRun,history}`. Routine states: active/paused/revoked/exhausted/blocked. Last finite-budget occurrences may settle while exhausted; paused/revoked/changed captures cannot. Occurrence states: running/complete/failed/stopped; outcome: report/no_update/failed/needs_owner/null. History includes scheduled instant, DST resolution, missed range, work ID, proposal IDs and safe reason codes. Inspection never ticks or infers authority. `attention(actor):RoutineAttentionSummary[]` returns at most 128 per-routine aggregates: `{routine,decisions:{count,at},settled,report,delivery}`. SQL selects actual proposed finding Work and waiting occurrence Work across all history before aggregating; notice age, reason, resolution or delivery state cannot remove an open owner decision. It reads only the latest settled occurrence/report per routine and aggregates delivery failures/uncertainty across all occurrence notices. Home/Work render at most one decision row and one failure/blocked row per routine plus one latest update; exact counts retain every open decision without an unbounded page. Exhausted/paused failures stay visible until a newer settled success or explicit revocation; owner-requested pause/revoke stops keep their existing history-only rule.

Introduced schema **11** (current combined **13**) adds routines, routine_occurrences (unique work ID), routine_results, attention_setting, attention_decisions and attention_notices, plus independent lifecycle.routine_usage. Earlier unreleased 1–12 refuse before writable open with fresh-state; legacy runtime is unchanged. Managed backup/restore transport remains OPS14-01, which must retain the current independent ledger.
