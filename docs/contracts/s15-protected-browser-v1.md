# s15-protected-browser/v1

Revision **2**, 2026-11-03: implemented bounded host API for BROW15-01 (#322). Requirements remain **FR-07/17/18/29/36/37/38/40; NFR-04/07/10/14; S15-AC05**. S15-D10/D12/D20 and RF15-G03/G04 govern the boundary. S14 remains the default; constructing this module requires `runtime: 's15'` and does not activate an installation or migrate existing data.

This revision replaces the earlier speculative ports, framing, support manifests and catalog/hash machinery with the actual exported TypeScript contracts in [src/s15/browser](../../src/s15/browser/index.ts). The older [documentation fixtures](fixtures/s15-protected-browser-v1.md) remain historical, unexecuted proposal material, not this implementation's test suite. [ADR 0068](../adr/0068-s15-protected-browser-operations-and-evidence.md) records the simplification. The existing [policy service](../../src/s15/policy/index.ts) supplies real authority, immutable actions, approvals, budgets, claims and publication guards. No VM/conversation internals or private Schway exports are used.

## Composition and custody

`registerProtectedBrowser(options)` constructs one protected host browser/profile registration. Register its `adapter` and `readHandler` when opening the real S15 policy service, then call `attach(service)` and `open(workActor)`. When the host also registers another read service, compose one validator for `read` by exact payload contract; each service validates its own resource binding. The returned work closure and `protectedBrowserTools(work)` have no owner, configuration, cookie, profile, raw protocol, JavaScript-evaluation or arbitrary-network API. Model output and page content cannot construct actors or change installed request semantics. The host calls `work.release()` after settled work before opening the profile for another actor; old closures and stale releases cannot control the new lease.

The host supplies a protected profile directory, Chromium executable, resource/fences, finite budget vector, a separate current-continuity SQLite path and trusted `BrowserSitePolicy`. Both profile and continuity must reside outside the root-administrable working VM and outside its mounts, tools, exports and snapshots. Chromium uses a private pipe control channel. The owner port remains in authenticated host composition; it must never be installed as an agent tool or a VM endpoint. The browser profile is not the policy/current-continuity store.

`BrowserSitePolicy.classify` is protected code: it must establish actual method, exact URL/query/body, destination, applicable classes and credential-free semantics. It returns a supported public/private read, protected owner login, known effect, an explicit unsupported reason, or null. Null refuses before outbound dispatch. A host allowlist or HTTP method alone is insufficient. `observable` separately identifies surfaces safe to expose; it is not a generic secret scrubber. Credential-bearing URLs, form tokens and script-readable session material require an independently reviewed safe boundary; otherwise the workflow is unsupported.

This is a protocol-level browser capability, not a website business API. General public JavaScript applications can load and render without a bespoke integration. Authenticated effects need trusted semantics and, to report business success, a trusted response verifier. Missing verification yields an unknown outcome, never success from an HTTP 200 alone.

## Operations and observations

Agent operations are the closed `BrowserOperation` union: navigate, read, find, screenshot, click, type, select and submit. Every input carries the current generation. Targets are opaque IDs from a fresh bounded observation, backed by fixed engine element handles and the observation generation; they are not CSS, coordinates or script. Mutations advance the protected generation. Document changes, takeover, hand-back and restart fence old input. File inputs, password/2FA fields, non-HTTP links, download attributes and popup targets are unavailable to agents. Fill never sends Enter.

Text is capped at 32 KiB with explicit truncation, observations expose at most 64 controls, screenshots at 2 MiB and request bodies at 64 KiB. URLs/ordinary input are capped at 4096 bytes. Captures exclude field values, hidden DOM and script text, and refuse password/2FA/file surfaces. A trusted safe-surface policy remains mandatory: field masking cannot certify arbitrary authenticated pages. The actual observed URL must match the admitted safe document. Each network read and each text/image capture has its own policy read claim and final current-authority/publication checks; output cannot renew a lease or grant an effect.

Input completion waits for native command acknowledgement, the expected navigation (including Chromium frame-stop after a refused request), and every intercepted request actually started by that input. A protected 30-second operation deadline reports an unknown outcome rather than inferring completion from elapsed time. `execute` and `resume` accept an optional AbortSignal; final input guards run after readiness waits and immediately before protocol enqueue, and cancellation suppresses later request release and result publication. If an effect's broker request has already been released, cancellation/deadline never aborts that transport or retries it: the original policy claim/capacity and reconcile-only continuity remain until actual settlement. Graceful close waits for retained transports instead of treating cancellation as proof of settlement.

JSON results distinguish observed content, image bytes, held exact action, denied/unsupported reason, unknown outcome and completed input. Completed input does not assert a remote business outcome. Page content is untrusted evidence. The Schway tool uses only the public `ToolDefinition` surface, with its work closure supplied by the host.

## Network boundary in both modes

`static` disables page JavaScript. `general` enables it. Both use the same Chromium request interception and protected host broker:

1. Chromium has a deny-only loopback proxy with loopback bypass disabled, DNS mapped to failure, QUIC/nonproxied WebRTC UDP disabled, service workers blocked and extensions/background networking disabled. The proxy never opens outbound sockets. WebSocket interception closes sockets; frames, workers, popups and browser downloads are disabled. Permissions for clipboard, camera, microphone, geolocation, payment, USB and serial are denied.
2. The private engine captures actual complete HTTP request method, URL, content type and body bytes while paused. It rejects file/multipart, incomplete bodies, unsupported protocols and non-main-page requests. Only the host broker opens outbound HTTP connections. It supplies fixed Accept/User-Agent headers, omits arbitrary page headers and referrers, and injects origin-scoped session cookies privately. Cookies/auth headers are absent from action/read payloads, prompts, logs and evidence exports.
3. Protected classification decides each request. Known credential-free public GET/HEAD reads to approved destinations pass without per-page approval and without session cookies. Private reads require the existing resource/data scope. Queries, forms or paths carrying private data cannot be declared public merely because they use GET. Known disclosure/new-recipient requests use the applicable `disclosure`/`new_egress` policy gates.
4. Supported main-document effects matching a single native request derived from the selected live anchor/form (including exact method/URL/form serialization) become immutable `s15-browser-request/v1` payloads, with method, URL, content type, canonical body base64 and navigation flag. Their trusted semantics map to policy ActionClass, including communication, financial, GitHub publication, production, disclosure, new egress, major change and ordinary edit. Financial and GitHub conditions use their real policy types. `prepare`/`evaluate` hold missing authority; `dispatch`/`DispatchContext.commit` bind the exact payload and final current fence before the broker creates a socket. Approvals cannot change the request or enable an unsupported workflow.
5. A held original browser request remains paused for at most 30 seconds. `resume(actionRef)` releases only its original protected context after exact approval/current policy. The broker sends once and fulfills that paused request; it never repeats the browser input. Takeover, expiry or process loss destroys the resumable context. The policy ledger retains its immutable action/claim facts.
6. Every browser response passes through the bounded broker. It uses manual redirects and refuses redirects before any follow-up request or browser 3xx release. Attachments, unknown/active download types and oversized responses are unavailable. There is no browser download/upload/import/export capability. Response bytes are bounded to 2 MiB and sensitive cookie headers stay inside the protected engine. `Headers.getSetCookie()` retains each cookie separately; only the private Chromium fulfillment boundary joins them with the newline separator Playwright uses to emit distinct Set-Cookie fields. Commas inside Expires attributes are never separators.

The host-broker send is deliberate: a browser callback alone cannot account for unobserved traffic or secret header injection. Interception plus a deny-only fallback leaves the broker as the only permitted application HTTP emitter. This is protection against website behavior, not a claim of safety after Chromium or protected-host compromise. The working VM's independent network/isolation enforcement remains #321/#335; this gateway does not give that VM an unrestricted browser or an outbound proxy.

## Honest support limits

Unknown requests are denied. Non-document JavaScript fetch/beacon/timer effects cannot be reliably attributed to one input by timing alone and are unavailable; they never inherit an active click's authority. EventSource/streaming protocols, WebSocket frames, service workers, frames, popups, redirects, file chooser, clipboard, upload and download remain unavailable. Background nonread requests are denied even during navigation. A page's automatic form submission cannot use a navigation operation's authority; only one exact expected native request can consume an input slot. Public scripts/assets still need known safe destinations/content semantics. The implementation does not claim every website, login mechanism or authenticated application works.

Public JavaScript page rendering and ordinary native form workflows are implemented. A missing causal/semantic/secret proof produces an actionable reason, not a broad approval card. There is no shell, raw CDP/BiDi or script fallback to bypass the boundary. Full cross-VM bypass/host-adoption acceptance is separate from the bounded browser evidence.

## Owner login and input

Only an authentic policy `OwnerActor` can take over, obtain live PNG frames or send transient finite named-field input. Input is restricted to protected configured login/2FA documents; website credentials go directly to the browser and never to the work API, ledger, receipts or logs. Owner input is not an alternative generic effect executor. Login requests stay inside their exact protected login semantics; other owner-generated effects are unavailable through this port.

Takeover advances the current durable generation, fences agent input/publication and aborts held requests. It waits for already-started native input to settle before returning owner control. Old owner frames/inputs cannot reuse a new generation. Hand-back advances it again and returns `checking`, or `cancelled`; it does not approve a held action.

`checkSession(ownerActor)` performs a bounded nonredirecting observation against the configured safe session probe using an origin-scoped HttpOnly cookie. Only the observed configured response plus cookie establishes `signed_in`. The configured signed-out response gives `not_signed_in`; missing/ambiguous/failed observations give `unknown`. Neither page text nor the hand-back button establishes sign-in. Visual design and HTTP/live-view presentation belong to #339; this slice delivers typed host ports, JSON results and Thai/English state/error keys only.

## Continuity and evidence

A small protected SQLite record outside the browser profile retains monotonic input generation and an armed/uncertain exact action reference. It is armed before action dispatch; crash/restart cannot clear it or reconstruct a callable request context. Unknown business outcomes remain reconcile-only and block fresh effect retries. Owner statements are not verification. The real policy ledger remains the authority for exact payloads, claims, approvals, nonrefundable budget charges and remote observations. Generic business reconciliation is unsupported until its protected verifier exists; opening a new browser/profile is not a retry mechanism.

Deterministic tests are [s15-browser.test.ts](../../tests/s15-browser.test.ts); real engine tests are explicitly opt-in [s15-browser-live.test.ts](../../tests/s15-browser-live.test.ts). The controlled HTTP fixture exercises ephemeral login/TOTP, misleading send labels, exact message/payment/private-query holds, reversible edit allow and background/redirect/popup/download denial in both modes. The public read task observes Excalidraw's client-rendered drawing toolbar without a bespoke business API. Credentials and installation-specific records are kept out of tracked files; actual Linux evidence/screenshots belong in ignored `.local` records and the implementation PR summary.

The opt-in command is `JIT_BROWSER_LIVE=1 JIT_BROWSER_EXECUTABLE=/protected/path/to/chromium bun test tests/s15-browser-live.test.ts`. A disposable Linux container is sufficient for engine evidence; it does not adopt S15, alter an installed Jit, certify x64, prove a guest-root boundary or provide universal egress/secret mediation. RF15-G03/G04 have bounded browser evidence; full integration/activation acceptance remains explicitly separate.
