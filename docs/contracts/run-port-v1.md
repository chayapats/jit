# Application run port, v1

Owner: Jit #8. `app.run_port/v1` lives in src/team/types.ts and run-port.ts. It is an application integration seam for JBR01; Schway owns real execution/providers/native lifecycle. It is not a second model/tool loop, provider SDK or native session format. Eligibility requires the tested artifact in the integration base.

ApplicationRunPort.invoke(request, signal, observe) accepts one immutable invocation: purpose/project/topic/role, one exact provider/model/auth-route reference, captured configuration revisions, independent opaque context (id, positive generation), job/attempt/owner-generation fence, separately typed trusted operator/responsibility instructions and untrusted source/claim revision manifest, exact tools, explicit restrictive policy and positive finite JOB01 limits. Sources carry project + exact source revision/generation + text; claims carry project + claim ID/revision/generation/text. Data cannot become instruction/authorization. Native paths, credentials and provider wire types are absent.

Typed observations are started/progress/finished. ApplicationRunOutcome records state, reason, evidence mode, bounded output, finite nonnegative usage and optional opaque adapter/session/context identity. Reasons include complete, unknown_model, route_unavailable, quota, needs_login, cancelled, max_rounds, budget_exhausted, invalid_result and context_retired. Completion is distinct from app acceptance/publication. Cancellation requests termination; the application fence still rejects late results. No implicit provider/model/auth/billing fallback or renewal of budgets exists.

retire(context) durably prevents replay of the exact generation, including started work. delete(context) retires first, then returns deleted or explicit delete_failed + retry_managed_delete. Unknown/malformed references reject. Repeated successful deletion is idempotent. The adapter owns managed native deletion; callers never edit native session bytes. Scripted records prove fencing/failure semantics only; actual Schway-managed deletion remains JBR01/ENG09 work.

ScriptedRunPort performs exactly one in-process scripted invocation without provider/network/discovery. It validates finite request/manifest sizes and limits, requires no tools and all restrictive policy flags false. It validates output/usage/session coherence, strips undeclared result fields, normalizes thrown/malformed results to fixed invalid_result, and rechecks cancellation/context after awaiting the script. Its mode is always fixture; production claims reject. It retains isolated copies of only the last32 requests. Optional trusted constructor callbacks select outcomes/delete failure; no HTTP field registers code.

Fixture sessions use adapter scripted, run UUID and the same independent context. Retirement/delete state persists across reconstruction. No native bytes are created. The producer rechecks source availability/generation/revision, job step/deadline, owner generation, scheduler ownership and cancellation before committing attribution. Real adapters must implement supported host/session/tool/budget semantics and native fencing; this fixture does not certify them.

Types reserve explicit application read-tool names for later seams; preview selects none. Generic execution/fetch, hosted lookup and repo instruction/skill/package autoload are disabled. Static import tests reject private Schway/TUI/SDK/IO dependencies here. Tests exercise one selected route on every normalized failure, finite budgets, source/instruction separation, independent contexts, pre-abort/late output, retirement/delete failure and invalid/oversized/wrong-session results without live quota.
