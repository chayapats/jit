# s16-first-selected-setup/v1

Status: implemented first-setup coordinator/routing with scoped copied-package
and owning-service/client conformance. Real host/account acceptance remains
separate. See [ADR 0130](../adr/0130-s16-first-selected-setup-with-original-intent.md).

This is a first explicit file/file-memory/routine/voice installation, including
explicit disabled flags that may retain selected formats. It is not a fallback
for missing current authority or an invented prior uninstall. Default S14,
unconfigured/default S15 and explicit legacy contracts remain separate.

`openS16FirstSetup` returns before opening root resources. New input comes only
from trusted first-host provisioning: exact credential-free config hashes/bytes,
original controller user/UID/GID/home, pinned Bun, qualified immutable release
and generated root-unit values. Validate actual account/Bun, complete artifact/
dependencies and configuration before publishing a bounded private root intent.
Require original state/current/root-unit absence. Retain the credential-service
unit without writing its service-owned home.

Genuine selector exclusion spans the original intent, first current selection,
root-unit publication, initialization, operations adoption, private owner-link
preparation and observed boot. Only exact original unit bytes or absence are
eligible; occupied different custody refuses. Current/config/source/identity
changes refuse. Crash temporaries are bounded and never adopted.

Record `init-intent` durably before the actual shipped `init --s15`. Run it only
for the original absent namespace before that first intent. Any existing state
uses actual current readers/adoption, never another initializer. Absent state
after an issued init intent is unknown even if interruption preceded creation;
partial/missing journals refuse in place. There is no rename-aside/reconstruction
path. The original deterministic adoption request and independently pinned
current owner identity survive continuation.

A prior trial may outlive loss of the root process. Conclusively stop it through
the original fixed manager/identity before obtaining current-source/adoption
exclusion. Actual package readers validate all current selected/retained SQL and
file/GitHub/helper/external/native-namespace metadata before restart. This is not
a historical point or deep native-state activation. Normal same-code runtime
reconciliation retains its own native/effect contracts.

Owner-link preparation retains the existing dedicated private pipe/terminal
contract. No plaintext credential enters the root intent/result, stdout/stderr
or ordinary exports. Existing configured owners are never reset. The installer
can recover lost first delivery only with a current operator terminal; unattended
updates do not issue a link without that private channel.

Start only the selected original executable after conclusive helper disposal.
Failed start/readiness conclusively stops the controller and retains generated
units, current package and all initialized/current facts. No composition, owner,
policy, artifact, native session, usage or unknown effect is restored. Resume
the original setup/package before considering a newly requested source; later
code uses the separate guarded release protocol over current state.

A completed response is a historical original first-boot receipt. Its retry
does not inspect/rewrite later state, initialize, issue credentials or stop/start
the current process. It never certifies a later service's liveness.

First-selected configuration retains exact bytes and VM selection. KVM discovery
cannot add a local VM to an explicit owner-supplied choice. A configured local
VMM must already match its original canonical account/UID/paths; mismatch refuses
before host changes. No UID/config refresh is part of this transition. The S15
dummy simulator refuses first-selected setup/continuation rather than producing
acceptance from inert markers.

Conformance uses actual copied initializer/adoption/readers, original intent
continuation, later owning file/session writes after failed first health, and
missing-state/store refusal. A separate actual sealed service/client journey
performs native artifact work and one conservative unknown payment after first
setup, then proves a setup-response retry leaves PID, receipts/session, usage and
external counters untouched. Account/systemd/UID/readiness/private owner delivery
ports are explicit fixtures. Rendered onboarding, Linux identity/VM enforcement,
live credentials and owner-host acceptance remain #430/#431/#432.
