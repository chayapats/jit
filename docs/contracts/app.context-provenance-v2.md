# app.context-provenance/v2

MEM14-01; consumes app.memory-scope/v2, app.bots/v1, app.conversations/v2 and app.work-grants/v1. `MemoryPacket` and the public service signatures are in `src/s14/memory-types.ts` and `memory.ts`.

`assemble(tx,{botId,conversationId,purpose,sources,attempt?,bytes?}):MemoryPacket` freezes origin, owner/Bot generations, source revisions, up to six accessible lexical claims, publication/share revisions and every live owner decision for the conversation. Initial packet budget is 16384 UTF-8 bytes (explicit trusted range 1024–65536). Decisions are charged first and never trimmed; overflow refuses `context_too_large`. Memory omissions are counted. Scope filtering happens before ranking. Fact/inference, conflicts and unavailable counterpart references retain their labels. The current owner purpose and pinned decisions precede source/claim text, which is always data.

Chat reserves the complete 128 KiB canonical command receipt, including the duplicated new message and assembled memory. It always retains the new message, then admits newest available prior messages until the next does not fit (at most 12 messages total). Withdrawn messages are filtered before selection. Each admitted message registers an exact source; the packet sources match the snapshot messages in order. The initial 16 KiB memory selection is reserved before history; source-reference growth and its recorded bytes consume the same remaining receipt budget. Suppressed/derived withdrawn messages cannot reenter automatic context. `ChatInput.memory` carries the packet; `Attempt.memoryId` identifies the work packet. Work grants and the existing `execution_capacity_held` serialization are unchanged. `attemptPacket(tx,attemptId)` supplies a current packet to the trusted executor. Later public reads append at most 64 total exact source references to the provenance record (with updated recorded bytes); this bounded audit growth is separate from the initial native input budget. Native history is never the source of current decisions or memory.

`current(tx,packet):boolean` rechecks sources/transitive lineage, decisions, owner/Bot generation, and publication/share revisions. It joins tool and result barriers; owner mutations fence queued/in-flight chat and scrub retained snapshots, retire old contexts and withdraw stale work output. Already dispatched transports may settle but cannot publish late evidence. `context(actor,id):MemoryPacket` returns no claim/decision payload for retired packets. `inspect`, `claim` and `preview` are read-only authenticated owner queries.

Sources from an answer conservatively inherit all supplied sources and memory/decision sources. Forward lineage closure suppresses descendants as well as same-source sibling claims. Deletion reconciliation consults the independent installation ledger before restored data can enter a worker. Pinned decisions are rebuilt on each assembly across reopen or context trimming. Native sessions retire on close through supported APIs; fresh session admission avoids replay of forgotten ancestry.

Sources and extracted assertions also retain access pins for every transitive claim used. History selection checks `sourceCurrent` before admitting a message; prior disclosure never bypasses a revoked access revision. Task acceptance pins the committed `sourceMessageId` as `Work.source:MemoryRef`; start and live grant checks repeat the source check, and admission includes that source in the work packet. A delegated input gets its own source with the parent's full source/access provenance, so changing relevance or receiving Bot cannot drop the lifecycle barrier. Missing attempt packets fail closed.

Assembly and startup prune disposable non-work packets, retaining the newest 256 plus queued/running chat packets; an assembly may temporarily add one further packet. Work packets are retained for their result/evidence barriers. Completed reply snapshots referring to pruned packets lose their memory/messages snapshot, while durable messages and source/access lineage remain. A pruned packet lookup returns `not_found`, and a detached packet fails `current`. Memory table scans use 256-row batches without an installation-lifetime 20000-record cutoff. Source traversal is iterative and visits each identity once; suppression is bounded by the finite stored source/claim graph rather than a fixed lifetime ceiling. No source or withdrawal is pruned, and ordinary volume cannot make startup refuse or permanently exhaust chat admission.

Limitations: deterministic lexical recall, conservative invalidation, depth8/64-visit claim graphs, finite packet/output budgets, serial execution and no transcript import. Full lifecycle operations still scale with retained provenance. Reports/artifacts, full Bot lifecycle and managed restore UX remain their own tickets. UI acceptance remains pending.
