# app.artifact-gateway/v1

REPORT14-01 (#252); consumes app.report-artifacts/v1, app.bot-computer/v1, app.work-grants/v1 and public schway.host.core-tools/v1. Service: `src/s14/artifacts.ts`; types: `report-types.ts`. No external storage or arbitrary host-file export.

```ts
S14Artifacts.stageWorkspace(attemptId: string, backend: ExecutionBackend, request: ArtifactRequest, signal?: AbortSignal): Promise<StagedArtifact>;
S14Artifacts.download(actor: OwnerActor, artifactId: string): {artifact: Artifact; bytes: Uint8Array};
validateArtifact(bytes: Uint8Array, request: Omit<ArtifactRequest,'path'>, maximum: number): void;
artifactHash(bytes: Uint8Array): string;
```

`stageWorkspace` is a trusted integration port, never an HTTP-upload/backend installation surface. Production closes the exact attempt-owned `ComputerSession.backend` in the `artifact_export` tool. This tool is offered only with explicitly granted computer work and uses the same computer/attempt/generation/budget guards. It does not authorize another Bot's workspace or browser/profile. Its exact input is `{path,name,mediaType,size,sha256}`. `path` is a bounded relative path under `/workspace`; absolute paths, empty/`.`/`..` components, traversal, backslashes, percent escapes and nonportable components refuse. Each parent/final entry must not be a symlink and must resolve to its exact workspace path; final type must be a regular file. The supported runner's content observation checks stable entry/content before returning bytes. The service rechecks authority after every async wait and verifies the exact expected byte size and SHA-256. No host filesystem read or shell fallback is used.

Initial delivery allows UTF-8 `text/markdown` (`.md`), `text/plain` (`.txt`) and valid `application/json` (`.json`) only. Active HTML/SVG/script/media types, credential-bearing content, malformed UTF-8, NUL/control data, directories, symlinks, size/hash mismatch and oversize refuse. Downloads are at most min(1 MiB, attempt output reservation), at most four private snapshots per attempt with finite aggregate bytes. The reused runner's observe response also has its independent fixed 16 MiB read ceiling; it is not an unbounded host read. Staging stores a bounded private immutable copy and source lineage in SQLite, not a live path. Staging alone cannot be downloaded, mark a report ready or complete work; failed/settled/restarted attempts lose unpublished staging.

Publication atomically associates snapshots with the committed report revision and creates the service-generated Markdown and structured evidence manifest. `Artifact` is `{id,reportId,workId,attemptId,name,mediaType,size,sha256,source,createdAt}`. IDs are service-generated 32-character lowercase hex; a download never accepts a path, Bot ID, backend handle or mutable filename. Hash/type/size/lineage are revalidated on every authorized download. Filenames are bounded portable ASCII and cannot inject response headers.

Authenticated routes are `GET /api/s14/artifacts/:id/download` and `GET /s14/artifacts/:id/download`. They return exact immutable bytes with `Cache-Control: private, no-store`, `Content-Disposition: attachment`, `Content-Type`, `Content-Length`, `Content-Digest` (SHA-256), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` and `Content-Security-Policy: sandbox; default-src 'none'; frame-ancestors 'none'`. Browser HTML content is never rendered as active app-origin output. Report text is untrusted data; the UI must escape it, not inject raw Markdown/HTML into the app document. No inline preview route, active HTML allowance or CSP relaxation is provided.

Revoked/forgotten/deleted/stale output returns unavailable; its BLOB is removed while immutable identity/hash metadata remains. The current independent lifecycle ledger prevents stale-image resurrection. See app.report-artifacts/v1 for exact lineage/recovery semantics and tests. Real Linux filesystem/race/resource evidence and product UI/device acceptance remain opt-in/pending; deterministic trusted-backend/runner fixtures do not certify a production host.

This includes uncited and transitive graph/delegation producers: staging inherits the attempt's producer/source pins, and reconciliation discards private snapshots whose upstream Bot/resource/computer lineage was withdrawn. Late publication cannot turn an earlier staged copy into a downloadable file. Delivered snapshots share their report's complete lineage and every revision is withheld after destructive upstream withdrawal, including on restore of pre-pin schema-10 data. Export signatures and required artifact fields remain unchanged.
