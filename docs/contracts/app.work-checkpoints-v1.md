# app.work-checkpoints/v1

REC14-01 (#254), S14-AC09/11/12; FR-14/15/16/18/35/37; NFR-02/05/08/10. Consumes app.work-graph/v1, app.context-provenance/v2, app.report-artifacts/v1, app.effect-approval/v2 and public `schway/host`. Opt-in schema **13** refuses unreleased 1–12 with fresh-state. UI acceptance remains pending.

Exact types: `src/s14/recovery-types.ts`; service: `S14Application.recovery:S14Recovery`; native adapter: `schwayRecovery(directory):NativeRecoveryPort`. No private engine imports, raw native parsing or resumed native history.

`prepare(tx,attempt)` records a WorkCheckpoint before dispatch: original attempt/work/step, fingerprint of immutable input/config/route/authority/graph/dependencies, trusted handler version/replay class, reservationId (original attempt), committed report IDs, transport observation and recovery status. The attempt and original memory packet retain exact sources, access/decision revisions, grant and route snapshots. The dispatcher records unknown transport before invoking its trusted executor. Result/report/artifact commit updates the checkpoint in the same transaction; a crash after that commit preserves evidence rather than replaying it. Finalizers record actual settlement, never mere cancellation. Each replay admission reserves a new attempt, step, inference call and output allocation; uncertain prior reservations are never refunded.

`intent(attemptId,contextId,route):NativeIntent` commits before native creation. An intent records opaque attempt/work/grant/Bot/context identities, exact non-secret route, private correlation workspace identity, saved execution branch, discovered lifecycle metadata, cleanup mode/state/reason. Each intent has its own service-generated workspace under the service native directory; the managed session store is shared. The same workspace is used for creation and inventory. This supplies correlation without inventing a caller-supplied Schway UUID API. `correlate(intentId,reference)` saves the actual execution branch after creation; inventory's main reference is for id-wide management only. `retired(intentId)` records a normal retirement acknowledgement. Both production research and chat use the intent seam; interrupted chat never automatically replays.

The independent lifecycle database retains an immutable identity catalog before native creation, effect claim identities, owner-outcome identities and monotonic charged reservation high-water marks. It contains no transcript, credential, source body or owner note. App and ledger updates share SQLite's attached rollback-journal transaction. Restoring an older app image cannot refund calls/reads/attempts/output, resurrect a claimed approval or hide a newly created native orphan. Missing attempts block their original grant as `native_checkpoint_missing`; discovery grants no replacement execution authority. Unresolved orphans retain global/route/Bot/computer admission occupancy. Managed backup/upgrade and restoration of all external resources remain #263; the current independent ledger must not itself be rolled back.

`await recovery.boot(port)` requires the existing exclusive process runtime lock and runs before any chat/work/computer worker. It first reconciles independent records, fences old attempts/effects, blocks interrupted chat, marks uncertain public reads and fences computer/input generations. It then inventories each persisted/catalog workspace through `HostRuntime.listSessions({limit:64,after?})`, follows every continuation and manages discovered sessions without reopening, inference or tools. Before-creation empty inventory is explicitly `not_created`; absent saved references remain `native_reference_missing`, not invented deletion. Active entries retire normally; stale/withdrawn/missing context entries delete through public lifecycle APIs. Busy leases, corrupt metadata, alias conflicts, partial deletion and failed close stay unresolved. Cleanup retries are idempotent on the next exclusive boot. Saved execution branches are never replaced with inventory's main branch.

Queued recoveries are revalidated on every boot until a replacement is actually admitted; renewed native uncertainty fences them again. Only after all discovery attempts finish does trusted replay evaluation run (see app.replay-policy/v1). Unknown transport keeps capacity; settled old attempts are fenced permanently. Requeue uses a fresh step revision/attempt/native context. A delayed old result or finalizer cannot publish or overwrite its replacement. Already committed siblings/reports remain independently inspectable, with partial coverage/gaps retained. Stopped work and stopped lane tombstones prevent restart execution. Boot can finish with explicit unresolved entries; they do not acquire replay permission.

The shared graph scheduler retains queued siblings and waiting dependency lanes after restart. A committed producer with only waiting synthesis remaining keeps the work queued until synthesis settles; recovery never marks the whole graph ready from the producer alone. Main's owned wake-up drain remains in place, but committed ingress and repeated drain calls cannot start chat/work during boot, including while native host close is still pending.

`recovery.view(actor):RecoveryView` / `GET /api/s14/recovery` is read-only owner metadata: `{checkpoints,native,actualUsage:null}`. Checkpoint states: prepared, dispatched, committed, waiting, queued, resumed, finished. `queued` means eligible requeue; `resumed` is written only when a new admission exists, with replacementAttemptId. A known returned handler failure is finished and does not acquire a reboot retry. Native states: creating, correlated, retired, deleted, not_created, unresolved. WorkView supplies retained reservation counts; unknown usage never becomes zero. Reasons include owner_stopped, owner_stopped_step, grant_revoked, grant_expired, owner_authority_changed, configuration_or_route_changed, source_or_context_changed, checkpoint_configuration_changed, budget_exhausted, old_transport_unsettled, unknown_effect_reconcile_only, handler_requires_reconciliation, native_checkpoint_missing, native_busy, native_storage, native_reference_missing, native_delete_partial and native_close_unresolved.

Exact additional owner command (same session/Origin/CSRF/receipt/audit envelope):

```ts
{ kind: 'effect.reconcile', requestId, expectedRevision,
  payload: { effectId, actionHash, outcome: 'occurred' | 'did_not_occur', note } }
```

It requires the exact current unknown action revision/hash and no previous owner resolution; original execution authority may already be stopped/expired. Note is bounded credential-free text. The command increments effect revision, records `resolution:{basis:'owner_statement',outcome,note,recordedAt}` and reason `owner_statement_not_verified`. Observed native/adapter `state` remains **unknown**: an owner statement is explicitly distinct from verified delivery. It never invokes a performer, read-back, retry, model, tool, grant or replacement work. Identical command retries return the committed receipt; stale/changed/extra fields refuse. The independent ledger restores the outcome identity with a placeholder note if an older app image lost the note. Any later resend requires new explicit work and a new exact-action approval, never reuse of this card. This slice installs no remote effect/read-back adapter and makes no exactly-once claim.
