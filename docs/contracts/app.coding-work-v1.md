# app.coding-work/v1

CODE14-01 (#257), Phase B; FR-06/07/08/14/17/35/36/42; NFR-01/02/07/14. Logic only, opt-in `--s14`; UI acceptance remains pending for Claude Opus 5.5 high. Exported contracts: `src/s14/coding-types.ts`, `coding-protocol.ts`, `coding-model.ts`, `coding.ts`. Combined schema **13** refuses unreleased 1–12 without migration or erasure.

Owner commands use `S14Application.execute`, the existing authenticated envelope, exact keys, receipts, audit and rollback boundary:

- `coding.repository.grant {id,botId,url,baseCommit}`, expectedRevision 0: a configured resource slot explicitly in that enabled Bot's ceiling. URL is exact credential-free `https://github.com/<owner>/<repo>.git`; baseCommit is a full nonzero SHA-1 commit ID. No Project, connection, work or network grant follows. The owner must preload that repository **inside** this Bot's `/workspace/repositories/<id>`; no host path or authenticated clone is offered. One immutable identity cannot be rebound; revoke then use another slot.
- `coding.repository.revoke {repositoryId}`, current repository revision: independent lifecycle tombstone fences future admission/tools/publication and stale-image restores.
- `coding.start {repository:{id,revision},work:StartPayload,install:CodingCheck|null,tests:CodingCheck[]}`, current conversation revision: atomically invokes ordinary work.start and captures the repository/commands. Exactly one Bot and one repository scope. Required tools are `computer,coding`; optional `effect_push` grants **proposal capability only**, not external execution. Other tools refuse. All Bot/work/resource/owner/route/time/budget checks remain in force. Internal coding without effect_push cannot propose Git effects.

`CodingCheck={argv:string[],timeoutMs:number,network:'none'|'registry',coverage:string}`. At most 8 tests, 32 literal argv entries each, 1–300000 ms each. `coverage` is an owner declaration, never a measured coverage claim. Credentials/control characters refuse. Network is always physically disabled by the existing Bot runtime. `registry` returns skipped/coding_egress_scope_unavailable, without dispatch; no implicit Phase A egress change, service install, alternative network or host fallback. Offline install/test code runs **only inside the box** and can fail honestly. Package tools/images must actually exist; this slice does not claim a new image or package proxy.

`S14Coding.scope(tx,ref):ScopePolicy|null` supplies typed repository policies. `job(tx,workId):CodingJob|null` reads a captured trusted plan. `run(directory,attempt,signal):Promise<WorkOutput>` is the trusted executor seam; root dispatches coding jobs through it before ordinary computer research. Public `schway/host` core tools perform edits in a fresh correlated/retired native context. Repository content, instructions and model done/coverage/test claims confer no authority or success. No private Schway imports or version change.

The service generates `/workspace/coding/<workId>` and branch `jit/<workId>`. An independent clone uses `--no-local --no-hardlinks --no-checkout`, then exact base checkout, with hooks/fsmonitor/helpers/signing/ambient Git config disabled. Source/checkout parents and `.git` must be ordinary canonical directories; path escapes, symlinks and gitdir indirection refuse. All Git/package/test processes stay behind the guarded runner in the Bot computer; the service never runs retrieved code. The explicit computer grant permits that Bot's workspace tools, not another Bot's filesystem/profile or any service credential. Both components retain `--network=none`.

After the edit turn, trusted runner operations create an exact local commit, capture actual test commands/exit codes/timeouts/output, verify head and clean status after tests, and collect the exact base→head diff with external diff/textconv disabled. Failed/skipped/no tests or changed working files/head remain partial. No automatic retry/replay: one coding run per work; interrupted runs retain interrupted/coding_interrupted_no_replay. Reservations are never refunded. Each check has a durable pre-dispatch unknown record; cancellation retains observed checks and refuses late artifact publication. Logs are bounded to 2000 characters per stream (excerpts, not complete logs); secret patterns are redacted. Oversized diff/output fails closed instead of certifying incomplete evidence.

Diff text and checks JSON are immutable staged artifacts published atomically by the existing report gateway/result commit; generated Markdown/manifest and source lineage retain the existing lifecycle protections. A model response alone cannot create them. `CodingRun={attemptId,workId,state:'running'|'reviewable'|'partial'|'interrupted',reason,baseCommit,headCommit,diffHash,reportId}`; reportId is populated only at committed publication. Until then run metadata is not a delivered artifact. Work remains waiting for owner review even when execution is reviewable; this does not assert owner completion or authorize a push.

Queries: `repositories(actor):CodingRepository[]`; `view(actor,workId):CodingView={job,runs,available,checks}`. Plans/check bodies are hidden when retained evidence authority is withdrawn; ordinary report/artifact queries enforce their independent lineage. Deletion erases duplicate plan/check caches; no credential is ever stored in these tables. `committed(tx,attemptId)` attaches immutable report IDs at result commit; `recover(tx)` marks interrupted shell work and removes lifecycle-deleted caches. Metadata is diagnostic, not an approval.

Deterministic generated-repository/scripted-model/fake-runtime tests prove actual edit→test→diff protocol, credential absence, hook/config/path refusal, duplicate receipt/no replay, changed-during-test partial state, failed/skipped registry checks and cancellation. They do not prove a container kernel boundary. Live/paid calls, real Linux x64/arm64 isolation, preloading UX and production package availability remain pending. UI boxes stay unticked.
