# app.coding-work/v1

CODE14-01 (#257), Phase B; FR-06/07/08/14/17/35/36/42; NFR-01/02/07/14. Logic only, opt-in `--s14`; UI acceptance remains pending for Claude Opus 5.5 high. Exported contracts: `src/s14/coding-types.ts`, `coding-protocol.ts`, `coding-model.ts`, `coding.ts`. Introduced schema **13**; the current combined schema **15** refuses unreleased 1–14 without migration or erasure.

Owner commands use `S14Application.execute`, the existing authenticated envelope, exact keys, receipts, audit and rollback boundary:

- `coding.repository.grant {id,botId,url,baseCommit,registry?:{hosts:string[]}|null}`, expectedRevision 0: a configured resource slot explicitly in that enabled Bot's ceiling. URL is exact credential-free `https://github.com/<owner>/<repo>.git`; baseCommit is a full nonzero SHA-1 commit ID. No Project, connection or work follows. Registry scope defaults to null (off); only an explicit owner selection grants the listed registry hosts. The service fetches the pinned commit through the trusted bundle broker below; no host path is accepted. One immutable identity cannot be rebound; revoke then use another slot.
- `coding.repository.revoke {repositoryId}`, current repository revision: independent lifecycle tombstone fences future admission/tools/publication and stale-image restores.
- `coding.start {repository:{id,revision},work:StartPayload,install:CodingCheck|null,tests:CodingCheck[],connection?:{id,revision}|null}`, current conversation revision: atomically invokes ordinary work.start and captures the repository/commands. Exactly one Bot and one repository scope. Required tools are `computer,coding`; optional `effect_push` grants **proposal capability only**, not external execution. Other tools refuse. All Bot/work/resource/owner/route/time/budget checks remain in force. Internal coding without effect_push cannot propose Git effects.

`CodingCheck={argv:string[],timeoutMs:number,network:'none'|'registry',coverage:string}`. At most 8 tests, 32 literal argv entries each, 1–300000 ms each. `coverage` is an owner declaration, never a measured coverage claim. Credentials/control characters refuse. Ordinary commands, model tools, Git and Phase A computers retain `--network=none`. `network:'registry'` requires the captured repository's explicit `registry:{hosts}`; without it the check stays unrun with `coding_registry_scope_required`. Hosts are an exact unique nonempty subset of the existing registry list: registry.npmjs.org, pypi.org, files.pythonhosted.org, proxy.golang.org, crates.io. Wildcards, URLs, IPs and repository/model-provided additions refuse. The normalized scope is visible in repository queries and receipts, captured in the job and hashed in the ordinary work/resource authority snapshot. Revoke fences admissions, dispatch and late publication; widening requires a new owner grant identity.

Registry checks run one at a time in an ephemeral container belonging to that computer, with only the selected Bot's bounded workspace mount, no profile/state/credential/control mount, finite CPU/memory/PID/tmpfs limits, no swap, read-only root, non-root user and no capabilities. Dependency scripts are untrusted box code. It joins a dedicated internal bridge with DNS disabled, verified as its only network, with no usable IPv4/IPv6 default route. The unchanged CONNECT-only/443 allowlist implementation and `ContainerRegistryProxy` are reused, with per-computer names/networks and exactly the granted hosts. Only the mount-free proxy joins the egress bridge; its forwarding is disabled and verified. Proxy variables are explicit and credential-free. Package managers that do not honor them fail; no direct-network or host fallback exists. Missing proxy/topology/routes/limits fail closed with box_proxy_unavailable, coding_registry_proxy_unavailable, coding_registry_boundary_unverified or the specific computer prerequisite reason. Failed setup never dispatches the command. All descendants/proxy/bridge are removed after every check, including cancellation/revocation; unconfirmed cleanup fences the runtime handle and cannot certify success. Boot/stop also remove orphan registry resources before reuse. This adds at most one component-sized check container and one 128 MiB / 0.5 CPU / 64 PID proxy per active coding computer. Runtime `/run` is a bounded 128 MiB tmpfs for bundle JSON/base64 and runner scratch; `/tmp` remains 64 MiB.

**Residual risk:** an allowlisted registry can carry workspace data out through package requests, package names, paths and query strings. CONNECT checks the destination host/port, not encrypted content. The scope does not promise prevention of data exfiltration to those registries or exact-action mediation of package requests. Owners must consider the workspace data before granting it. No credentials are supplied to install scripts. Package tools/images must actually exist; missing tools remain failed checks.

## Trusted repository preload

`coding.start.connection` defaults to null: public fetch, with no inherited credential. An explicit `{id,revision}` selects the current resource-scoped write-only GitHub connection from app.git-effects/v2. Secret release rechecks live coding authority, repository scope, exact connection revision, independent lifecycle revision and vault availability, recording identity/revision/attempt/time only in `git_preload_releases`. Rotation/removal fences the in-flight read/import; no credential/account fallback occurs. Creating a connection never starts work.

`repositoryBundle(repository,secret,signal,allowed,transport?):Promise<Uint8Array>` in `coding-preload.ts` is the trusted seam. Public/private repositories use the same fixed HTTPS smart-Git v0 POST to the exact GitHub origin's `/git-upload-pack`, requesting only the grant's full baseCommit. Authentication is confined to that service HTTPS request header, never argv, box environment, remotes, git config, prompts, logs or bundle. Redirects, nonidentity encoding, unexpected status/MIME/packet framing, corrupt/trailing packs, missing/different commit and incomplete objects refuse. HTTP body/pack and final bundle are each <=16 MiB; the decoded object stream (including Git framing) is <=32 MiB and rejects the credential or its Basic/base64 representations before bundle creation; one 60-second deadline covers read and verification. Oversized declared or streamed bodies cancel before import. No live network call occurs in deterministic tests.

A fresh private broker-owned bare repository with empty template/environment receives only the bounded pack through strict index-pack (with max-input-size), verifies the exact commit and strict fsck, and produces a single refs/heads/preload bundle. It never checks out repository files, imports source config/hooks, invokes filters/textconv/helpers, or runs submodule commands. Credential release is not permission to run repository code on the host. Temporary objects are removed after settlement. A bounded bundle enters the Bot workspace over the guarded runner; clone/checkout runs there with hooks/helpers/ambient config disabled and origin removed. No authenticated process enters the box. Full history must fit the cap; partial/shallow/LFS/submodule fallback is not implied. Git object parsers remain trusted host dependencies, not a kernel sandbox for a compromised Git binary.

`S14Coding.scope(tx,ref):ScopePolicy|null` supplies typed repository policies. `job(tx,workId):CodingJob|null` reads a captured trusted plan. `run(directory,attempt,signal):Promise<WorkOutput>` is the trusted executor seam; root dispatches coding jobs through it before ordinary computer research. Public `schway/host` core tools perform edits in a fresh correlated/retired native context. Repository content, instructions and model done/coverage/test claims confer no authority or success. No private Schway imports or version change.

The service generates `/workspace/coding/<workId>` and branch `jit/<workId>`. An independent clone from the broker bundle uses `--template= --no-local --no-hardlinks --no-checkout`, then exact base checkout, with hooks/fsmonitor/helpers/signing/ambient Git config disabled. Checkout parents and `.git` must be ordinary canonical directories; path escapes, symlinks and gitdir indirection refuse. Checkout Git/package/test processes stay behind the guarded runner in the Bot computer; the service never runs retrieved code. The explicit computer grant permits that Bot's workspace tools, not another Bot's filesystem/profile or any service credential. The ordinary workspace and protected browser retain `--network=none`.

After the edit turn, trusted runner operations create an exact local commit, capture actual test commands/exit codes/timeouts/output, verify head and clean status after tests, and collect the exact base→head diff with external diff/textconv disabled. Failed/skipped/no tests or changed working files/head remain partial. No automatic retry/replay: one coding run per work; interrupted runs retain interrupted/coding_interrupted_no_replay. Reservations are never refunded. Each check has a durable pre-dispatch unknown record; cancellation retains observed checks and refuses late artifact publication. Logs are bounded to 2000 characters per stream (excerpts, not complete logs); secret patterns are redacted. Oversized diff/output fails closed instead of certifying incomplete evidence.

Diff text and checks JSON are immutable staged artifacts published atomically by the existing report gateway/result commit; generated Markdown/manifest and source lineage retain the existing lifecycle protections. A model response alone cannot create them. `CodingRun={attemptId,workId,state:'running'|'reviewable'|'partial'|'interrupted',reason,baseCommit,headCommit,diffHash,reportId}`; reportId is populated only at committed publication. Until then run metadata is not a delivered artifact. Work remains waiting for owner review even when execution is reviewable; this does not assert owner completion or authorize a push.

Queries: `repositories(actor):CodingRepository[]`; `view(actor,workId):CodingView={job,runs,available,checks}`. Plans/check bodies are hidden when retained evidence authority is withdrawn; ordinary report/artifact queries enforce their independent lineage. Deletion erases duplicate plan/check caches; no credential is ever stored in these tables. `committed(tx,attemptId)` attaches immutable report IDs at result commit; `recover(tx)` marks interrupted shell work and removes lifecycle-deleted caches. Metadata is diagnostic, not an approval.

Deterministic generated-repository/scripted-model/fake-runtime tests prove actual edit→test→diff protocol, credential absence, hook/config/path refusal, duplicate receipt/no replay, changed-during-test partial state, scoped registry dispatch/refusal and unavailable proxy checks and cancellation. They do not prove a container kernel boundary. Live/paid calls, real Linux x64/arm64 isolation, product UX and production package availability remain pending. UI boxes stay unticked.

Schema 15 adds identity-only git_preload_releases and captures normalized registry/connection scope in repository/job JSON; earlier unreleased stores refuse before writable open. ADR 0057 records these engineering choices.
