# s16-forward-payload-repair/v1

Status: implemented protected forward repair protocol under
[ADR 0119](../adr/0119-s16-noreplace-forward-payload-publication.md).
Complete service/client release lifecycle and aggregate acceptance remain pending.

The protected operator supplies an original request and retained point ID, never
archive/live/scratch paths or ownership hashes. Its command binds current config
and actual executing compatible package. Original current-control exclusion,
retained-point/completed-backup receipts, independent complete current preparation
and deep public candidate verification precede byte selection. All current SQL,
native, helper, credentials, client bindings and working disks stay in place.

Current missing FILE/GitHub pins select exact candidate inventory members. A
missing current pin with no exact bytes refuses the whole repair. Present corrupt
or unsafe current state refuses; current intact post-point bytes remain intact.
Withdrawn/pending/unreferenced historical material is never a target. Artifact
custody remains inert; current CHAT/publication/lineage/expiry/recipient guards
still decide every release. Required current SQL/parser/native continuity refuses
without historical replacement or initialization.

An original capture_backend action binds the immutable plan, independent current
cohort/point/package hashes, fixed parents and every member's prior absence,
expected bytes/hash, candidate member identity and empty same-parent temp inode.
New byte parents have separate independent empty-ownership actions before temp
creation. An unprepared missing plan can be reconstructed only while every original
owned temp still exists empty and targets remain absent, with the same original
independent digest. Prepared missing plans and missing/substituted owned paths
refuse recreation. Unowned nonempty fixed-nonce temps refuse adoption.

One original byte-capture intent precedes ingestion. Streamed copies compare the
whole existing owned temp prefix to the authenticated original source before
appending; no truncation or overwrite repairs a mismatch. Source FD/EOF/hash and
private inode checks bind the complete bytes. Only verified full temps settle the
original capture and permit preparation. Finite plan/count/per-file/combined byte
and node quotas include same-parent temps before ingestion.

An original replace intent precedes publication. Genuine complete current SQL
writer reservations match original current images/source identities throughout
synchronous publication. Atomic link-to-absent-target, parent fsync, removal only
of the exact original temp name, parent fsync and readback implement no-replace
publication. Temp-only/both-names/target-only are the only allowed progress states;
all must retain the original planned inode and exact expected bytes. A both-names
state has exactly two links; all other owned members have exactly one. Occupied,
substituted, changed or extra-linked files refuse without deletion or replacement.
The actual immutable plan and durable filesystem state are per-member progress;
no self-authenticating mutable progress record or new request/action identity is
used after process death or response loss.

After conclusive cut release, candidate/current public-native/helper/external/
package facts revalidate. Fresh complete owning FILE/GitHub collectors must match
exactly original custody plus the repaired current pins, with all temps absent.
Every original present file/empty parser directory and original unknown/current
SQL fact remains. A final complete SQL reservation protects original publication
readback/receipt. Close all original resources conclusively before completion and
admission clearance. Unknown close retains original capabilities/process leases;
unknown provider/VM effects are never settled or replayed by local file evidence.

This protocol is not bare recovery after losing current authority, disk rollback,
native resurrection, automatic retention or a certificate of compatible service/
client upgrade/fallback/uninstall. Those remain explicit OPS16-01 acceptance.

The protected `restore --s15 --config --request-id --point-id` command exposes
this operation. A complete request returns its original metadata-only receipt
before reading its old candidate/cohort again. A later withdrawal must never be
undone by response retry. Partial requests require their original owned paths and
unchanged independently captured current facts; unknown close keeps admission
fenced until the exact original capability conclusively disposes its resources.

Plans are at most 16 MiB, with at most 20,000 targets and 4 GiB of selected bytes.
Every staged member is at most 1 GiB. The existing combined recovery staging
quota is 12 GiB/250,000 nodes/depth 32; existing same-parent temps are included
in current byte custody and reserved before ingestion. Bounds refuse the whole
operation without truncation, eviction, deletion of unrelated bytes or a weaker
publication fallback. FILE's own upload/artifact limits still apply independently.
