# app.managed-backup/v1

OPS14-01 #263, opt-in `--s14`, current schema **17**. Implements FR-15/16/18/31/35/36/38; NFR-05/07/08/10/12/14 and S14-AC01/05/06/11/14. Engineering choices: ADR 0057. Legacy `ops.backup_manifest/v1`, its commands, registry and images are unchanged and are never accepted as S14 images.

Types: `src/s14/ops-types.ts`; engine: `S14Maintenance` in `src/s14/ops.ts`; image allowlist/verification: `ops-image.ts`; supported adapter: `schwayOpsNative(nativeRoot):OpsNativePort`. `S14Store.snapshotBytes():Uint8Array` serializes the main database, including immutable artifact BLOBs, from the exclusively locked maintenance process. Online ingress is `app.backups` (`S14Backups` in `backups.ts`); both modes use `captureS14Backup` in `ops-capture.ts`. No UI is authored in this slice.

## Running-service owner capture

Routine backup needs no terminal: send typed `OnlineBackupCommand` (`backup.create`, payload `{}`) through the authenticated JSON or no-script command endpoint. The service uses its already-held runtime lock. `expectedRevision` is `GET /api/s14/ops` → `backup.revision`, independently of Home and offline maintenance revisions. The direct service seam is `app.backups.execute(actor,command):OnlineBackupReceipt`; it synchronously reserves one durable request and returns `capturing`. Query `app.backups.receipt(actor,requestId)` / `GET /api/s14/backup-receipts/:requestId`; queries never capture. Exact retries return the current logical result; changed retry envelopes, forged actors, stale revisions, extra payload/path fields and unauthenticated/CSRF-invalid requests refuse.

Capture admits only settled transports/effects/computer operations, stopped/deleted computers, settled Bot cleanup and no active device sign-in. Busy state refuses `s14_ops_quiesce_required`; existing owner stop/account controls can settle it without a terminal. It does not cancel work or stop computers implicitly. While capturing, a durable `capture.json` blocks every managed writer (including another already-open store and owner-link issuance) while existing authenticated reads/progress remain available. All worker pumps pause. The writer-lock recheck happens inside the SQLite transaction, excluding a process that checked before the fence and then waited. Native snapshots, the application/artifact view and current ledger therefore belong to one unchanged state.

Progress is a finite phase plus completed/total native intents (0–1024), with a 60-second deadline. The HTTP response does not wait for native I/O. A deadline cannot cancel an unsupported native operation: `waiting_native_settlement` reports `s14_backup_deadline_waiting_for_settlement`, retaining the writer fence until actual close/settlement; no success or released capacity is inferred. The next boundary refuses `s14_backup_deadline_exceeded`. A failed native close reports `s14_ops_native_close_unresolved` and keeps workers paused until exclusive process restart/boot reconciliation. Generic failures expose only `s14_backup_capture_failed`, never transport exception text. Completion requires durable components and registry commit. Boot under the runtime lock first resolves an interrupted online request from that registry, removes only its orphan, and records blocked/no-auto-retry or committed completion before any store/worker starts. Unknown markers fail closed. Shutdown waits for actual capture settlement.

The online journal is outside all images, bounded to 100 durable retry identities; exhaustion refuses with `s14_ops_receipt_bound` pending a reviewed archival contract. Online retention leaves at most nine registered images, reserving the tenth slot for offline recovery. It rotates only oldest online-created images after the replacement is verified and registered, protects offline images and the current stage's source/recovery IDs, and refuses when protected points occupy the available capacity. Failed capture never prunes a recovery point. Registry and journal crashes reconcile on next boot; at most one extra candidate directory exists during replacement. A historical complete receipt describes capture at that time; `backups` is the current retained inventory.

## Offline authority and consistent capture

Stop `serve --s14` first. `S14Maintenance(path,options,native,fault?)` checks the application header and independent ledger before using the same OS-backed runtime lock as serve. No worker, model, service transport or vault is created by the CLI. A live service or another maintenance process refuses with `s14_runtime_already_open`. No in-place boot migration occurs. Existing legacy/unknown/newer headers refuse before any lock/control/image write.

`execute(actor,command):Promise<OpsReceipt>` revalidates a registered live owner actor; model text, retrieved content and the command file do not supply an actor. Commands are exactly `{kind,requestId,expectedRevision,payload}`, with `expectedRevision` from maintenance status, independently of application/conversation revisions. Extra keys, stale revisions and changed retry payloads refuse. Up to 100 logical command receipts are retained outside images; reaching this finite bound refuses new commands (`s14_ops_receipt_bound`) without evicting retry protection. The last slot is reserved for a terminal capture/activate/discard/rollback, so receipt exhaustion cannot strand a prepared candidate behind its fence. This research-MVP bound requires a future reviewed journal archival policy for long-lived operation.

`backup.create` has payload `{}`. Capture requires readable current ledger, supported native snapshots, settled transports/attempts/chat/effects and stopped/deleted computers. Unknown effects may remain recorded and never execute. Unsettled state refuses `s14_ops_quiesce_required`; use normal exclusive-boot REC14 reconciliation first, inspect its actual outcomes, and stop the service. The operator must not clear transport occupancy manually.

The process lock excludes other managed writers across all asynchronous native calls. A durable external fence additionally blocks ordinary `S14Store` reads/writes and service boot. The image and artifact inventory come from this unchanged view. Every non-deleted/non-empty native intent must be retired with its exact saved reference; an unresolved/creating/correlated/missing reference blocks completion. Each snapshot is captured separately through `snapshotSessions([reference])`, validated through `validateSessionSnapshot`, matched to the saved branch and required to be retired. The independent lifecycle position is rechecked before publishing. The manifest is written last and the registry/receipt commit only after durable verified components. Orphans without a registry entry are unusable; no incomplete image is advertised as complete.

## Files, manifest and bounds

Registry, receipts and boot fence are at `<database>.ops/`, outside all images. A backup is one registered ID under `backups/<id>/` containing:

- `application.sqlite`: fresh compacted credential-free main image, containing the transactional immutable artifact BLOBs.
- `native-<index>.json`: one opaque public `HostSessionSnapshot` per retained intent.
- `manifest.json`: `ManagedBackupManifest`, `contract:app.managed-backup/v1`, `format:jit.s14/v1`, schema/build/id/installation identity/time, `state:complete`, lifecycle digest and hash-only append-table prefix positions, native contract/format, every component's flat name/size/SHA-256, exact committed artifact id/size/SHA-256 inventory, and `credentials:excluded_reconnect_required`.

Bounds: 64 MiB application plus serialized native bytes, 2 MiB manifest/control files, 1024 native intents/snapshots, 200000 application rows or ledger records and 10 registered backups. Offline capture refuses a full registry; online rotation is limited as above. Remote hosting and retention UI remain outside this slice. Unregistered interrupted captures may be removed by an exact `restore.discard` using `pendingBackupId` from offline status after a process crash. Registered complete backups survive discard.

No tar/zip extraction, caller-selected path, path-bearing manifest entry or external arbitrary archive import exists. Only this installation's registered images can restore. Flat names are derived, duplicate native IDs refuse, file reads use `O_NOFOLLOW`/regular-file/single-link/size checks, writes are exclusive mode 0600 in same-owner mode 0700 directories, and application/native/control component hashes are checked. Ancestor symlinks refuse; macOS's root-owned fixed `/var`→`/private/var` and `/tmp`→`/private/tmp` aliases are the sole development-platform exceptions. Each newly created directory and its parent are fsynced before descendants are published; existing directory entries are flushed again to cover interrupted mkdir/fsync windows. Component file contents and containing-directory metadata are fsynced before manifest/registry completion, and atomic journals require a successful directory fsync after the shared durable-write helper. A forged main schema, trigger, integrity error or FK violation refuses before writable quarantine opens.

## Credentials and lifecycle separation

Every main and lifecycle table is explicitly classified; unknown tables fail closed, even when empty. `opsMainTables` and `opsLedgerTables` are the reviewed inventory, guarded against the actual fresh schema in `tests/s14-ops.test.ts`. Owner password hash becomes a non-authenticating placeholder in the image. Sessions, login throttle, command receipts, Parallel connection/session references, personal OAuth flows (including state hashes), browser input/leases, transport rows and unpublished staging are emptied. Parallel resets to anonymous mode. Every retained string/BLOB is scanned with the shared credential detector and registered-secret fingerprints; a hit blocks capture rather than rewriting immutable evidence. SQLite secure deletion plus VACUUM removes free-page copies. The archive contains neither the independent lifecycle database nor a usable owner password/session.

Personal client/connection/grant metadata, source scope/consent pins, read caches, draft revisions and effect observations are retained as credential-free data. Client secrets, OAuth state/verifier/code, access/refresh tokens, sealing keys and ciphertext remain in the separate protected vault and are never captured. A known credential in any retained connector record blocks capture. Quarantine fences archived consent and requires reconnection even when the installation vault still exists; source/read/report lineage remains subject to the current independent lifecycle ledger.

Coverage includes graph/default/step/transport state; reports, `report_reviews`, artifacts and staging; both share kinds; native intents/checkpoints; routines/results/attention; Bot generations, capability proposals and payload-deletion markers; computer activity/operations/attempt generations; memory source/access-history pins, decisions and producer lineage. Durable evidence is retained, transient tables are emptied, and restore revalidates every retained dependency. `lifecycle.withdrawals` includes `retained_evidence` entries as well as deletion/access/share/grant/computer/attention/routine facts; none are replaced by an archived copy.

The filesystem is never recursively copied. Schway home/credential storage, Jit/channel/vault secrets, `<database>.owner-setup.json` and temporary owner-link files, device sign-in protocol/approval state, computer volumes, raw browser cookies/profiles and host files are excluded. The public native envelope contains its required workspace identity and opaque conversation/metadata artifacts; native bytes are never interpreted or rewritten as native records. Public artifact envelopes allow generic decoded-byte credential scanning. No archive or native bytes enter prompts, logs, HTTP metadata or command receipts. Arbitrary unrecognized secrets in user-authored prose cannot be inferred from shape alone; the supported host surface excludes credentials and Jit registers known secrets.

Sign-in receipts are excluded with all `command_receipts`; provider credentials remain in the separate native credential store. Setup capability files are not archived, and activation retains the current owner verifier locally, so an old setup link never becomes usable. Runtime-lock/ops journals are installation control state, not image authority.

The live independent `<database>.lifecycle.sqlite` remains authoritative. Archives carry only its identity/digest and immutable-table prefix count/hash metadata, never replacement authority. A missing/mismatched/unreadable ledger fails closed; a current ledger that lost the archived append-only prefix also refuses. Current monotonic usage/reservation facts, withdrawals, Bot generations, native intent catalog, effect claims/outcomes and routine consumption are consumed by the existing S14 lifecycle/REC14 code before activation. Restore details: [app.restore-activation/v1](app.restore-activation-v1.md).
