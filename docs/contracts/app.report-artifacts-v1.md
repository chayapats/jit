# app.report-artifacts/v1

REPORT14-01 (#252), S14-AC06/08; FR-07/16/18/29/42, NFR-05/07/08/10. Opt-in S14; exported shapes in `src/s14/report-types.ts`, trusted handler in `reports.ts`. Consumes app.work-graph/v1, app.external-evidence/v2, app.context-provenance/v2 and app.memory-scope/v2. Schema **13**, refusing unreleased schemas 1–12 with fresh-state.

A report is immutable committed data, independent of free-form `WorkResult`. `WorkOutput` may carry `report?:ReportProposal`; no free-form done text, workspace file or staged snapshot creates a report. `Work.state:'ready'` retains its existing meaning of inspectable result evidence. Only a committed `Report.state:'ready_for_review'` certifies the report/files exist. Neither state closes the owner's obligation. `ReportView.completion:'owner_review_required'|'owner_accepted'` and `acceptance:ReportAcceptance|null` are live projections outside immutable `Report`, separately from `Report.coverage:'partial'|'covered'`.

Exact trusted integration signatures:

```ts
S14Reports.publish(tx: AppTransaction, attempt: Attempt, proposal: ReportProposal, resultBytes: number): Report;
S14Reports.list(actor: OwnerActor, workId: string): ReportView[];
S14Reports.view(actor: OwnerActor, reportId: string): ReportView;
S14Reports.review(actor: OwnerActor, workId: string): ReportReview;
S14Reports.apply(tx: AppTransaction, command: ReportCommand): ReportReceipt;
S14Reports.reconcile(tx: AppTransaction): void;
```

Publication is called only from `S14Authority.commit`, in the same writer transaction as the fenced work result, lineage source, report revision and immutable artifact bytes. It is not an owner command or model authorization surface. The public native executor requests JSON `{text,report}` (routines also allow `{outcome:"report",text,report,proposals}`); the report remains untrusted data until this handler validates it. Free-form/malformed non-report text remains ordinary inspectable result evidence and supplies no report readiness. Invalid typed report publication rolls back its result/files together.

`ReportProposal` is exactly `{title,claims,missing,limitations,artifactIds}`. At most 32 claims, 8 citations per claim, 32 missing/limitation items and 4 staged artifacts. Each claim is `{id,text,kind:'quote'|'inference',citations,covers,conflicts}`; text is at most 4096 UTF-8 bytes. A citation is exactly `{attemptId,id,revision,quote,scope:'snippet'|'excerpt'|'page'}`. The target is the current attempt or an accessible committed graph dependency whose actual evidence entered the bounded handoff. Every citation resolves through `app.parallel.citation`; the source revision must exist, belong to this work and contain the exact quoted text. Guessed IDs, wrong revisions, invented quotes and unread/cross-work references refuse the atomic report. Original source/access pins remain in publication lineage.

Claim `kind:'quote'` requires its text to equal a verified citation quote; otherwise it is unsupported. Inferences remain explicitly labelled. Page scope cannot be claimed from a snippet/excerpt or a truncated full response. Unsupported claims can be inspected, with `support:'unsupported'`, an explicit flag and a missing-evidence entry; they do not satisfy a target. Conflicts retain both claim/source sets, remain flagged and force partial coverage. No majority vote resolves them. Cache/freshness/coverage metadata comes from actual evidence; unknown freshness never becomes fresh.

`ReportClaim.covers` remains the Bot's untrusted target declaration, preserved for compatibility even when it does not pass the evidence tests. Claim cards label it “Bot claims to address” in both locales; only `Report.covered` is the service's aggregate validated target set. A supported excerpt can still fail a full-page target, and another claim satisfying that target never certifies this claim. Ready for review and owner acceptance never imply coverage. The visual structure is unchanged.

The authenticated `work.start` payload can include `requiredEvidence:EvidenceRequirement[]` (at most 32), captured in the immutable grant. Each target is `{id,label,url:string|null,coverage:'snippet'|'excerpt'|'full_content_returned',freshness:'any'|'live_reported'}`. These are owner-defined evidence tests, never model-defined completion authority. Claim covers may reference only these IDs. Required source URL, content coverage, truncation and requested freshness are checked against cited actual evidence. Missing targets, unsupported/conflicting claims, graph gaps, omitted handoffs and failed/missing web reads remain in `Report.missing:ReportGap[]` even when a model omits them. An absent/empty target list always records `{kind:"completion_rule_not_machine_verified"}`; Jit never interprets arbitrary prose as machine-proven completion. `covered` means these bounded evidence tests passed, not that the conclusions are true or the owner closed work.

`ReportGap` is a discriminated service-only union: `{kind:'completion_rule_not_machine_verified'}`, `{kind:'required_evidence',targetId}`, `{kind:'unsupported_claim'|'conflicting_claim',claimId}`, `{kind:'step',stepId,state}`, `{kind:'handoff',stepId,reason}`, `{kind:'read',readId,outcome}`, `{kind:'missing_url',url}` or `{kind:'failed_url',url,failureKind}`. The handler constructs and deduplicates these facts. `ReportProposal.missing:string[]` remains model data and is copied only to `Report.modelMissing:string[]`. A model gap can make coverage partial conservatively, but can never create a service code/target/read/claim fact. UI always renders `modelMissing` in the existing untrusted frame, even when text matches a real service ID or code. Markdown and JSON manifests separate both fields; immutable export bytes never claim to contain live owner acceptance.

The owner-only `report.review.accept` command is exactly `{kind,requestId,expectedRevision,payload:{reportId,reportRevision}}`. `expectedRevision` is the current **review** revision from `GET /api/s14/work/:id/report-review`, not the report number or Work revision. `ReportReview` is `{workId,revision,reportId:string|null,reportRevision:number|null,completion,acceptance}`; no report gives revision 0/null identities. First publication creates review revision 1. Acceptance increments it and records `{reportId,reportRevision,ownerGeneration,requestId,acceptedAt}` in a separate `report_reviews` record. It only accepts the latest available exact report. Stale review/report revisions or an older report fail `stale_revision`; withdrawn payload fails `report_unavailable`; a fresh request for an already accepted target fails `report_already_accepted`. Authentication, Origin, CSRF, exact shape, retry digest, receipt/audit and transaction rollback use the common command boundary. Receipt `{kind,requestId,conversationId,review}` has no report body. The same request returns its historical receipt; it never resurrects a superseded acceptance.

Acceptance grants no execution, creates no Work/grant/coverage mutation and does not turn partial into covered/complete. Publication of any new report revision increments the review revision and clears acceptance; all older report views then require review. Forget/delete/correction/revocation of the accepted report lineage clears acceptance and increments the review revision before reads or acceptance, including reconciliation after stale-image restore with the current independent ledger. An owner-generation change also invalidates acceptance. Valid acceptance survives an ordinary restart. Review history remains in authenticated command receipts; immutable report/file hashes do not change.

The Report tab carries the owner acceptance control using this command and projection (`src/s14/web-report.ts`). It appears only for the current review target; evidence coverage and partial wording stay independent. See section 19 of the experience document.

Committed handoffs contain only accessible result excerpts (8192 bytes each) plus actual evidence read via the citation port, bounded to 49152 bytes. Omissions/excerpts are explicit gaps. Synthesis sees committed untrusted data, not peer native sessions, private workspaces or operator instructions. Successful siblings and older report revisions remain independently inspectable; a failed sibling cannot erase them or claim complete work.

Each report has opaque ID, immutable per-work revision, producing attempt/Bots, creation time, source identity, normalized claims/evidence/flags, covered/missing targets and limitations. Publication always produces `report-rN.md` and `evidence-rN.json`; the latter contains exact citation/evidence metadata with source content excluded. Validated optional workspace snapshots are added through app.artifact-gateway/v1. Delivery bytes plus result text must fit the attempt's already reserved output; serialized report data is separately bounded by that same reservation and 1 MiB maximum. The service creates files from validated data; a model cannot select a host path.

Lifecycle: report and staged-file sources conservatively inherit all original packet sources, claim/decision ancestry and access revisions. Preview now includes `MemoryImpact.reports:{id,workId,revision}[]` and `artifacts:string[]`. Forget/delete/correction/revocation retires dependent reports and removes downloadable payload; source/claim originals follow existing memory policy. Revoked Bot/resource/source access and explicit computer reset/delete withhold descendants too. Execution stop fences future calls/publication while retaining already committed owner evidence; ordinary process restart/idle stop does not erase immutable snapshots. Grant expiry alone does not create new execution authority and does not erase otherwise valid committed owner downloads. Source withdrawal, revocation and computer invalidation are checked before each read/download and after async snapshot waits. No late fenced publication can commit.

Retained producer checks traverse all actual graph inputs and delegation parents, including uncited/transitive result text, rather than treating citations as complete ancestry. Source producer pins and pre-pin service-record resolution (app.context-provenance/v2) enforce the same boundary before a report or staged snapshot can be committed. Destructive computer withdrawal reaches every dependent report revision, generated file and workspace snapshot, invalidates acceptance and remains effective after stale-image restore. Ordinary restart and unrelated reports remain readable.

The independent current lifecycle ledger also records identity-only revoked access/share revisions, stopped execution grants and reset/deleted computer generation ranges. Reconciliation applies access/share revision tombstones before old application images can expose reports, artifacts or memory again. Republish/new share cannot revive derivatives pinned to a revoked revision. Startup discards private staging and fences uncertain native work; committed valid reports/files survive restart. Keep the current ledger when restoring an application image; managed backup/restore/replay remains #254/#263, not shipped by this slice. External provider copies are not erased by local withdrawal.

Schema 8 introduced reports (unique producing attempt and per-work revision, immutable metadata, nullable body), artifacts (opaque ID, immutable metadata, nullable BLOB) and artifact_staging (private bounded snapshots). Schema 9 adds `report_reviews` (work FK, revisioned JSON) and typed report-gap/graph-phase records. Combined schema 13 also retains first-run computer activity; schemas 1–12 are refused rather than migrated. SQL rejects changing committed report/artifact metadata or replacing non-null content; lifecycle may only remove payload. SQLite rollback-journal publication remains atomic with the attached independent ledger. No filesystem blob path or credential is exported.
