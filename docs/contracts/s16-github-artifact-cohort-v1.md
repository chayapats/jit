# s16-github-artifact-cohort/v1

Status: protected current component selected by
[ADR 0109](../adr/0109-s16-github-artifact-custody.md); aggregate acceptance incomplete.

The current control capability supplies its genuine exclusive installation lease,
CHAT exclusion and exact runtime/github.sqlite source (application 0x4a473135,
format 1, current installation), plus selected/retained DATA15 disclosure.sqlite
(application 0x4a445135, format 1). Existing source presence cannot be omitted.
It reads raw metadata without constructing
GithubStore, performing application recovery, reading a credential or calling a
gateway, workspace, Git or provider. Current connection/withdrawal/unknown-effect
authority stays in the independent complete SQL cohort.

The owning identity/records/receipts schema and known record kinds are bounded
before allocation. Combined rows are at most 50,000/64 MiB JSON, each JSON row
1 MiB; malformed UTF-8/JSON, foreign readers/identity, unknown schema/kinds and
invalid owning bundle references refuse. Exact bundle_<SHA256> refs require
revision 1/generation 1. Slots are selection.evidence, action selection/evidence/
effect, top-level coding work_evidence and select_* receipts. DATA15's derived
artifact slot also participates, including a bundle captured before GitHub
selection publication. It retains its exact domain-hashed row/ref identity;
its own 10,000-row/64 MiB/128 KiB-row bounds apply before loading. Current and older
action/receipt refs remain distinct; arbitrary remote-content keys are ignored.
The metadata states GitHub, namespace and DATA15 presence separately.

Every file in the fixed installation github-artifacts namespace must have its
owning hash-addressed name and private same-owner single-link regular custody.
All referenced bundles must exist. Valid unreferenced files are retained with no
inferred correlation, publication or execution authority. An unused absent/empty
namespace stays absent/empty; a missing registered namespace or unowned nonempty
namespace refuses without initialization. No suffix-based cleanup occurs.

At most 20,000 files/4 GiB bytes/4 MiB metadata and 50,000 correlation entries are
accepted. Individual bundles obey the protected payload component's 1 GiB limit;
the current Web writer's lower 256 MiB bound is not imposed retroactively on
retained files. Full aggregate immutable/native budgets still apply. The existing
64 KiB no-follow payload reader verifies hashes/EOF/FD attributes without decoding
or exporting content. A matching hash is not proof of Git ancestry or fresh scope.

The immutable observation has path-free role/reference metadata and SHA-256,
separate host-only payload descriptors and an original assertCurrent capability.
Original absence/namespace/file inodes and attributes remain pinned; revalidation
rereads metadata and hashes, rejecting changes rather than replacing its expected
cut. Closed contexts cannot reuse observations. Archive metadata cannot create
this live capability or revive an old action, recipient or selected issue.
