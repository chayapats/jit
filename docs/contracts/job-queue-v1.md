# JOB01 queue admission, v1

Owner: Jit #6. `jobs.queue_admission/v1` is implemented on this issue branch; downstream eligibility requires its tested artifact in the integration base. FR-07/10/14/15/18, NFR-05/06/10. See ADR0010. This is application admission and service-owned work, not a production Schway bridge, native-session reconciliation or JOB02 attempt fencing.

`src/jobs/types.ts` defines the data contracts. Trusted composition registers `WorkDefinition` objects with stable IDs, configuration revision, exact provider/model/auth-route references, declared initial usage, pure input validation and one asynchronous bounded step. The registry has at most 32 definitions. Registration is process-owned code; there is no HTTP/model/repository code loading. Change a definition's revision when its semantics change. Its route/cost identity is fingerprinted. The included `project.status` handler reads one exact committed project revision without inference or external requests.

| Entry | Contract |
| --- | --- |
| `new JobQueue(store, policy, definitions, options?)` | Validates finite policy/definitions before claiming one local scheduler in SQLite. Clock/process/timer ports are fixture seams. Another live process or another instance in the same process rejects. Only a proven absent prior PID permits recovery; ambiguous/PID-reuse cases fail closed. |
| `Application.execute(actor, EnqueueJobCommand)` | Exact project scope, expected project revision, explicit input/configuration/policy revisions, purpose, priority and positive limits. Commits job, owner authorization generation, receipt and audit atomically before acknowledgment. This command authorizes the named work to start; task acceptance does not. |
| `Application.execute(actor, ResumeJobCommand)` | Exact project/job and expected job revision; waiting only, unchanged definition/policy/route, remaining deadline and retry budget. Explicit resume consumes one remaining retry. Exhaustion becomes a visible terminal result rather than extending budgets. |
| `Application.jobs(actor, projectId, after?)` / `job(actor, projectId, jobId)` | Authenticated committed projections; bounded insertion-order cursor pages, exact job scope, inert work choices and local admission availability/next action. No provider request, receipt or admission side effect; persisted jobs remain readable without a scheduler or provider connection. |
| `JobQueue.pump()` | Admits queued interactive work before background work within global and provider/auth-route concurrency. Models on the same auth route share that route's ceiling. Running calls retain slots. Each admission reserves declared cost in a successful transaction before invoking the adapter. |
| `WorkContext.reserve(usage)` | Commits additional nonnegative finite usage before the trusted adapter may spend it. Overdraw terminates visibly; uncertain/spent reservations are not refunded. Adapters must reserve each Schway call's context/output and maximum request-retry cost before dispatch. The queue does not implement request retries or a model/tool loop. |
| Step outcomes | `succeeded` requires bounded nonempty committed evidence; `yield` stores a bounded checkpoint and appends behind same-priority peers; quota/login/unavailable become waiting on the original route. A bounded failure with evidence is partial; raw exceptions/malformed outcomes become fixed safe failure reasons. |
| `JobQueue.close()` / `idle()` | Close prevents new acknowledgments/admission and requests cancellation. An unsettled adapter retains ownership/capacity; `idle` waits only for currently active steps and must not be awaited on an intentionally stalled fixture. Late success after shutdown/deadline cannot publish. |

`JobLimits` requires every positive finite field: roles, calls, rounds, hops, contextTokens, outputTokens, retries and wallMs. Counters include the registered work-step invocation; adapters reserve additional chain/model usage before spending it. Remaining counters may reach zero. Deadlines cover queue/wait time and are not renewed by resume. Exhaustion is blocked/partial/failed with a safe reason and next action. `occupiesAdmission` distinguishes a visible timeout from confirmed adapter settlement; cancellation is a request, not proof a running provider call stopped.

Policy and defaults come from declared `JIT_JOB_*` settings in `readConfig`: revision 1, pending queue 32, global concurrency 2, per-auth-route concurrency 1, input 16384 bytes, evidence 4096 bytes, maximum roles/hops 16, calls/rounds 64, context/output tokens 64000/16000, retries 3 and wall-clock 60000 ms. These are finite development settings requiring measurement before pilot, not account capacity claims. Invalid values fail startup before admission. Hard validation ceilings also apply to trusted direct callers. No route/provider/model/auth/billing fallback exists.

The Web project menu links to `/projects/<project>/jobs`. A named start form discloses its selected route and finite profile. Job details show state, reason, next action, input/configuration revisions, remaining budgets and committed evidence. Read projections compute queued/admitted/waiting wall time left from the current clock, capped by the last committed remaining value; terminal budgets stay frozen. Reads never change job revisions, state or replay receipts. Waiting jobs offer an explicit continuation action. Native forms/links preserve the owner session, exact Origin, CSRF and request deduplication. Evidence is escaped untrusted text; scripts/URLs cannot execute.

Inputs and checkpoints are bounded plain JSON: dense ordinary arrays and plain objects have at most 256 entries, nesting at most 12, no accessors/symbols/extra array properties or executable values, and a final UTF-8 byte ceiling. Array length is checked before traversal or serialization; input-owned methods are never invoked.

| HTTP | Payload/result |
| --- | --- |
| `GET /[api/]projects/<project>/jobs?after=0` | Bounded committed list with choices, `hasMore` and `nextAfter`. |
| `GET /[api/]projects/<project>/jobs/<job>` | Project-scoped committed job. |
| `POST /[api/]projects/<project>/jobs` | `requestId`, `expectedRevision`, `type`, `configurationRevision`, `policyRevision`, `purpose`, `inputRevision`, JSON `input`, `priority` and JSON `limits`; forms encode input/limits as JSON strings. JSON returns receipt; form redirects to stable job detail. Unknown fields reject. |
| `POST /[api/]projects/<project>/jobs/<job>/resume` | `requestId`, expected job revision; no replacement route or new budget fields. JSON receipt or detail redirect. |

Schema v3 snapshots existing v0/v1/v2 stores before migration and keeps owner/project/conversation/source records intact. Queued work and all budgets survive restart. A recovered interrupted admission becomes waiting with an inspection action; it is not declared successful or retried implicitly. Single-host PID liveness is intentionally conservative and is not a distributed lock. JOB02 owns durable attempt/native-session reconciliation and cross-store publication semantics.

Deterministic evidence uses scripted adapters, fake clocks, real SQLite commit failure, independent processes, SIGKILL at job/receipt writes, queue contention, shared-route capacity, deadline/cancellation, all resource bounds, waiting/resume, restart, injection fixtures and a frozen published v2 schema. `bun test` and `bun run typecheck` require no account, network inference, Pi provisioning or live quota.
