# s16-control-maintenance/v1

Status: protected OPS16-01 current-control inspection component, not a complete
point, historical backup, restore command or worker-admission certificate.

`openS16ControlMaintenance(config)` receives the trusted parsed explicit S15
configuration. It acquires the existing installation exclusive lease before
opening any owner/runtime connection, then the existing runtime CHAT lease.
Both must remain held while current control is inspected or captured.

The capability includes the actual runtime maintenance set plus separately
classified `outer` current connections: owner state, its linked independent
lifecycle ledger, recipient continuity and selected/retained website continuity.
These are protected current continuity under `s16-recovery-point/v1`; especially
owner auth/lifecycle state must never be included in ordinary exports or
silently promoted from a historical archive. Raw connections/identities never
enter HTTP, tools, prompts, artifacts or execution-plane state.

The opener never uses application constructors, initializes missing ledgers,
repairs permissions, boots workers or invokes providers/parsers/VMs. Private
paths, bounded main headers and logical WAL formats are checked before use;
exact owner memory/lifecycle identity, configured recipient/site installation,
meta epoch, JSON syntax and actual SQLite/FK integrity are required. Current
owner identity is distinct from the configured S15 identity. Known retained
website state is included even when a later config disables that browser.
Unknown outer SQLite files, missing mandatory state and existing outer
maintenance/capture fences refuse. Bounded exceptions are the exact
current `s16-operations-adoption/v1` or [current maintenance intent](s16-operations-control-v2.md) supplied by protected operator code,
matched to the actual owner, configuration and installation. Foreign/torn/
changed fences still refuse; candidate archives never supply that expectation.

Protected adoption methods retain that original fence, bind the independently
verified initial current journal and clear only completed initialization.
They hold both process leases continuously, do not mutate application ledgers,
and grant no effect, policy, restore or worker-admission authority. Only the
known atomic receipt transition refreshes its owning exclusive lease guard.

The protected `operations()` capability keeps both actual leases while writing
the existing bound current journal. Its maintenance fence binds the exact
original operation, current journal revision/configuration and actual owner.
Only verified terminal metadata clears that original gate. Lost gates are
rebuilt from current immutable fields, never by replaying an unknown effect.
The capability performs no physical capture, activation or point deletion.

`nativeNamespace()` resolves the fixed CHAT/MODEL/GitHub namespaces from the
current runtime handles and original VM custody under both retained leases.
Its [versioned inventory](s16-native-namespace-v1.md) preserves missing,
uncorrelated, untracked and ambiguous ownership instead of shrinking the set.
It grants no native execution/settlement and does not itself capture sessions.

`firecracker` holds the separately registered current controller intent journals
under their original process leases. Its [owning custody protocol](s16-firecracker-controller-custody-v1.md)
supplies additional SQL sources while preserving original accepted/dispatched/
unknown facts without adapter construction, credential access or helper calls.
The parent closes these sources before outer/runtime handles; unknown disposal
retains installation/CHAT exclusion. Root-helper physical state is separate.
The immutable `sources` collection combines outer, selected/retained runtime
and auxiliary controller SQL sources with unique aliases/handles. Aggregate
SQL capture must use it; it does not imply non-SQL installation completeness.

`helperCustody()` reads the [complete current helper metadata cohort](s16-helper-cohort-v1.md)
through the authenticated read-only custody operation and existing-only vault.
It preserves every original controller intent and independently retained helper
authority. Await original reads before closing; in-flight/unknown reads retain
all source/process exclusion. An immutable observation revalidates against its
original complete digest before aggregate publication/activation. It grants no
physical settlement, root reconstruction or historical authority.

`fileCustody()` supplies the [current FILE/parser cohort](s16-file-cohort-v1.md):
owning-pinned ready/staged bytes and separately untrusted original fragments,
unpublished bytes and parser snapshots. It keeps pending/withdrawn states and
unobserved container/job/generation facts without boot recovery, parser reset or
output promotion. Original absence/inodes/bytes remain guarded; host-only source
paths never enter its metadata. This remains separate from physical settlement.

`githubArtifacts()` supplies the [current GitHub bundle cohort](s16-github-artifact-cohort-v1.md)
from raw owning slots and the complete hash-addressed namespace. Older action/
receipt references, DATA15 pre-publication lineage and unpublished bundles remain retained. It runs no store
recovery, Git, credential read or gateway action, and does not infer publication
or settlement. Original namespace/absence/inodes and metadata/bytes stay guarded.

`nativeSet(requestId, options)` supplies the [protected native-set coordinator](s16-native-set-v1.md)
with this genuine lease, current namespace and original journal. The context
retains exclusion while any returned session is unreleased. Await session close
before synchronous context close; a premature/unknown close refuses before any
outer database or process lease is released. No async capture becomes detached
from the context's resource custody.

`assertCurrent` rechecks both retained leases, runtime/current configuration
binding, outer inventory and observed owner/ledger inodes/permissions/attributes.
Closing first releases only the raw outer handles, then runtime handles/CHAT
exclusion, then installation exclusion. Unknown close keeps the remaining
process exclusion held; no file is unlinked to force release. Failure during
open cannot release installation exclusion after an unknown runtime release.

For the future forward activation coordinator, [ADR 0115](../adr/0115-s16-source-retirement-with-retained-exclusion.md)
adds `retireSources()` and `assertExclusion()`. Retirement first requires current
guards, released native/helper resources and no open SQL source transaction.
It closes original controller/outer/runtime data handles while retaining every
installation/CHAT/controller process lease. Full content/capture/journal methods
refuse once retirement starts. Unknown data disposal retains all process locks,
including controllers already retired earlier in the attempt; retry the same
context or complete its original close. Successful retirement is idempotent.

`assertExclusion()` requires completed retirement, the original live process
transactions/lock and root identities, current configuration/composition and
original fence. It intentionally makes no current-data, target or compatibility
claim. The coordinator must separately bind and revalidate exact current cohort/
prior/target hashes and durable per-component progress. A completed source close
does not supply a restore intent, activate an archive or clear an admission gate.

Byte/native/profile/vault/helper/device/package custody and durable aggregate
fence/intent/activation are still separately required. This component does not
certify physical/native settlement, independent receipt provenance, historical
reconciliation or full installation completeness.
