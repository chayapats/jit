# app.memory-scope/v2

MEM14-01 logic delivery; S14-AC05/06, FR-04/05/16/31, NFR-05/07/08/10/11. Types: `src/s14/memory-types.ts`; implementation: `src/s14/memory.ts`. Product UI: `src/s14/web-memory.ts`.

`S14Application.memory:S14Memory` owns sourced, private-by-default claims. `MemoryRef` is exactly `{id,revision,generation}`. `MemorySource` records originating Bot/conversation, owner/bot/external attribution, exact content snapshot, derived source references and time. `MemoryClaim` records that origin, source reference, fact/inference, quote, conservative dependencies and conflicts. A fact proves an exact owner statement, not truth or execution authority. No Project identity or mandatory embeddings exist.

`memory.remember` explicitly retains owner text in the conversation's Bot scope. Chat replies may suggest bounded extractor assertions in `ChatOutput.memory`, validated by `extract(tx,packetId,sourceRef,output):{claims:MemoryRef[],rejected:number}`. Assertions have exactly `{kind:'fact'|'inference',text,quote,conflicts:MemoryRef[]}`. Maximum 16, text/quote 2048 UTF-8 bytes, exact quote in an admitted source, conflicts restricted to admitted claims, every admitted claim inherited as a dependency. Fact requires owner attribution, text equal to quote and no derived claim input. Unsupported fields, fabricated references and derived/suppressed sources refuse. Extraction never changes publication or owner decisions.

`lookup(tx,botId,ref,attempt?):MemoryLookup` checks access before payload/lineage. Private means originating Bot only. Explicit owner publication uses a separate `MemoryAccess` revision and audited receipt. Shared assertions remain untrusted facts/inferences and do not authorize outbound disclosure. A private dependency remains inaccessible even when a dependent assertion was published. The shared MEM01 active-lineage traversal fails closed at depth8/64 visits, including prospective claim roots. Lexical retrieval reuses the existing ASCII word/non-ASCII trigram policy for Thai no-space text; access filtering precedes relevance ranking. Paraphrase recall is not claimed.

`memory.share` creates a nontransitive immutable claim snapshot with explicit receiver, resource scope ID and expiry (at most 24 hours). That ID must already be in installation resource policy and the receiver's Bot ceiling. `memory.scope(tx,ScopeRef):ScopePolicy|null` supplies the existing work-grant intersection; the receiving attempt must carry that exact share revision. Chat membership and guessed IDs confer nothing. `memory.revoke` revokes shared publication and all shares of that claim; already disclosed knowledge cannot be erased. Publication history remains inspectable.

Generated `MemorySource.access` and extracted `MemoryClaim.access` pin the originating consumer Bot's publication/share revisions, including transitive claim dependencies. `derive(tx,packet):{derived:MemoryRef[],access:MemoryPacket['access']}` supplies these pins for replies, evidence and work handoffs. `sourceCurrent(tx,ref):boolean` checks the entire source ancestry and original access pins. Revocation prevents their future automatic use even after republication, while retaining the originating Bot's original source/claim. Older derivatives without access provenance fail closed. Owner conversation projections retain reply text and add `Message.contextState:'withdrawn'`; the existing withdrawn label is shown beside that text. This is context withdrawal, not erasure of prior disclosure.

`memory.correct` withdraws the old assertion and creates a fresh private exact owner fact. `memory.forget` retains the original source for owner inspection while suppressing automatic re-extraction. `memory.delete` removes source/claim/message payload locally. Preview uses `preview(actor,ref):MemoryImpact`: affected claims, source siblings, transitive dependents, derived answers and contexts. The conservative suppression closure reuses the same lineage walker as legacy forget propagation, without importing legacy Project authorization. Correction never silently preserves old shared scope.

Every mutation is a typed authenticated command through `execute`, with strict payload/revision, retry digest, receipt and audit in one SQLite transaction. Payloads and exact revision sources are in [HTTP handoff](s14-foundation-http.md). Model/source output cannot call this boundary. Owner decision command `memory.decision.set` is independent of extraction and pins live conclusions by conversation/key.

Combined schema **6** includes: memory_sources, memory_claims, memory_access, memory_access_history, memory_shares, memory_decisions and memory_contexts. An independent attached `<database>.lifecycle.sqlite` stores installation identity and append-only identity-only withdrawals. SQLite rollback journals atomically commit both databases; never switch either database to WAL independently. A restored application image must retain the current installation ledger, never restore an older ledger. Missing/wrong ledger refuses, and application construction reconciles deletions and retires stale packets before workers/projections. Earlier unreleased S14 schemas and legacy stores are refused, never auto-upgraded or deleted; full managed backup/upgrade/restore remains OPS14-01. Both files are service state outside execution boxes. No credential or raw native transcript is in this ledger.

Native integration creates a fresh session per invocation, uses `HostSession.retire()` and closes through pinned `schway/host`. It never reopens old ancestry, including after compaction/restart. Physical native history deletion, filesystem recovery and full artifact lifecycle delivery remain later lifecycle slices; no erasure of external provider copies is claimed.

Deterministic evidence: `tests/s14-memory.test.ts` covers private/guessed-ID denial, owner publication history/deduplication, Thai/English retrieval, conflicting provenance, malicious extraction, receiver shares, in-flight chat/work barriers, correction/forget/derived suppression, decisions and bounded packets, restart, stale-image restore, missing ledger and rollback of both databases. No live or paid inference.
