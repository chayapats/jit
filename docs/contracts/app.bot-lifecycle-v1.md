## Owner boundary and exact policy proposals

All commands use the foundation `{kind,requestId,expectedRevision,payload}` envelope, live registered owner actor, exact keys, session/Origin/CSRF and atomic receipts/audit. An identical retry returns its original logical receipt (subject to later payload deletion redaction); changed input conflicts. Model/source text cannot create or accept policy proposals. Queries never authorize or start cleanup.

| Kind | Exact payload | expectedRevision |
| --- | --- | --- |
| `bot.capabilities.propose` | `{botId,capabilities:{tools,resources}}` | current Bot.revision |
| `bot.reenable.propose` | same shape, explicit current capabilities | current retired Bot.revision |
| `bot.capabilities.accept` | `{proposalId,proposalHash}` | CapabilityProposal.revision |
| `bot.retire` | `{botId,previewHash,retain:{history:true,evidence:true}}` | current Bot.revision |
| `bot.delete` | `{botId,previewHash}` | current Bot.revision |

A CapabilityProposal pins Bot ID/revision/generation and owner generation, action capabilities/reenable, exact selected ceiling, hash and proposed/accepted/superseded state. A newer owner proposal supersedes earlier open proposals at that Bot revision. Proposal creation changes no Bot/work/resource. Accept revalidates the exact current proposal/hash/Bot and current installation policy. It adds no account, resource/share grant or work authority. Adding web_search/web_fetch to a tool-less Jit is supported. Effective tool use still intersects current resource/work policy. Every accepted policy change (including widening) creates a new Bot generation and fences old captured grants/contexts; old work never inherits new tools. Before changing the Bot, acceptance records independent `retained_evidence/owner_retained` facts only for already committed results whose original lineage is still current. Narrowing and widening preserve those result/report/artifact bytes for owner inspection, including after execution expiry and restart; they never retain an uncommitted attempt or restore withdrawn content. Original source/access/share/route/computer withdrawal checks still apply. An in-progress transition keeps Bot.enabled false until all affected transports/computer/native cleanup settle, then policy changes become active. This conservative invalidation is an engineering choice within Q7.

Main Jit capability repair is allowed. `bot.retire` and `bot.delete` for ID jit refuse `main_bot_required`; no coordinator-replacement UI or implicit coordinator removal is invented. A stale-image main-Jit policy generation fails closed and requires a new owner reenable proposal with current selected capabilities. A deleted identity can never reenable. A retired identity can reenable only via a new exact proposal/new generation after settlement; original grants, routine captures, input leases and contexts remain fenced. Fresh work/current resources are required.

## Exact lifecycle preview and fencing

`preview(actor,botId,action:'retire'|'delete'):BotLifecyclePreview` returns current Bot/transition, action/retention, owned sources/private claims and forward descendants, contexts/reports/artifacts, owned conversation revisions, affected work/routine revisions, scoped withdrawal facts, dependent memory/snapshot share revisions, exact computer/workspace/profile IDs/generation/revision and owned/affected native intent states and exact cleanup modes. Sibling sessions in an affected stopped grant retire; only owned/dependent withdrawn contexts delete. It enumerates retained effect IDs/revisions/action hashes/outcomes, and includes identity_hashes_and_independent_originals retention and cannot_recall for already disclosed knowledge. SHA-256 binds this exact manifest. Recomputing the manifest in the receipt transaction rejects new data, revisions, changed native/computer scope and stale previews. A preview read confers no authority.

Retire explicitly retains owner history/evidence; deletion is separate. Retain flags must both be true in this phase: retirement is not an implicit data eraser. Already committed results/report files retain an independent owner-retention fact for inspection, while old context packets remain retired and cannot execute. Original source/access/share/computer withdrawal still invalidates retained evidence. Retirement stops processes but preserves computer data; computer-only reset/delete does not retire the Bot. Retired/deleted Bot memory decisions cannot create new private context.

Transitions increment Bot generation/revision and disable the Bot in the same transaction as independent identity facts. All originating grants containing that Bot are stopped (including their queued lanes), and routines capturing it are blocked. This stops a whole affected grant rather than silently changing its participants. Independent grants/Bots remain untouched; committed siblings keep their own evidence. Tool, input, credential-write, native creation/inference and publication barriers re-read current authority. Cancellation follows commit, so rollback never aborts legitimate work. Work/transition stays stopping until actual work, chat and browser input transports settle; native busy/missing/corrupt/partial/close failures remain unresolved. Unknown external effects retain their existing reconcile-only ledger and never retry.

## Deletion and recovery

Delete records an independent root Bot tombstone and generation event before destructive cleanup. Source/claim/share/context withdrawal identities are propagated through the existing forward lineage algorithm, never backward into independently owned originals. Received copies/derivatives are withdrawn, while the foreign original remains. Already disclosed model/recipient knowledge cannot be erased. Sources/claims/messages/decisions, derived result/report/artifact BLOBs, copied shares, chat snapshots, private work/graph/attempt payload caches, proposal histories and vendor correlation caches are erased/redacted locally. Immutable identity/hash/authority audit facts and independently owned command intent are retained. Exact effect payload caches are redacted with Effect.payloadState=deleted while the original actionHash/outcome stays intact; an unknown effect is never made retryable. Independently authorized work of another Bot remains retained even when it used the deleted Bot's conversation without reading a deleted source. Tombstoned work/attempt payload markers permit only service-owned cleanup to redact otherwise immutable snapshots; grants remain permanently revoked.

Cleanup stages are fenced → data → computer → native → complete. `drain(port:NativeRecoveryPort):Promise<void>` retries the same authorized named cleanup, never dispatching work. It waits for real transports first, destroys only the Bot's computer components, and uses supported public inventory/retire/delete for owned native contexts and forward-derived contexts (including another Bot's session that consumed the deleted source). Context identities are recorded independently before caches are scrubbed, so loss of a pruned/old application packet cannot hide native ancestry. Recorded interrupted native orphans can retry scoped metadata reconciliation without replay or fencing unrelated work. Missing old correlation stays unresolved. Busy/unconfirmed cleanup preserves stopping/deleting with a safe reason. Every stage is idempotent across crash/reopen. Computer reset is a separate command.

Application construction reconciles the current independent ledger before owner projections/workers. Older Bot generations are disabled with empty ceilings and stopped/retired for fresh owner review; deleted roots reapply all owned-data tombstones and cleanup. Independent native catalog/usage/grant/share/context facts prevent stale-image resurrection. Recovery boot fences transports and performs native metadata reconciliation before any replay; a lifecycle-withdrawn grant never requeues. OPS14-01 must retain the current ledger and still owns managed backup/restore activation; this slice does not claim full installation restore transport.

`view(actor,botId)` returns `{bot,lifecycle,proposals}`. Transition state is active/stopping/retired/deleting/deleted; target is active/retired/deleted; stage is fenced/data/computer/native/complete. Reasons include bot_transports_unsettled, bot_computer_cleanup_unresolved, bot_native_cleanup_unresolved and restored_bot_generation_withdrawn. Receipts describe committed intent; poll current queries for settlement. No request supplies an owner identity.
